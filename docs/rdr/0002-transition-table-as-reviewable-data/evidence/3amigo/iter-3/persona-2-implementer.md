# 3amigo Iteration 3 — Persona 2 Implementer

- **IMP3-001 — The normative closed layout omits `[[rule]].source`, which every rule in the normative fixture authors, so the fixture cannot survive its own strict-decoding contract.** The closed-layout clause enumerates the admitted keys exhaustively — "root `outcomes`, root `terminal`, `[model]` (with `[model.metadata]`), `[initial]`, `[tags.<tag>]`, `[read.<id>]`, `[write.<id>]`, `[gate.<id>]`, `[context.<id>]`, `[[rule]]`, and `[dump]`", with rule-level `clear`, `gate`, and `escape` named as the only rule-level scalars/lists — and closes with "No other root key or table is admitted (strict decoding, below)". But `evidence/spikes/iter-2/rdr-fixture.toml` authors `source = "rdr:prelock"` on all five rules and `kata-fixture.toml` on both, and `main.go`'s `Rule` struct maps it (`Source string \`toml:"source"\``). Testing Strategy scenario 1 requires these two fixtures to "decode ... under strict decoding" and scenario 3 makes `unknown schema field` a category asserted on. As written, a Monday implementer building the `Rule` struct from the normative text alone gets a decoder that refuses the normative fixture with `unknown schema field: rule.source` — the same failure the RDR celebrates for the pre-§D7 fixtures ("`unknown schema field` on `accessors.*` and `tags.*.accessor`, which is the sharpest statement of why they could not be promoted"). The same hole covers `[model].description`, which Technical Design part 1 names ("table id, version, human description") and both fixtures author, but which neither the closed-layout clause nor the Load-Bearing Decisions wire-format bullet lists. Blocks: whether `source` and `description` are admitted keys, and therefore whether the promoted fixtures load at all — the first struct definition of Phase 3. Passage: Proposed Solution / Normative Contracts — closed-layout clause (`No other root key or table is admitted`); Load-Bearing Decisions — Wire / byte format.

- **IMP3-002 — The source locator's normative floor ("at least the model id and rule id") is contradicted by the only implementation of it, which stores an authored non-unique string.** The Technical Design closes with "The locator must identify at least the model id and rule id; byte line/column coordinates are optional diagnostic detail," and the Round-Trip clause makes this load-bearing: "The locator's **presence and its rule-identifying part are compared**, even though its line/column detail is not: excluding the whole field would let a normalizer that dropped locators entirely satisfy the invariant." The spike populates `Row.Locator` from `rule.Source` (`main.go:670`), the authored `source` key — and in `kata-fixture.toml` both rules author `source = "kata:review"`, so the locator identifies neither the rule nor the model. Nothing in the RDR says whether the locator is derived (from `(model id, rule id)` plus the source id the Existing Infrastructure Audit says `Load` takes) or authored. Combined with IMP3-001, an implementer has three live readings: derive it, admit `source` as an authored override, or both. The Round-Trip "rule-identifying part" comparison is unwritable until this is fixed, because under the fixture's own locators two distinct kata rows carry an identical locator. Blocks: the `Locator` field's type and provenance, and the scenario-5 Round-Trip comparator. Passage: Technical Design — normalized candidate row / locator floor; Round-Trip / Inverse Invariants — locator presence-and-rule-identifying-part paragraph.

- **IMP3-003 — The literals clause fixes set-valued *atom* literals as member sequences but says nothing about set-valued *write* values, which the write-replaces clause introduces and the spike joins on a comma — the exact defect the literals clause exists to ban, one field over.** The literals clause is scoped to atoms throughout: "A set-valued **literal** MUST normalize to an ordered sequence of its members"; "Wherever **atoms** are compared, keyed, deduplicated, or sorted ... the literal field MUST be compared as the member sequence." The write-replaces clause (cove-touched) introduces the set-valued write — "for a `set` kind the array literal is the whole new set" — and the dump contract lists "next-state tags, writes including `<clear>` entries" as compared Round-Trip fields, but no clause says a write value is a sequence. The spike scalarizes it: `Write.Value string`, filled by `renderValue`, which for a list does `strings.Join(parts, ",")` (`main.go:895`); `kata-fixture.toml`'s `labels = ["needs work"]` renders `labels=needs work`, and `["a,b","c"]` versus `["a","b,c"]` produce one identical write value. Since RDR 0004's read-back "compares the held value for equality (JDR 0001 §D7(iv))", that collision is not cosmetic — two different intended sets become one write. The fail-fast clause's own carve-out names this class ("A defect consumed earlier in the pipeline — merged away, de-duplicated, or otherwise absorbed before any category is decided — trips *zero* categories"), but its remedy points only at "the merge clause's set-over-full-identity obligation, and the literals clause's ban on joined identities", neither of which reaches a write value. Blocks: the `Write` value type (string vs `[]string`), the Round-Trip write comparator, and whether writes need their own member sort — decided before the first normalized-row struct is written. Passage: Proposed Solution / Normative Contracts — literals clause; write-replaces clause ("A write replaces").

- **IMP3-004 — Guard-block operators are entirely unconstrained: no clause names the admitted operator set for `all`/`unless`, yet `unknown operator` is a normative category and a scenario-3 control.** The match-block restriction is precise ("a match block admits only `eq` and `in`"; "a comparison, existence, `contains`, or any other operator under `[rule.match]` or `[context.<id>.match]` is refused at load as a malformed predicate atom"), but the guard side has no mirror. The category floor names `malformed predicate atom (unknown operator; ...)` and scenario 3 requires a control for it, while the Technical Design defers: "RDR 0003 owns the fixed predicate operators" and the Capability Dependencies row for RDR 0003 reads `Pending` — and RDR 0003 is now itself `Draft` (demoted 2026-08-24), with its closed set `{eq,in,lt,lte,gt,gte,exists,contains}` in a record this RDR nowhere cites by clause or by member list. The spike implements no unknown-operator check at all: `mergeAtoms` (`main.go:851-866`) takes whatever TOML key appears under `[rule.guard.all.<tag>]` as the operator token verbatim, with `exists` the sole special case. So the operator token reaching `Atom.Operator` — which the atom identity tuple, the merge key, and the dump sort all compare — is unvalidated. Blocks: whether Phase 3's predicate validator can be written at all before RDR 0003 re-locks, and whether `unknown operator` is this RDR's check or a deferred one — the scenario-3 fixture cannot be minted either way. Passage: Proposed Solution / Normative Contracts — match-block operator restriction (kernel-handoff clause) vs. Load-time category floor — `malformed predicate atom (unknown operator; …)`; Testing Strategy scenario 3.

- **IMP3-005 — `[model]`'s own well-formedness has no category: a missing `id`, and a missing `version`, both fall outside the stable category floor.** The version clause states "`[model]` MUST contain `id` and `version`", but the category floor lists `unsupported version` and nothing for an absent `id` or an absent `version`, and scenario 3's enumeration carries no control for either. The spike invents an off-contract refusal for the first (`malformed model: missing id`, `main.go:267`) and silently folds the second into the wrong category: `probe.Model.Version != 1` on an absent key yields the zero value, so a document with no `version` at all refuses as `unsupported version 0` — a diagnostic that names a version the author never wrote, which is structurally the same confusion A14's two-pass gate was built to prevent. Since the category floor is declared an API surface ("The Testing Strategy asserts on the category, so these identifiers are an API surface, not message text"), an implementer cannot pick a name without extending it. The same hole covers a model with no `[tags.recognized]` declaration: the spike refuses `expected exactly one recognized declaration, got 0`, another category the floor does not carry (`reserved_tag_key` covers only misnaming, not absence). Blocks: three category identifiers and their fixtures, and whether an absent `version` is a version failure or a shape failure. Passage: Proposed Solution / Normative Contracts — version-gate clause (`[model]` MUST contain `id` and `version`) vs. Load-time category floor.

- **IMP3-006 — The accessor-entry clause states a missing/invalid rule only for `timeout`, leaving `role`, `path`, an empty `keys`, and `read_back` with no stated obligation — and the one rule it does state ("non-positive") is unimplemented.** The clause reads "Every entry carries `role`, `path`, `keys` (a non-empty list of declared tag keys), and `timeout` (a Go duration string; missing or non-positive is a malformed accessor declaration); a `[write.<id>]` entry additionally carries `read_back = true`." Only `timeout` gets an explicit refusal rule. Whether a missing `role`, a missing `path`, an empty `keys` list, or a `[write.<id>]` authoring `read_back = false` refuses — and under which category — is unstated, while `malformed accessor declaration` is a floor category asserted on by category in scenario 3. The spike guesses: it refuses an empty `keys` under `malformed accessor declaration` (`main.go:350`), never checks `role` or `path` at all, never checks `read_back`, and checks `timeout` only for `== ""` — never parsing it, so `timeout = "0s"` and `timeout = "banana"` both load despite the clause's explicit "non-positive is a malformed accessor declaration". Scenario 3's only accessor-declaration control is "an accessor entry missing `timeout`", so the non-positive arm the clause states normatively has no oracle. Blocks: the accessor struct's required-field set and the `malformed accessor declaration` fixture set — Phase 3's first validator. Passage: Proposed Solution / Normative Contracts — Accessor tables clause (`role`, `path`, `keys`, `timeout`, `read_back` sentence); Testing Strategy scenario 3.

- **IMP3-007 — `[dump]`'s column vocabulary and its malformed forms are unspecified, so the one presentation table in the closed layout has no shape and no category.** The dump clause says "`[dump]` settings MAY reorder the rendered columns; they MUST NOT omit a field. A dump missing any field is not an expanded table dump" and "Normalization MUST ignore it entirely", but nothing names the column identifiers a `[dump]` may use, whether `order` is the only key, or what happens when `order` names an unknown column, omits one, or repeats one — even though "MUST NOT omit a field" makes an omitting `order` a violation of something. The category floor carries no `malformed dump declaration`, and no scenario-3 control exists. The spike decodes `Dump{Order []string}` and then never reads it (`main.go:64,122`; `render` hardcodes the field order), so both fixtures' ten-element `order` lists are dead text that would pass any test. An implementer choosing to honour `order` has to invent the column-name alphabet, and choosing to ignore it silently violates the clause's premise that "the column order a table wants reviewed travels with that table". Blocks: whether Phase 2's dump reads `[dump]` at all, and the identifier set if it does. Passage: Proposed Solution / Normative Contracts — dump clause (`[dump]` is presentation, MUST NOT reach the normalized value); Load-time category floor (no dump category).

- **IMP3-008 — The fail-fast clause's "first category a document trips is the refusal" is unimplementable as stated across the two-pass version gate, because the first pass must decide `malformed TOML` before the gate it is required to precede.** The version clause fixes exactly one ordering as normative — "Only the version gate's precedence is normative" — and the fail-fast clause (cove-touched) makes everything else free. But the two-pass shape the clause mandates ("read `[model]` permissively enough to obtain `version`, refuse on any value but `1`, and only then decode the document strictly") requires a parse of the whole document to reach `[model]`, so a document that is both syntactically malformed and `version = 2` necessarily refuses `malformed TOML`, never `unsupported version`. The spike does exactly this (`load`, `main.go:222-227`: `toml.Unmarshal` into the probe, wrapping any error as `malformed TOML`, before the version comparison). That is almost certainly the right behavior, but the RDR states no precedence between `malformed TOML` and the version gate while asserting the gate's precedence unconditionally, and A14's "If wrong" frames the whole point as "a future v2 file fails with a diagnostic ... never mentioning the version". An implementer has to decide whether `malformed TOML` sits above the gate (making the gate's precedence relative, not absolute) or whether a lexer-level version scrape is required. Blocks: the `load` entry point's pass structure and the A14 precedence oracle's scope. Passage: Proposed Solution / Normative Contracts — version-gate clause (two-pass paragraph) and the fail-fast paragraph ("Load is fail-fast: the first category a document trips is the refusal").
