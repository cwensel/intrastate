# 3amigo Iteration 3 — Persona 1 Product Manager

- **PM3-001 A13's "If wrong" understates the harm and is the basis for the survivability claim that lets this RDR lock** — The desk trace's `merge atoms` row records the surviving CONTRADICTION concretely: a joined merge key makes `in = ["a,b", "c"]` and `in = ["a", "b,c"]` on one key and block collapse, so "the rule normalizes to a **live expanding row** instead of a dead rule." That is the user outcome inverting — the artifact says an edge is legal where the author wrote a self-contradictory rule, which is precisely "is this transition legal" answering wrong rather than answering once. But A13's own `If wrong` reads "The normalized atom set carries duplicates, inflating the dump and the Round-Trip field list **without changing match semantics** — or a de-duplication keyed too widely drops the A13-adjacent distinct-literal atoms." Neither arm names the live-row case, and the first arm asserts the opposite of what the trace found. Prerequisites then rests on exactly that text: "None is load-bearing for a *pre-lock* MVV assertion; **each is survivable per its 'If wrong'**." The survivability of the one assumption the cove pass demoted is therefore argued from a hazard statement the same pass's own trace contradicts. **Blocked decision**: whether A13 can stay `Pending` through lock, or whether the delimiter-bearing control (Testing Strategy 2) is a pre-lock gate rather than an implementation-time owed fixture — the RDR cannot answer that while its cost-of-being-wrong text and its evidence disagree. Passage: Critical Assumptions A13 — `If wrong`, read against Conditional Mini-Checks `trace` (merge atoms row) and Implementation Plan / Prerequisites (first bullet).

- **PM3-002 the reviewable artifact is admitted ambiguous at the one place reviewers read it, and the fix is charted to no named successor** — The Problem Statement's outcome is that "every legal edge live in one reviewable artifact." The cove pass corrected the Round-Trip section to admit that the rendered dump — the artifact reviewers actually read — makes a set-valued atom literal non-recoverable: "`["a,b", "c"]` and `["a", "b,c"]` render identically," and the `#`-ban does not reach atom literals because "an atom literal in a guard block or on any `string`-kind tag may hold any byte." The RDR's answer is "Rendering is a review surface here, and the normalized value is the contract," and the `fidelity` table's read-back row charts the inverse "to a successor dump-format RDR" — which is named nowhere in Capability Dependencies, References, or the phase plan. So the contract-level value is unambiguous while the human-facing view is not, and the mitigation is an unscheduled RDR. This is the same collision the literals clause treats as fatal one layer up (a joined rendering becoming an identity is banned precisely because "the dump's atom sort certifies the collision as canonical"), tolerated one layer down where a human, not a comparator, does the disambiguating. **Blocked decision**: whether Phase 2's dump deliverable must carry an escaping or quoting rule for set-valued literals before this RDR is implementable, or whether the review surface is allowed to ship lossy — nothing in the phase plan or Day 2 Operations forces that call, and no successor RDR exists to inherit it. Passage: Round-Trip / Inverse Invariants — lossy-site paragraph, and Conditional Mini-Checks `fidelity` (dump row, read-back row).

- **PM3-003 fail-fast single-category refusal forecloses batch diagnostics for the hand-authoring workflow this RDR exists to protect, without weighing the trade** — The Decision Rationale's stated purpose is authoring ergonomics: a fully expanded table "would force authors to copy the same predicate fragments across rows. **That is exactly the DX failure this RDR must avoid.**" The version-gate clause then fixes the opposite property for diagnostics: "Load is fail-fast: the first category a document trips is the refusal," the order among independent defects is "deliberately **unspecified**," "a document tripping two categories MAY be refused with either," and "an accumulating loader that returns a list is a **different contract** than this one." For a hand-authored sparse model carrying 23 load categories, that means an author fixing a new table does one edit-reload cycle per defect, with no ordering guarantee about which defect surfaces, so two implementations — or the same one after a refactor — may report different first errors on the identical file. The clause argues only that the freedom is *testable* (the one-defect-per-fixture rule makes order unobservable) and never that it is *good for the author*; the ergonomics outcome the RDR's own rationale names is not weighed against it anywhere, and no lint-side accumulate mode is reserved. **Blocked decision**: whether RDR 0005 may expose a "report every problem in this file" mode — this clause makes an accumulating loader a contract violation at the data layer, so 0005 cannot add it later without reopening 0002; that call belongs here and is not made. Passage: Proposed Solution / Normative Contracts — version-gate block, fail-fast clause.

- **PM3-004 `[model.metadata]` is specified in full and has no named consumer, no phase deliverable, and no path to any reader of the reviewable artifact** — The cove pass expanded this to a full clause: the loader "MUST decode it as a free-form table, carry it through to the normalized model untouched, and MUST NOT interpret any key in it"; it is "model-level and reaches no candidate row," outside the dump field list, outside the Round-Trip invariant, and its internal shape is "deliberately unconstrained." Two documents differing only in it "normalize to identical row sets while carrying different normalized models, and that is intended." What is missing is anyone who reads it. Capability Dependencies names no consumer; RDR 0006 (which consumes the normalized model) is not cited for it — grep of `docs/rdr/0006-*.md` finds no `metadata` reference — and JDR 0001 §D7(v) justifies it only as "one sanctioned namespace for tooling," naming no tool. Testing Strategy scenario 1 asserts it decodes and is "carried verbatim," and the `fidelity` table's parse row repeats that, but the normalize row is silent on it and Phase 2's deliverable list ("outcome lifted, per-atom block retained, `RequiresOwned` derived, existence constants emitted") does not include carrying it. So the normalized-model field it mandates is required by contract, untested past decode, and read by no one. Rendering it as a dump header is permitted ("Nothing here forbids a dump from rendering it as a header; that is presentation") but not required, so it need never reach the reviewable artifact at all. **Blocked decision**: whether the normalized model must carry a metadata field in Phase 2 — an implementer can satisfy every asserted obligation by decoding it and discarding it after load, and nothing in the RDR distinguishes that from conformance. Passage: Proposed Solution / Normative Contracts — layout block, `[model.metadata]` clause, read against Implementation Plan / Phase 2 and Capability Dependencies.
