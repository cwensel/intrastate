The two `probe-*` entries are the **enumeration witnesses** for the
unauthorable provenance arm of `malformed initial declaration`: an observed
key in `[initial]` has exactly two authorings — no writer serves it, or one
does — and both refuse under a writer-binding category before the owned-tag
predicate is reached. That is why scenario 3 carries no observed-key control
for that category and controls it by its value arm instead
(`neg-initial-bad-value`, `neg-initial-int-out-of-range`).

Strict decoding accepts `[model.metadata]`'s free-form keys while refusing
an unknown key anywhere else (`neg-unknown-field` above): the strict check
descends only into struct branches, leaving a `map[string]any` untouched.

## Merge semantics (contexts clause; A13)

```

merge-distinct           atoms=[status.eq=Draft@match; status.eq=Final@match]
```

A rule and an inherited context contributing a byte-identical
`(block, key, operator, literal)` atom collapse to ONE (the idempotence half
A13 names); two contexts contributing the same `(key, block, operator)` with
DIFFERENT literals both survive, and the two `use` orders digest identically.
