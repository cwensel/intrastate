## Step 3 — findings

**Finding 1 — `0019:C1` — class (a), codebase claim REFUTED.**
Claim: "A `decision-table` model has no `[initial]` (0010:C2) and therefore no bootstrap to materialize; initialization MUST refuse for that class rather than succeed vacuously." Source: a decision-table model carrying `[initial]` is unconstructible — it refuses at load on `malformed_accessor_binding`, `write_to_non_owned_tag`, or `malformed_model_declaration` (`internal/table/load.go:819-839`, `:1566-1573`, `:1714-1716`; reproduced against three fixtures at HEAD). Every loadable decision-table model has `len(Model.Initial) == 0`. The clause's premise is true but its refusal arm can never distinguish a class violation from an ordinary empty `[initial]` — the arm as written tests a state the loader forbids. Also lands on `0019:S7` and `0019:MVV` step 8, whose fixtures ("a `decision-table` model" expecting "the C1 class code") cannot be authored to exercise what C1 describes. Not approach-reopening: the verb still needs *a* refusal for the class, but C1 must key it on `IsDecisionTable(m)` alone, and the record must stop citing "has no `[initial]`" as the discriminator it isn't.

**Finding 2 — `0019:C1` / `0019:D-selection-predicate` — class (a), codebase claim REFUTED (structural).**
Claim: seed "iff the bound artifact carries NO key … the count is over STORE keys, not owned keys", anchored to `internal/cli/flowbind/flowbind.go::store`. Source: `internal/accessor/binding.go:34-42` — `ReadBinding.Read` answers only the *requested* keys and returns no cardinality; `flowbind.store` is unexported (`internal/cli/flowbind/flowbind.go:105`) and no exported `flowbind` symbol surfaces key count. The predicate as specified cannot be evaluated by any verb sitting on the shipped seam, while C1 simultaneously forbids direct artifact access ("it MUST NOT write an artifact directly", `0004:C3`). This is the highest-value finding: the empty-store predicate is the safety property the whole approach rests on (Decision Rationale's deciding automation row), and no shipped surface can compute it. `§existing-infrastructure-audit` has no row for it and `§technical-design` claims "the only new data flow is the *source* of the planned writes" — which is false; a store-cardinality read is a second new data flow, and it needs a decided carrier (a new seam method, a new `flowbind` export, or a `read-state`-family probe).

**Finding 3 — `0019:C1` / `0019:A5` — class (a), codebase claim REFUTED.**
Claim: the store predicate, `sealedKey`, `load`'s absent-is-empty rule, and "artifact bytes are unchanged" describe how init-state's target behaves. Source: `internal/cli/flowbind/registry.go:60-82` constructs **three** write carriers — `NewEditWriter` (`internal/cli/flowbind/edit.go:74`, RDR 0028 line-oriented edit), `cmdbind.Writer` (RDR 0025 command-backed), and the JSON `flowbind.Writer` — selected by `len(acc.Edit) != 0` and `commandBacked(acc)` (`registry.go:121-123`). For the first two there is no JSON store, no `sealedKey`, and no "artifact bytes" in the sense A5 verified. A5's spike ran only against the file-backed carrier. C1 must either scope the predicate to the file-backed carrier and say what init-state does for the other two, or state a carrier-independent emptiness test. Currently the record does not mention command-backed or edit-carried writers anywhere.

**Finding 4 — `0019:D-naming` / `0019:BR3` — class (b), new rule with an existing sibling.**
Claim: `--from-initial` on `set-state` is rejected because "one verb with two write-plan sources (request vs model) muddies the payload's writes-echo-the-request grammar". Sibling: `set-state` **already carries two write-plan sources** and already merged them cleanly — `internal/cli/flow_input.go:273-296` (`--plan <file|->`) and `internal/cli/flow_state.go:434-470` (`parseWrites`, one `admitWrite` body, per-carrier `param`, duplicate refusal naming "`--plan`, `--write` and `--clear`"). The stated ground is refuted by shipped code. The naming decision may still be right for other reasons (the `*-state` family, REQ-3's flag list, A4's override), but the load-bearing sentence in D-naming and BR3 asserts a property `set-state` does not have. Since A4's entire override cost hangs on the verb-vs-flag fork, the fork's rationale needs a ground that survives `--plan`.

**Finding 5 — `0019:C1` — class (d), RDR is silent on multi-role artifacts.**
C1's predicate is written for "the bound artifact", singular, and RT2/S9 assert on "artifact bytes". But `internal/table/model.go:521` `Writers map[string]Accessor` permits N writers over N roles, and `internal/cli/flow_state.go:351-362` already iterates writers checking `req.artifacts[def.Accessor.Role]` per writer — the record itself relies on this in F2 ("Torn (multi-writer)") and in C1's "no cross-writer atomicity". Whether init-state seeds when *all* bound artifacts are empty, when *any* is, or per-artifact is undecided, and the three answers give different cleared-key-safety guarantees. The silence sits exactly on the clause that A5 exists to protect.

**Finding 6 — `0019:C1` — class (c)/(a), internal redundancy against source.**
C1: "each value is held to its declaration with `table.ConformValue`". `internal/table/load.go:1701` already runs `conform(decl, "eq", members)`, which for `eq` is `conformKind` + `conformDomain` per member (`:1841-1848`) — the exact body of `ConformValue` (`:1813-1818`). A loader-normalized `Model.Initial` value cannot fail the step C1 mandates. Harmless as defense-in-depth, but C1 states it as load-bearing ("so read-back equality stays byte equality"), which it is not — the byte-equality property comes entirely from `canonicalSet` (`internal/cli/flow_input.go:770-774`), which C1 also names. The clause overstates what the conform step buys.

**Finding 7 — `0019:§existing-infrastructure-audit` — class (a), "Reuse" overstated.**
