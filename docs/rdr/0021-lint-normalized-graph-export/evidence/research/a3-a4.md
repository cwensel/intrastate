# A4 — 0005:C1 carve-out vs. a new root `graph` verb

Accepted citation: `0005:C1`, governing sentence verbatim:

> "The CLI MUST expose one command group for skill integration with these verbs: next, resolve, read-state, and set-state. Other command groups (lint, dump, parse) are outside this contract and are owned by the RDR that names them."

Analysis: the carve-out is a closed enumeration — "Other command groups (lint, dump, parse)" — naming exactly three existing groups. It does not say "any command group other than flow" or "any verb outside the four listed"; it names the three it is aware of. A new ROOT verb `graph` (per RDR 0021, presumably `intrastate graph export` or similar, sitting alongside `lint`/`dump`/`parse` rather than under `flow`) is not lint, dump, or parse, and is not one of next/resolve/read-state/set-state either. The sentence's closed phrasing ("Other command groups (lint, dump, parse)") reads as an enumerated list of the groups known at 0005's authoring time, not as an open rule ("everything but flow is out of contract"). Textually, the carve-out does NOT explicitly admit a new root verb — it only explicitly excludes the three it names.

This is a finding, not a citation fix: 0005:C1 as worded does not say whether a *new* root command group is automatically outside its contract or requires its own carve-out language. The envelope contract's own scope sentence — "The CLI MUST expose one command group for skill integration with these verbs" — binds C1 to the flow group specifically; a `graph` verb never claims to be `flow`, never emits `next/resolve/read-state/set-state`, and never claims skill-integration status, so on the contract's own terms (what MUST comply) a `graph` verb is simply not addressed by C1's obligations. But the enumerated carve-out list does not textually stretch to cover it as a *named exception* — it falls outside C1 by not matching its subject (the flow group), not because the carve-out clause enumerates it. Net: A4's conclusion (no amendment needed) is likely correct in effect, because C1's MUST-clauses are scoped to "one command group for skill integration" (i.e., `flow`) and simply have no jurisdiction over a root `graph` verb — but A4's own citation (the parenthetical closed list) does not itself establish this; it only covers lint/dump/parse by name, not graph.
