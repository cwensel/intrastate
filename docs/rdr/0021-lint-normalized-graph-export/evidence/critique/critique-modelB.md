## 1. The three most likely ways implementation goes wrong

**(a) The completeness surface (A8) ships as a signature change that quietly reopens A2's coupling.**

Root cause: `0021:A8` is `Pending` at lock — not `Verified`, not even graded a `constraint` the way its sibling A2 was. C4 requires the export's `graph-export-too-large` refusal to be driven by an EXPORTED completeness bool, but today `Reach()` (the only exported traversal wrapper) explicitly discards it: `nodes, _ := reach(m)` in `internal/graphlint/reach.go`. A8's own text says the plan is "a NEW exported function beside `Reach`" that returns `nodes, edges, complete` together, and that "`reach()` and lint's `analysis.go` call site" stay untouched. That is a plan, not a verified fact — A8's evidence section is explicit that this is unconfirmed and names the verification as future work ("confirm the new signature returns nodes, edges, and completeness together, and that lint still reaches `reach()` directly").

The specific hazard: A2's entire result — "the widening arm is dead code, so post-hoc edge recovery equals the traversal exactly" — is a STRUCTURAL proof about `indexOf`/`subsumes` as they exist today, verified by exhaustive lemma plus a zero-event audit over the current code shape. A8's new function is additional code sharing the same package, likely calling `successorsOf`/`indexOf` a second time to recover edges post-fixpoint (per A2's mechanism), or instrumenting `reach()` directly (the alternative C4 also blesses "if Resolve picks A2's in-traversal edge observer"). Either path touches the exact machinery A2's spike proved correct for the CURRENT unmodified code. Nothing in the RDR requires A8's implementation to re-run A2's differential test (36 real models, synthetic fixtures A–I, positive/negative controls) against the NEW function once it exists. The Prerequisites checklist even says "A1/A2/A5/A6 are spikes" and gates Phase 1 on A2 — but A8 is not in that gating list, despite being the assumption C4's refusal path structurally depends on.

Symptom: either the ceiling refusal doesn't fire correctly (a huge model exports a truncated document instead of refusing — C4's "never a partial document" invariant silently violated), or the completeness plumbing forces a change to `Reach`'s public signature that breaks the two known test-only callers, or — worst case — the new function's edge-recovery arm diverges from lint's traversal in some code path A2's spike never exercised because it was written against the code as it exists pre-A8.

**(b) The bare-JSON-on-stdout envelope collision ships without any runtime guard, only a documentation MUST.**

Root cause: `0021:C5` states "`--as=text` (the default) stdout carries the selected document verbatim and nothing else" and requires "a consumer that parses stdout as an envelope MUST use `--as=json`" — enforced entirely by prose. The premortem (P-10, folded into C5 per the Decision Rationale) already flagged this: "the chosen design's `--as text --emit json` cell emits a bare JSON document on stdout of a tool whose json-looking stdout otherwise means 'envelope.'" C5's mitigation is a documentation contract, not a structural one. The RDR's own Testing Strategy scenario 5 tests that `--as=json | jq .data` equals the text document — it does NOT test that an envelope-sniffing consumer, pointed at the (default) `--as=text --emit json` output, fails loudly and identifiably rather than silently misclassifying the payload.

Symptom: any existing internal or third-party wrapper around `intrastate` that treats "stdout starts with `{`" as "this is a CLIError/OK envelope" (a completely reasonable heuristic for every OTHER verb in this CLI) will silently misparse `graph`'s default output the day it is first invoked without `--as=json` — which is also the DEFAULT invocation shown first in the RDR's own Illustrative Code (`intrastate graph --model flow.toml > graph.json`).

**(c) The reviewer-facing "review it as a diagram" outcome degrades because normalization is not proven to be a faithful, human-traceable projection.**

Root cause: A3's evidence is a field-existence walk ("`Model.ID`/`Class`/`Tags`/`Initial`/`Terminal`/`Rows`... every one a pure function of the model value") — it verifies that fields EXIST on the model value, not that what ends up on the wire is recognizable to the human who authored the TOML. The problem statement's headline user story is "a reviewer... wants to see the graph lint actually certifies — review it as a diagram," but C2's schema exposes normalized rows and reachability nodes keyed by an escaped, compiled fingerprint (`(Node).key`), not by anything the author wrote. Nothing in A3, C2, or the testing strategy verifies round-trip legibility — that a human can look at a `reach.edges[].rule` value and recognize the rule they wrote, when the row's atoms have already gone through whatever compilation (e.g., one authored key becoming multiple atoms — a documented normalizer behavior elsewhere in this codebase's history) happens before `graphlint` ever sees the row.

Symptom: a reviewer opens the DOT rendering expecting "the diagram of my TOML" and instead sees node ids and edge labels that require them to already understand the normalized/compiled representation to map back to what they authored — the review workflow the RDR is pitched to serve degrades to "review an artifact only the normalizer's author understands," exactly the premortem's P-8 finding, which the RDR's own citation trail (A3's narrowing note) never closes because A3 was narrowed to be ABOUT structural field carriage, not about authored-identity legibility.

## 2. The one section that will be rewritten within 6 weeks

**Normative Contract C4 (Neutrality), specifically its ceiling-refusal clause, tied to A8.**

This is the one place in the RDR where a `Pending` critical assumption is load-bearing for a MUST-clause inside a locked normative contract, rather than for background rationale. Every other Pending-adjacent risk in this RDR (A2's coupling, the DOT escaping order, the empty-collection rule) was resolved to `Verified` or pinned in code before this draft reached its current state — the rulings.md trail shows Q1–Q3 and F1–F3 all closed with evidence. A8 is the one exception still standing at `Pending` with "Verification: confirm the new signature returns nodes, edges, and completeness together" written as a TODO, not a result. C4's own text already had to be corrected once this cycle (3amigo iteration 3, finding #2: the ceiling sentence wrongly called the guard-product bound "distinct" when it's the same `reach()`/`nodeCeiling` bound at two call sites) — that is a section under active editorial churn even before implementation starts. The moment Phase 1 actually writes the edge-recovery-plus-completeness function, one of two things happens: either the signature comes out differently than A8 assumed (forcing a C4 rewrite to match reality), or it comes out as assumed but A2's differential test has to be re-run against it and reveals a gap the spike never covered (also forcing a rewrite). Either path lands inside six weeks of Phase 1 landing, because A8 is explicitly gating Phase 1's very first deliverable (the document-assembly component "over `*table.Model` + `Reach`-with-edges").

## 3. The assumption that will not survive first contact with a real user

**A6/C2's claim that the abstraction marker plus one prose sentence is sufficient for a formal-methods consumer to use the export safely.**

C2 requires the `reach` block to carry `abstraction: "declared-over-approximation"` and states "the schema docs state the soundness rule in one sentence: universal claims... hold at runtime; existence claims... may be spurious." The Risks section names this as the mitigation for "consumers mistake the merged, over-approximate relation for runtime behavior." This is a real mitigation for a reader who (a) reads the schema docs, (b) reads them BEFORE deriving a model, and (c) correctly maps "universal vs. existence claim" onto whatever formal notation they're using (TLA+, Alloy, SMV all have their own idioms for this distinction that don't spell "universal" or "existence"). The premortem's own prospective-hindsight narrative (P-7, in the pre-existing propose-premortem critic) already dramatized exactly this failure: a platform team derives a TLC model, "reported that terminal states were reachable from every node... six weeks later a runtime trace showed an unreachable terminal," and traced the cause to working from the DOT rendering — which the RDR requires to carry the marker in "the graph header comment/label," a place graphviz renderers, and especially anyone piping straight to `dot -Tsvg` for a diagram, routinely never look at. RDR 0022 (the terminal-reachability-liveness RDR, explicitly named as a prospective consumer of this exact relation) is the single most likely real "first user" of this export, and liveness/reachability-of-terminal is precisely the EXISTENTIAL claim class C2's own soundness sentence says "may be spurious" over a merged, over-approximate relation. The RDR ships the abstraction marker as a courtesy annotation and calls it done; it will not survive the first person who asks "is my terminal state actually reachable" and gets "yes" from a merged node that over-approximates presence.

## 4. Premortem

It is six weeks after `intrastate graph` shipped. Three things happened, and they compound.

First, RDR 0022 landed its terminal-reachability-liveness invariant as a prospective consumer of this export's `reach` block, exactly as `0021:§references` anticipated. The 0022 author read C2's one-sentence soundness rule, understood "universal claims sound, existence claims may be spurious," and built the liveness check anyway — reasoning that since `0021:A2`'s spike had proven edge-recovery EQUALS the traversal (36/36 real models, exhaustive lemma), the exported relation was "the same graph lint reasons over," and treated a terminal-reachable-from-every-node result as trustworthy. It was not: the relation is still the DECLARED over-approximation `reach.go::Reach`'s own doc comment names — merged nodes, unpruned guard/observed atoms — and 0022's liveness check inherited that unsoundness silently, because nothing in either RDR forced a worked example distinguishing "A2 proved recovery is FAITHFUL to the traversal" from "the traversal itself is SOUND for existence claims." Those are different properties and the RDR conflates them in exactly the place a downstream author would need them separated.

Second, the `graph-export-too-large` refusal (`0021:C4`, gated on `0021:A8`) shipped as planned — but A8's Pending verification turned into exactly the kind of after-the-fact discovery its own evidence section predicted was possible: the new completeness-carrying function needed a small change to how `successorsOf` results were being folded, because the straightforward "call the existing post-hoc recovery, thread the ceiling bool through" implementation didn't compose cleanly with the existing package-private `reach()` without also touching a helper A2's spike had never instrumented. The change was small, reviewed, and merged — and it was never re-run against A2's differential corpus (the RDR's Prerequisites checklist only names A1/A2/A5/A6 as gating spikes; A8 isn't in that list, so nobody re-ran `TestGraphEdgesEqualTraversalEdges`-equivalent coverage against the new code path). Three months later, a customer model with a specific subsumption pattern the 36-model corpus never exercised showed the export's edge count silently disagreeing with lint's internal traversal by one edge, on one model, discovered only because a paranoid CI job happened to byte-diff the graph export against a from-scratch instrumented rebuild for an unrelated debugging session.

Third, an internal tooling script (`scripts/ci/graph-baseline.sh`, unowned by this RDR, written by a platform engineer who copy-pasted the RDR's own Illustrative Code example almost verbatim: `intrastate graph --model flow.toml > graph.json`) fed straight into a generic "any intrastate output starting with `{` is an envelope" wrapper the org already had for parsing `lint`, `dump`, and `resolve` output uniformly. It broke immediately: `graph`'s default `--as=text` output is the bare document, not an envelope, and `0021:C5`'s MUST-use-`--as=json` rule was never enforced by the CLI itself, only documented. The on-call engineer spent forty-five minutes bisecting a "malformed CLIError" alert before realizing the tool had a new verb whose default text mode was intentionally NOT an envelope, unlike every sibling verb they'd built tooling against.

None of these three failures required implementation bugs relative to the RDR's own text — `runExportGraph`, the eventual CLI entry point, and the new `graphlint` completeness-carrying function all did exactly what C1–C5 specify. The RDR's own contracts were the failure surface.

## 5. Acceptance tests that would have caught each failure at RDR-review time

**AT-1 (catches C-1 / premortem failure two — A8's unverified completeness plumbing)**
- Given the new exported completeness-carrying function A8 proposes
- When A2's full differential test suite (36 real models + synthetic fixtures A–I + positive/negative controls) is re-run against it, not against the original `reach()`/`Reach()`
- Then edge-set equality against the in-traversal observer holds with the SAME zero-divergence result A2 reported for the pre-A8 code
- And this re-run is listed as a Prerequisite gating Phase 1, alongside A1/A2/A5/A6, not left implicit

**AT-2 (catches C-2 — the permanently-dead `--flow` flag)**
- Given a new user runs `intrastate graph --flow anything`
- When C1's mirrored arm set fires `flag-invalid-value`
- Then the RDR states, before lock, either (a) why `--flow` should be exposed on a brand-new verb at all when it is guaranteed to fail in this build, or (b) an explicit decision to omit `--flow` from `graph`'s arm set rather than mirror it verbatim, with the help text difference called out as a UX decision, not an oversight inherited from `lint`

**AT-3 (catches C-10 / assumption in §3 — the soundness sentence is not enough)**
- Given a downstream consumer (explicitly RDR 0022, or an external TLA+/Alloy generator) derives a liveness or reachability-of-terminal property from `reach`
- When they read the schema docs' soundness sentence
- Then the RDR provides at least one WORKED example fixture showing a case where an existence claim ("terminal is reachable from node X") is TRUE over the exported relation but FALSE at runtime, so a consumer has a concrete counter-example to calibrate against, not just prose
- And RDR 0022 (or any RDR consuming `reach`) is required to cite this worked example before treating a liveness result derived from this export as meaningful

**AT-4 (catches C-5 / premortem failure three — envelope-sniffing collision)**
- Given an existing generic wrapper that classifies any `intrastate` stdout beginning with `{` as an envelope
- When it is pointed at `intrastate graph --model <fixture>` with no `--as` flag (the documented default)
- Then either the CLI detects and refuses this specific ambiguity (e.g., a distinct first-byte convention for bare-document text mode vs. envelope mode), or the RDR explicitly accepts and documents the incompatibility as a MIGRATION concern for every existing wrapper in the org, with a named remediation path — not just a MUST-clause aimed at future callers who haven't been told this verb exists

**AT-5 (catches C-8 / premortem-adjacent — ceiling refusal defeats the debugging use case)**
- Given a model that both fails `intrastate lint` AND exceeds the reachable-node ceiling
- When `intrastate graph` is run against it
- Then the Testing Strategy names this COMBINED scenario explicitly (today scenario 4 "model loads but lint refuses" and scenario 7 "ceiling exceeded" are tested independently, never together) and states the defined outcome — total refusal is the documented behavior, but the RDR should say in Consequences or Risks that the debugging journey for exactly this model class gets no graph at all, so that's a stated trade-off rather than a silent gap discovered by a frustrated user

**AT-6 (catches C-3 / §1(c) — reviewer traceability)**
- Given a TOML model where the normalizer has transformed authored content before `graphlint` sees it (e.g., one authored guard compiling into multiple atoms, a documented normalizer behavior elsewhere in this codebase)
- When the model is exported and rendered as DOT
- Then a human reviewer can map at least the RULE IDENTITY on every edge back to something present verbatim in the authored TOML (the RDR's own Illustrative Code already carries `rule` as a row identity — this AT asks the RDR to state and test that this identity survives normalization unchanged, not just that C2 assumes it does)

**AT-7 (catches C-6 — no machine-checkable schema)**
- Given the `intrastate.graph/1` document is described as a locked wire format
- When a consumer library wants to validate a document against the schema
- Then a JSON Schema (or equivalent IDL) exists and is checked in CI against every golden fixture, not just prose field lists in a markdown RDR plus a byte-identical golden for one or two authored models

## Verdict basis

C-1/C-8 and the A8 gap are the load-bearing defects: a `Pending` assumption sits inside a MUST-clause of a locked normative contract, ungated by the RDR's own Prerequisites list, and it is the one section under active editorial churn (3amigo iteration 3 already had to correct a factual error in this same clause). C-2, C-5, and C-10 are real but survivable UX/documentation debts the RDR could plausibly ship with and patch later without breaking the wire format. C-3, C-4, C-6, C-7, and C-9 are latent risks worth flagging at review but not individually blocking.
