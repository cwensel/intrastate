## Findings

### F1 — §JD-4 narrowing exists in exactly one body, and the other body does not cite it

TYPE: gap
A-QUOTE (0003:781-786, `Normative Contracts`): "An exhaustiveness claim MUST NOT be stronger than the runtime it describes: lint MUST NOT certify a row group exhaustive when a participating row can refuse `guard_unevaluable` under RDR 0007's aggregation veto. Where the two disagree the lint promise narrows; the runtime veto MUST NOT be weakened."
B-QUOTE: **silent in the normative body.** RDR 0006's only exhaustiveness clause is 0006:356-361: "Graph lint MAY claim exhaustiveness only over finite declared domains supplied by the predicate/tag model. If a required dimension is not finite, lint MUST emit a blocking inability-to-prove finding for any contract that depends on closed coverage." `guard_unevaluable` appears only at 0006:10 (Status) and 0006:825 (appendix).
EXPLANATION: RDR 0003 has already taken the §JD-4 recommended arm and states the narrowing normatively, but RDR 0006 — the document §JD-4's head clause actually names — carries neither the clause nor a citation to 0003's, so an implementer reading only 0006 has no instruction that a fully-finite product can still be refused.
SEVERITY: blocks-impl
OWNERSHIP: joint
BLOCKS: RDR 0003 A8 (`0003:250-294`, Pending, "the one record that still gates lock" per `0003:1647`); RDR 0006's re-lock. Prevents MVV Scenario 6 (`0003:1516-1526`) from having a peer that emits the finding it asserts.

**Verified sub-claim: the two triggers genuinely differ.** They do.
- 0006's trigger (0006:358): `If a required dimension is not finite` — a property of the **declared domain**.
- 0003's trigger (0003:783-784): a fully-finite product where `a participating row can refuse guard_unevaluable`, decided per 0003:829-835 by whether "the row carries a value atom whose key is not declared present-for-every-reachable-predecessor" — a property of a **row's atom against declared optionality**.
0003's own `disposition` table separates them into two rows (0003:927 "Guard dimension lacks a finite declared domain" vs 0003:930 "Row group is domain-exhaustive but a participating row can refuse"). A model whose every dimension is finitely declared but whose key is declared optional fires 0003's clause and **not** 0006's. The divergence is real, not a wording artifact.

### F2 — `graph-unprovable-coverage` can carry the narrowing; 0003 forbids the non-blocking tier and 0006 permits one

TYPE: contradiction
A-QUOTE (0003:818-827): "'Refuse' and 'downgrade' are one outcome, not an author's choice: every case this RDR sends to refuse-or-downgrade — a non-finite dimension, a finite product too large to prove deterministically, and a withheld claim under the narrowing above — MUST produce the blocking inability-to-prove finding. **This RDR MUST NOT mint a non-blocking warning category for these cases; whether lint gains one at all is open under JDR 0001 §JD-4 and belongs to RDR 0006.**"
B-QUOTE (0006:302-304): "Blocking findings make the command fail. **Non-blocking advisories may exist for redundant rows or unreachable rules only if they do not weaken the mandatory acceptance gate.**" and (0006:327-329) "Non-blocking advisories, if implemented, are warnings and do not change the success disposition."
EXPLANATION: 0003 defers the existence of a warning tier to 0006 as an open §JD-4 question, while 0006 already permits one — but 0006 scopes it to "redundant rows or unreachable rules", which does **not** include the withheld-claim class, so the two are reconcilable and the correct disposition is to say so, not to leave the reader to infer it.
SEVERITY: risks-impl
OWNERSHIP: joint
BLOCKS: The §JD-4 sub-question "whether lint gains a warning category" (`jdr/0001:240`). Without an explicit statement, an implementer may read 0006:302 as license to file a withheld claim as an advisory, defeating 0003:789-795.

**Verified sub-claim: `graph-unprovable-coverage` can carry the narrowing without a new code.** Yes.
- The code exists and is already blocking: 0006:314 `| Required finite-domain proof unavailable | graph-unprovable-coverage |`, listed inside the "Mandatory blocking finding codes" table (0006:306).
- 0003 already targets it by name: 0003:789-795 "A withheld exhaustiveness claim MUST be observable, not silent. It takes the same blocking inability-to-prove form an unprovable dimension already takes — **RDR 0006's `graph-unprovable-coverage`**".
- 0003's `authority` census (0003:911) records the intent: "it reuses 0006's existing blocking code rather than minting a category §JD-4 leaves open".
- **No 0003 clause forbids a non-blocking tier existing in 0006 generally** — 0003:823-824 forbids *this RDR* minting one *for these cases* and explicitly assigns the general question to 0006. So reuse is unblocked; only the recording assignment (F1) remains.

## Answers to the five directed questions

1. **Does `guard_unevaluable` / the narrowing appear in either body, and do the triggers genuinely differ?**
   0003: **yes**, normatively at 0003:781-786 with a decision procedure at 0003:829-835. 0006: **no** — 2 occurrences, both outside the normative body (Status L10, appendix L825). The triggers **genuinely differ**: 0006:358 fires on a non-finite *dimension*; 0003:783-784 fires on a fully-finite product whose *row* carries a value atom over an optionally-declared key. 0003's own disposition table keeps them as separate input classes (0003:927 vs 0003:930). See F1.

2. **Can `graph-unprovable-coverage` carry the narrowing without a new code, and does 0003 forbid a non-blocking tier?**
   **Yes to reuse** — the code is already blocking (0006:314, inside the mandatory blocking table at 0006:306) and its stated meaning "Required finite-domain proof unavailable" covers a withheld claim; 0003 already names it as the target (0003:791, 0003:911). **0003 does not forbid a non-blocking tier in general** — 0003:823-824 forbids *itself* minting one *for the refuse-or-downgrade cases* and explicitly assigns the general question to 0006 under §JD-4. 0006 already permits advisories but scopes them to "redundant rows or unreachable rules" (0006:302-304), which excludes the withheld-claim class. Compatible; needs stating. See F2.

3. **Row group: one-directional or still a cycle?**
   **One-directional, no longer a cycle.** 0003 defines it (0003:603-612) and no longer reads it back; 0006's body neither defines it nor cites 0003's definition, using the undefined phrase "state/outcome pair" instead (0006:286-291). The two phrasings are compatible but the agreement is unstated. See F4.

4. **Does 0006 state a predecessor reachability contract 0003 can cite?**
   **No.** 0006 asserts the owned-set-before-match *invariant* (0006:294-296) and names "predecessor/write reachability" as a pipeline input (0006:99, 0006:737), but publishes no relation, domain, or decidability contract; the only contract-shaped mention is the appendix admitting the gap (0006:865). 0006 also frames the check as graph reachability where 0003 requires a syntactic decision over declarations (0003:832-833) — an unreconciled second divergence. See F5.

5. **Does 0006's lint input contract still assume an unhomed producer for finite-domain metadata?**
   **No for finite-domain metadata** — 0006:261-264 and 0006:124-126 already cite "the RDR 0003 tag declaration model" by name, making 0006's appendix defect #4 stale (F6). **Yes for one adjacent field**: `single-valued grouping` (0006:264) is attributed to that model, which never declares it (zero hits in 0003; zero in 0002) — a live unhomed producer for a blocking invariant (F7).
