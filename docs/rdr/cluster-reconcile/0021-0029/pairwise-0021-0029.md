## Findings

### Finding 1 — 0021 never assigns the tiers 0029:C4 obliges it to assign

TYPE: gap
A-QUOTE: silent — no clause in 0021 uses the words `frozen`, `append-only`,
`growing`, or `tier`. C1 introduces `--emit <format>` with the value set
`json` (default) or `dot`; any other value -> `flag-invalid-value` naming
`emit`; C4 mints the scalar refusal code `graph-export-too-large`; C2 fixes
the document field list. None of the three carries a stability tier, and
neither §cross-cutting-concerns ("**Versioning.** The document carries a
required leading `schema` field, initial value `intrastate.graph/1` (C2)")
nor §references mentions the tier vocabulary at all.
B-QUOTE: "Second, the vocabularies `cli/0021` emits under `data` — its
`--emit` format set, its `graph-export-too-large` refusal code, and the field
names its C2 fixes at Resolve — are machine-readable surfaces this census does
not enumerate, because they do not exist on `main` yet. They take their tier
assignments in `cli/0021` itself, in the change that adds them, per the rule
above."
EXPLANATION: 0029:C4 discharges its own census completeness by delegating three
named 0021 surfaces to 0021, but 0021 accepts no such obligation anywhere in
its text, so the surfaces land untiered — which 0029:C4 itself defines as a
defect ("an unassigned machine-readable surface is a defect").
SEVERITY: blocks-impl
OWNERSHIP: joint
BLOCKS: 0021 Phase 4 (contract surfaces) cannot state the promise for `--emit`,
`graph-export-too-large`, or C2's field names; and 0029's A7 snapshot check
("a new machine-readable surface cannot merge unassigned") fires red on the
commit that lands 0021, since the tiered-vocabulary snapshot has no rows for
the three surfaces and no seam to enumerate them by.

### Finding 2 — the delegation in 0029:C4 has no enumeration seam obligation attached, so 0021's surfaces cannot be asserted even once tiered

TYPE: gap

document: `json` (default) or `dot`; any other value -> `flag-invalid-value`
naming `emit`", with the set spelled inline in prose rather than behind a seam.
B-QUOTE: "A tier assignment obliges an ENUMERATION SEAM: an exported accessor
returning the vocabulary's members, in the package that owns them. Without one
the tier is unassertable — a `frozen` set has nothing to compare by value and
an `append-only` set has nothing to check membership and uniqueness over, so

EXPLANATION: 0029:C4's seam rule is written as binding on every tiered
vocabulary and its table accounts "Six owed, nine carried", but the three
delegated 0021 surfaces appear in neither count and 0021 owes no accessor, so
whatever tier 0021 eventually assigns is unassertable by construction.
SEVERITY: risks-impl
OWNERSHIP: joint
BLOCKS: the S6 by-value / S7 membership assertions cannot be written for the
graph-export surfaces; 0029:C4's "the count is the census, not a subset of it"
claim stops being true the moment 0021 lands.

## Seams interrogated and found consistent (no finding raised)

These were examined under the assignment and produced no anchored contradiction.
Recorded so the negative result is legible.

- **Two-level versioning (seam 1) — consistent, and bilaterally declared.**
  0021:C2: "The JSON document is a documentation artifact, versioned by a
  required leading `schema` field, initial value `intrastate.graph/1`;
  evolution within `/1` is additive … and an incompatible change bumps the
  marker under the `0.x` promise RDR 0029 governs." 0029:C4: "the document
  VERSIONS ITSELF: its required leading `schema` field … versions the
  document, while `schema_version` versions the envelope carrying it —
  consistent with C1's rule that `schema_version` is never projected into
  `data`, so the two markers coexist at different levels and neither
  substitutes for the other." 0029 §cross-cutting states the same boundary.
  This is a deliberate two-level scheme, not a collision.

- **`.data` agreement (seam 5) — consistent.** 0021:C5: "Under `--as=json`
  stdout carries exactly one terminal `ok` envelope whose `data` embeds the
  same document". 0029:C1: "`schema_version` rides the TOP LEVEL of each
  terminal record only. It is never projected into `data`, where it would
  collide with a verb's own payload". The document occupies `.data`, the
  version marker stays above it; 0021:S5's `--as=json | jq .data` comparison
  against text-mode output is unaffected by the added top-level key.

- **RT1 value identity (seam 4, decode half) — holds.** 0021:RT1 quantifies
  over "every field C2 lists" ("The quantifier is C2's field list, not
  'whatever was exported'"), and C2's list is the document's fields. Since
  `schema_version` never enters `data`, `json-decode ∘ export` re-pairs the
  document value-for-value with `schema_version` present. No input class
  breaks RT1. The exposure is RT2/C3's byte form only, recorded as Finding 4.

- **0021:A4 vs 0029:C1 (seam 3) — A4 survives.** 0021:A4: "A new root export
  verb requires no amendment to RDR 0005's envelope contract", resting on
  0005:C1's scope sentence, "so every MUST-clause that follows binds the `flow`
  skill-integration group and has no jurisdiction over a root `graph` verb."
  0029:C1 does amend the envelope's shape, but A4's claim is about whether
  0021's own verb forces an amendment, not about whether the envelope is
  immutable. 0029:C1 further argues its own compatibility with 0005:C1 ("This
  does not breach `0005:C1`'s 'exactly one omitempty structured field,
  `findings`'"). The two claims are about different subjects and do not
  collide. The practical coupling that does exist is the byte-golden one
  already raised as Finding 4.

- **0029:C3 joint-decision home (seam 6) — 0021 is not a sibling.** 0029:C3
  governs "A lint finding code is introduced at severity `info`." 0021 mints no
  lint finding code: C4 states the export "MUST NOT run the lint invariants,
  MUST NOT emit findings", and its one minted code, `graph-export-too-large`,
  is a scalar CLIError refusal code (GroupUserEnv, exit 2), which falls under
  0029:C4's `append-only` CLIError `code` row rather than C3's severity rule.
  So 0021 owed no sibling entry to the 0022 joint decision. Its vocabularies do
  owe tiers — that is Finding 1, a C4 obligation, not a C3 one.

## Verdict

Four findings: three `gap`, one `round-trip`. Two are blocks-impl (1, 4), two
are risks-impl (2, 3). Three are joint — the tier delegation, the seam
obligation, and the golden re-capture ordering are shared decisions neither
record solely owns. Finding 3 is single-RDR to 0021.

The pair's versioning design is coherent; what is missing is the follow-through
on 0029:C4's explicit delegation to 0021, and an owner for the envelope-golden
re-capture that 0029's added field forces on 0021's byte-identity assertions.
