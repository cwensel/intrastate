# Pairwise reconcile — RDR 0008 × RDR 0005 and RDR 0008 × RDR 0006

- **RDR_A**: `docs/rdr/0008-recognized-tag-key-ownership.md` (Final, unimplemented)
- **RDR_B1**: `docs/rdr/0005-skill-integration-cli-contract.md` (Final, unimplemented)
- **RDR_B2**: `docs/rdr/0006-graph-lint-authority-and-guarantees.md` (Final, unimplemented)
- **Seams**: (0008×0005) `reserved_tag_key` data-level failure → user-facing CLI
  surface → `CLIError.Code` → exit group; caller `--tag` grammar → reserved key.
  (0008×0006) declaration-name validation vs. blocking graph-lint acceptance
  authority and invariant taxonomy.
- **Verdict**: BLOCK (2 blocks-impl, 1 risks-impl)

Mechanical baseline established before reading for meaning:

- `0005…md` contains **zero** occurrences of the string `0008`.
- `0006…md` contains **zero** occurrences of `0008`, **zero** of `reserved`,
  and **zero** of `reserved_tag_key` / `tag key`.
- `0008…md` cites `0005` nine times and `0006` five times.

The citation traffic is therefore entirely one-directional: 0008 knows about
both peers, neither peer knows about 0008. That asymmetry is the shape of all
three findings below — 0008 charts obligations onto peer surfaces that the
peers, being Final, do not carry.

## F1

PAIR: 0008x0005

TYPE: gap

A-QUOTE: "Scoped precisely: this RDR guarantees the failure
*exists and carries its guidance* at load/lint; which
user-facing command surfaces it, and under which exit
code, is RDR 0005's mapping decision and is not settled
here (charted)."

B-QUOTE: silent

EXPLANATION: RDR 0008 explicitly routes the surfacing decision for its new
`reserved_tag_key` category to RDR 0005, but RDR 0005's Failure Modes table
("Minimum stable code strings") enumerates twelve `flow-*` codes covering
malformed `--tag`, duplicate tag, malformed `--artifact`, model-not-found,
unknown outcome, zero/multi match, missing fact, unevaluable guard, accessor
unavailable, gate indeterminate, and write read-back mismatch — and contains no
code, no group assignment, and no category-mapping mechanism for any
table-load/lint validation failure at all, so the failure 0008 authors has no
declared path to a user.

SEVERITY: blocks-impl

OWNERSHIP: joint

BLOCKS: An implementer cannot write the test 0008's own scenario 7 gestures at
("The consumer is a test stub, not RDR 0005's exit-code map: this RDR asserts
the payload contract, and 0005 owns whatever mapping it later adds") because
0005 declares no mapping to assert against — there is no stable `flow-*` code
string, no `Group`, and therefore no exit code to pin for a
`reserved_tag_key` failure reaching the CLI. Blocks the decision of which of
0005's four verbs (or RDR 0006's `intrastate lint`) is the surfacing command.

Corroborating detail, not a separate finding: 0008's A1 evidence *relies* on
this same silence as proof of safety — "RDR 0005 never enumerates RDR 0002's
data-level categories at all (zero occurrences)" — treating the absence of a
closed downstream enum as a licence to add a category. That reading is correct
as far as it goes (nothing in 0005 is contradicted), but the identical silence
that makes the addition safe is what makes it unreachable. 0008 uses the
silence as evidence in A1 and as a deferral in the Approach; it is never
converted into an obligation on 0005.

## F2

PAIR: 0008x0005

TYPE: gap

A-QUOTE: "Producers of kernel `Input` MUST NOT supply an owned or
observed tag keyed `recognized`; the reserved key enters the
assembled view only through `Input.Recognized`. A breach is
a producer programmer mistake — not table data, and never a
new `RefusalKind` — and travels the Go error path RDR 0001
reserves for programmer mistakes."

B-QUOTE: "State binding is explicit. Commands accept a model or flow identifier plus
state tags supplied as repeated `--tag name=value` flags in the MVP."

EXPLANATION: RDR 0005's `flow` verbs are producers of kernel `Input` whose
observed-tag content comes straight from caller-supplied `--tag name=value`
flags, so `intrastate flow resolve --flow rdr --tag recognized=x` is a
reachable user invocation that trips 0008's producer precondition — but 0008
classes that breach a "programmer mistake" on the Go error path, while 0005 has
no code for it and its only adjacent codes (`flow-tag-invalid`,
`flow-tag-duplicate`) are `GroupUserEnv` user-input refusals, so the two RDRs
disagree on whether a user typing a reserved key is a user error or a
programmer error.

SEVERITY: blocks-impl

OWNERSHIP: joint

BLOCKS: The `flow resolve` / `flow next` implementation cannot decide what to do
when `--tag recognized=…` is supplied. Three incompatible readings all conform
to something: (a) refuse at flag-parse time with a new `flow-tag-*` code
(0005's shape, but 0005 declares no such code and 0008 forbids the
declaration-channel category here since this is data, not a declaration);
(b) pass it through and let 0008's `Resolve`-entry predicate return a non-nil
Go error, which under 0005's contract must still become "exactly one CLIError
refusal mapped from the resolver kernel" — but 0008 insists it is "never as a
modeled refusal," and a raw Go error has no `CLIError.Code`; (c) let it reach
`ExecuteAndEmit` as a bare Cobra error, violating 0005's "Failures MUST use the
existing CLIError JSON/text envelope." Blocks the typed-refusal test in 0005's
Validation scenario 3 for this input class.

Note on 0008's own coverage of this path: 0008's A8 sweep for the breach's
blast radius is scoped to `internal/resolve/*_test.go` Go literals and
concludes "The kernel has **zero non-test callers** at HEAD." That is true at
HEAD and is exactly why the collision was not caught — 0005's `flow` verbs are
the first non-test callers, and they do not exist yet. A10 closes the
*accessor* half of the data channel ("no accessor-produced owned tag key at
HEAD … spells `recognized`") but says nothing about the *caller-supplied
observed* half, which is precisely the `--tag` channel. 0008's Failure Modes
asserts "no user data is reclassified as a programmer mistake" on the strength
of A10's accessor argument alone; the `--tag` path is user data, and it is
reclassified.

## F3

PAIR: 0008x0006

TYPE: gap

A-QUOTE: "Not RDR 0006's graph lint, and not a competing acceptance
rule under its \"MUST NOT define different acceptance rules\"
clause: 0006 consumes \"a normalized graph value, not Cobra
command state and **not sparse TOML**\" (`0006…md:244-246`),
takes declared tags with provenance as already-valid input
(`:251`), and leaves \"table source and normalization … in RDR
0002\" (`:458-460`)."

B-QUOTE: "Graph lint MUST be a blocking acceptance gate over the normalized transition
model. A model with any blocking lint finding MUST NOT be accepted for resolver
use or CI success."

EXPLANATION: RDR 0008 disclaims RDR 0006's lint and homes the reserved-key
check upstream in RDR 0002's normalizer — a layering argument that reads
correctly against 0006's stated input contract — but RDR 0006 also declares
itself the singular blocking acceptance authority ("The authoritative CLI
surface for graph acceptance MUST be the root command `intrastate lint`"), and
0006's mandatory eight-code invariant taxonomy has no `reserved_tag_key` slot,
so a model that fails 0008's reserved-key rule passes `intrastate lint` clean
and CI reports the model accepted.

SEVERITY: risks-impl

OWNERSHIP: joint

BLOCKS: The decision of who enforces the reserved-name rule at gate time. It is
**assumed, not stated**: 0008 asserts enforcement lands "inside 0002's own
normalizer work" (Prerequisites: "RDR 0002 implementation underway (the
enforcement point is its normalizer's load/lint path; this RDR's checks land
inside that work, not before it)"), but 0002's normalizer has no declared CI
gate of its own, and 0006's MVV — which is the repo's only declared blocking
gate — enumerates its illegal-fixture matrix exhaustively ("must assert
`graph-dangling-edge`, `graph-dead-end`, `graph-overlap`, `graph-coverage-gap`,
`graph-unprovable-coverage`, `graph-single-valued-state`,
`graph-owned-before-write`, and `graph-terminal-escape`") with no ninth entry.
Prevents writing the CI test that proves a wrong-named recognized declaration
is rejected before use.

Scoped honestly, which is why this is risks-impl and not blocks-impl: 0008's
layering argument is *sound*. 0006 genuinely does take "declared tags with
provenance" as already-valid input, so a normalizer that rejects the model
never hands 0006 a graph to lint, and the two rules cannot conflict. The
residual risk is ordering and gate coverage, not contradiction — if the
normalizer's rejection is wired into the same CI invocation 0006's A5 pins
("`make check` or `.github/workflows/ci.yml` invokes the production
`intrastate lint` command"), the gap closes with no contract change. If it is
not, the reserved-key rule has a normative MUST and no gate.

Related, deliberately not raised as a fourth finding: 0006's Capability
Dependencies row "CLI command exposure | RDR 0005 plus this RDR" and 0005's row
"Graph lint authority | RDR 0006 | Out of scope for this contract" are mutually
consistent, so the 0005↔0006 boundary is clean; only the 0008 obligations
crossing it are unhomed.

## Probe answers

**Does the `reserved tag key` failure reach the user through 0005's CLI
surface, and does 0005's taxonomy have a slot?** No, and no. 0008 defers the
question to 0005 by name; 0005 never enumerates RDR 0002's data-level
categories at all (0008's own A1 confirms zero occurrences), declares no
table-load failure code among its twelve, and its Capability Dependencies table
has no row for table validation. F1.

**Does 0006's lint authority cover the reserved-key check; does its taxonomy
have a category; who owns enforcement at lint time?** No, no, and *assumed*.
0008 explicitly disclaims 0006 and homes enforcement in 0002's normalizer, and
that layering is defensible against 0006's stated input contract — but the
ownership is stated only in 0008, never acknowledged in 0006, and 0002's
normalizer carries no declared CI gate while 0006's is the only one that
exists. F3.

**Can a caller pass `--tag recognized=...` and collide?** Yes, and the two RDRs
do not agree. 0005 accepts arbitrary `--tag name=value` with only
malformed/duplicate refusals; 0008 makes a `recognized`-keyed observed tag a
producer breach on the Go error path, explicitly "never as a modeled refusal" —
which collides with 0005's "flow resolve MUST return exactly one resolved next
tag-set or exactly one CLIError refusal mapped from the resolver kernel." F2.

**Does 0008 assume lint or CLI behavior 0006/0005 never promised?** Yes, in
three places, all of which 0008 is candid about being unsettled — the
difference is that it charts them as its own future work rather than as
obligations on peers that are already Final. Its Risks section anticipates
exactly F1 ("category-enumerating consumers (RDR 0005's exit-code map, refusal
renderers, remediation docs) render the new category as generic") and mitigates
it with payload discipline, which protects the *data* but does not create the
*route*. Its A12 falsification already established the general mechanism failure
— "no engine mechanism carries this RDR's `Overrides` to a `Final` peer's
implementation" — and repaired it for RDR 0002 only, by adding an explicit
Prerequisite handoff. The identical handoff gap to 0005 (F1, F2) and to 0006
(F3) is left unrepaired; the A12 repair is scoped to one peer when the
diagnosis applies to three.
