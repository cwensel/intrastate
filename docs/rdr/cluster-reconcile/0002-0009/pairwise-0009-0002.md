# Pairwise reconcile: RDR 0009 ↔ RDR 0002

- **RDR_A** = `docs/rdr/0009-escape-row-shape-conformance-ownership.md` (Final, unimplemented)
- **RDR_B** = `docs/rdr/0002-transition-table-as-reviewable-data.md` (Final, unimplemented)
- **Seam under test**: RDR 0002's normalizer *produces* candidate rows; RDR 0009 imposes an escape-row shape *precondition* on those rows, enforced at two points (RDR 0001's kernel entry, RDR 0002's normalizer/lint).
- **Claim under test** (from 0009 Overrides): this RDR "makes RDR 0002's escape-rule prohibition an explicitly owned producer obligation" and "does not change RDR 0002's authored grammar."

Verdict on that claim: **the grammar is unchanged, but the *validation surface* is not.** 0009 imposes an authored-path enforcement semantic (presence-keyed rejection) and a normalizer-side failure-mode requirement that RDR 0002 does not declare, and the produce/validate seam does not round-trip on one input class the authored grammar admits.

---

## Finding 1 — the normalizer cannot emit the row 0009 validates, because 0002's escape-row rendering has no `Writes` slot at all

TYPE: gap

A-QUOTE: "Escape-row shape conformance — an escape row carries no owned-state mutation — is a PRODUCER obligation on every constructor of resolve.Row values: a Row with a non-empty Escape list MUST have an empty Writes slice."

A-QUOTE (corroborating, A4 *Consistency note*): "RDR 0002's escape-row rendering (\"row kind `escape`, its normal predicate set, source rule id, source locator, and modeled failure class list\") names **neither** writes **nor** next-tags, so a normalized escape row is authored-path-stricter than the kernel predicate requires. Stricter upstream, consistent — not a conflict."

B-QUOTE: "Normalization MUST render an escape rule as a candidate row with row kind `escape`, its normal predicate set, source rule id, source locator, and modeled failure class list."

EXPLANATION: RDR 0002's escape-row rendering contract enumerates a *closed field list* that omits `Writes` and `NextTags` entirely, while RDR 0009's producer obligation is stated over `resolve.Row` values that necessarily carry both fields — so the normalizer has no specified way to construct the kernel `Row` that 0009's precondition is written against, and 0009 disposes of the mismatch as "stricter upstream, consistent" without saying which of the two field lists the normalizer's output type actually has.

SEVERITY: blocks-impl

OWNERSHIP: joint

BLOCKS: The Phase 3 "shared normalizer conformance fixtures" cannot be written. Scenario 8 ("normalized escape rows render write-free") is unassertable until it is settled whether a normalized escape row *has* a write-free `Writes` field (0009's reading, testable as `len(row.Writes) == 0`) or *has no writes field* (0002's enumerated rendering, where "renders write-free" is a type property, not a value assertion). It also blocks the "one predicate, two call sites" clause: `Table.CheckValid()` is a method on the kernel `resolve.Table`, and if the normalizer's row type is not `resolve.Row`, the normalizer cannot call the same predicate and the two enforcement points *do* drift — the precise outcome the clause exists to prevent.

Note on the corroborating quote: 0009's A4 *Consistency note* is the only place either RDR touches this, and it explicitly declines to resolve it ("Stricter upstream, consistent — not a conflict"). That disposition is correct about the *invariant* (a stricter producer cannot breach a looser predicate) but does not answer the *representation* question that Phase 3 must answer to write a fixture.

## Finding 2 — presence-keyed rejection of an empty write block is a validation semantic RDR 0002 does not declare

TYPE: contradiction

A-QUOTE: "Rejection keys on the PRESENCE of the block, not its contents — RDR 0002 forbids an escape rule from containing a write block, so an empty one (`writes = []`) is rejected too. The authored layer is therefore stricter than the kernel's length-based predicate, deliberately"

B-QUOTE: "An escape rule MUST contain an `escape` list and MUST NOT contain a write block or clear list."

EXPLANATION: RDR 0009 reads 0002's prohibition as presence-keyed and binds a normative fixture to it (Phase 3: "an escape rule carrying an **empty** write block (`writes = []`) fails load the same way"), but 0002's own text never distinguishes presence from contents, never names `writes = []` as an input class, and — decisively — its Failure Modes and Testing Strategy scenario 3 enumerate the malformed variants the normalizer must reject without listing the empty-block case, so 0009 is fixing a semantic on 0002's validation surface that 0002 does not currently declare.

SEVERITY: blocks-impl

OWNERSHIP: joint

BLOCKS: Whether RDR 0002's implementation must reject `writes = []` on an escape rule. This is a real fork, not a clarification: TOML decoding into a Go struct is presence-losing by default (`[rule.write]` with no keys and an absent `[rule.write]` both decode to an empty/nil map unless the decoder is asked to track presence). So 0009's clause is not merely a stricter reading of 0002 — it imposes a **decoder requirement** (presence tracking, e.g. a pointer-to-map or `toml.Unmarshal` metadata inspection) on RDR 0002's parser that 0002's Technical Design never specifies and its A1 spike never exercised. It also directly contradicts 0009's own Overrides claim that it "does not change RDR 0002's authored grammar": distinguishing an empty write block from an absent one *is* a grammar-level distinction.

Corroborating B-QUOTE (the enumeration that omits it): "Validation rejects malformed tags, unsupported model versions, unknown predicate operators, writes to non-owned tags, rules that match on missing tag declarations, unresolvable context references, unknown accessor names, malformed escape declarations, and ambiguous overlaps between candidate rows."

## Finding 3 — ROUND-TRIP: an authored escape rule does not survive `parse ∘ normalize ∘ dump` as an identity, because the dump contract drops row kind and escape classes

TYPE: round-trip

A-QUOTE: "one canonical authored-clear case pins the `<clear>`-sentinel-write representation identically for the kernel suite and the normalizer suite, so the two enforcers of one invariant cannot drift."

B-QUOTE (the invariant): "`parse ∘ normalize ∘ dump = expanded-table value identity` on valid transition model fixtures: dumping the normalized model and reading the dump as a table view must preserve the candidate-row set, including row identity, source locator, row kind, predicates, writes, and escape failure classes."

B-QUOTE (the dump contract that cannot deliver it): "The expanded table dump MUST be derived from the normalized candidate-row value: model id, row identity, source locator, predicates, and writes. Dump ordering MUST be deterministic across source key order by sorting rows by row identity, then sorting predicate and write keys within each row."

EXPLANATION: RDR 0002's Round-Trip invariant requires the dump to preserve **row kind** and **escape failure classes**, but its own dump-derivation contract enumerates a strictly smaller field set — model id, row identity, source locator, predicates, writes — that contains neither, so the escape-row input class round-trips to an ordinary row: kind and failure classes are unrecoverable from the dump.

**Input class that breaks identity**: any escape rule (0002's `escape = ["no_match"]` / `["ambiguous_match"]` form — the class 0002's own A3 spike fixture and Illustrative Code both exercise via `draft-no-match-escape`). This is a **fidelity loss, not an outright failure**: the dump succeeds, is deterministic, and is byte-stable; it simply loses the discriminator. It is non-idempotent in the strict sense — `dump(normalize(parse(x)))` re-read as a table view yields a row set in which the escape row is indistinguishable from an ordinary write-free row.

**Why this is a 0009 finding and not merely a 0002-internal defect**: RDR 0009 makes the escape/ordinary discriminator load-bearing for a safety invariant, and pins it to exactly one signal.

A-QUOTE (the pin): "The shared resolve.Row type keeps its single shape: escape identity remains discriminated solely by a non-empty Escape list. No ordinary/escape type split and no row-kind field is introduced at the kernel boundary."

Under 0009, `len(Escape) != 0` is the *sole* carrier of escape identity at the kernel boundary, and `Table.CheckValid()` reads exactly that field. A dump that drops escape failure classes therefore produces, on re-read, a row with an empty `Escape` list — which `CheckValid` classifies as an **ordinary** row, for which a non-empty `Writes` is perfectly legal. So the round-trip does not merely lose review fidelity: it **launders a breach**. An escape row that `CheckValid` would reject before the dump becomes a conforming ordinary row after it. The two enforcers 0009 promises "cannot drift" drift across the dump boundary, and they drift in the unsafe direction.

SEVERITY: blocks-impl

OWNERSHIP: joint

BLOCKS: RDR 0002's Testing Strategy scenario 5 ("Normalize and dump two semantically identical fixtures … The expanded-table value is identical") cannot be written to cover escape rows until the dump field list is reconciled with the Round-Trip invariant. It equally blocks RDR 0009's Phase 3 fixture "normalized escape rows render write-free": that assertion is only meaningful over a dump in which the row is still identifiable *as* an escape row, and under 0002's current dump contract it is not. Until reconciled, no test can distinguish "the normalizer correctly rendered an escape row write-free" from "the normalizer rendered an ordinary row that happens to have no writes."

## Round-trip invariant assertion across the produce/validate seam — per input class

The authored grammar (RDR 0002, `[[rule]]`) admits exactly these row classes. Asserting `CheckValid` conformance and dump identity across each:

| # | Input class (authored) | `CheckValid` verdict | Round-trip identity | Disposition |
| --- | --- | --- | --- | --- |
| 1 | Ordinary rule, write block, no clear | conforms (empty `Escape`) | holds | clean |
| 2 | Ordinary rule, write block + `clear` list | conforms; clears normalize to `<clear>` writes, still empty `Escape` | holds | clean |
| 3 | Ordinary rule, multi-tag write | conforms | holds | clean |
| 4 | Escape rule, `escape = ["no_match"]`, no write/clear (the legal escape form) | conforms *if* the normalized row has a `Writes` field at all — **undetermined**, Finding 1 | **BREAKS** — row kind and escape classes dropped by the dump contract, Finding 3 | **fidelity loss**, and it launders the discriminator |
| 5 | Escape rule, `escape = ["ambiguous_match"]`, no write/clear | same as 4 | same as 4 | same as 4 |
| 6 | Escape rule carrying a write block (illegal) | rejected at load ("malformed escape declaration") — never reaches the kernel | n/a, rejected pre-normalization | clean; this is the case both RDRs actually agree on |
| 7 | Escape rule carrying a `clear` list (illegal) | rejected at load | n/a | clean |
| 8 | Escape rule carrying an **empty** write block `writes = []` | **undetermined** — 0009 requires rejection, 0002 does not declare it, and TOML decoding is presence-losing by default, Finding 2 | n/a if rejected; if admitted, normalizes to a write-free escape row and then hits class 4 | **outright failure of specification** — the two RDRs give different answers |
| 9 | Empty / no-rows table | conforms vacuously (0009 states this explicitly) | holds trivially | clean |

**Summary of breaks**: class 4/5 (every legal escape row — the whole point of the feature) is a **fidelity loss** that degrades into a safety hole under 0009's sole-discriminator pin. Class 8 is an **outright failure**: the two Final RDRs specify contradictory behavior, and neither can be implemented without picking one.

Classes 1–3, 6, 7, 9 hold. The invariant "an escape row bears no owned-state mutation" is *preserved* across the seam in every class where the row is still identifiable as an escape row; the defect is that the seam does not preserve *escape identity itself*.

## Double-enforcement / duplication assessment (asked directly)

**Verdict: not a duplication defect. The two checks are deliberately, and correctly, non-identical.** 0009 is explicit that the kernel predicate is length-based and the authored predicate is presence-based, and it argues the asymmetry rather than assuming it:

A-QUOTE: "an empty Writes slice reaching the kernel is a Go representation detail that cannot mutate owned state."

A-QUOTE: "*Locus* — one exported function, called at both sites, so any future change is a single-site edit that cannot desynchronize the two enforcement points."

The "one predicate, two call sites" clause scopes to the *kernel's* two call sites (`Resolve` entry and construction-time producer calls), not to the kernel-vs-normalizer pair. Kernel-side and normalizer-side are two *different* predicates over two different representations, and 0009 says so. That is sound layering, not duplication.

The residual risk 0009 already names and mitigates is the inverse — under-enforcement, not double-enforcement:

A-QUOTE: "**Risk**: RDR 0002's implementer treats the kernel precondition as *the* enforcer and skips or weakens load-time rejection, so table authors get an exit-2 internal error instead of a load diagnostic naming their rule."

That mitigation (Phase 3 normative fixtures + a Prerequisite binding 0002's implement stage) is adequate *in form*. It is defeated in *substance* only by Findings 1 and 3: a fixture set cannot bind 0002's build if the row representation it asserts over is undetermined, and a "renders write-free" assertion is vacuous over a dump that has already dropped escape identity.

## Does enforcing shape conformance in the normalizer require RDR 0002 to emit a validation category or failure mode it does not declare? (asked directly)

**Category: no. Failure mode: yes — one, plus a decoder requirement.**

- The *category* is already there. RDR 0002 declares "malformed escape declaration" in its Normative Contracts validation-category list and again in Failure Modes. 0009's authored-path clause routes to exactly that category and mints nothing. This half of 0009's Overrides claim holds.
- The *failure mode* is not. `writes = []` on an escape rule is a new rejection trigger (Finding 2) that 0002 does not enumerate, and honoring it requires presence-tracking decode that 0002's Technical Design does not specify and its A1/A3 spikes did not exercise. 0002's `New Dependencies` pins `github.com/pelletier/go-toml/v2`, whose default struct decode does not preserve the empty-vs-absent distinction.
- Separately, RDR 0002's A5 ("Standard parse and validation failures can be surfaced through the existing CLI error envelope") is stated over *load/lint* failures only. 0009 adds a **runtime** breach on the same conceptual invariant, surfaced through the same envelope with a new stable code `escape-row-shape-breach` and a new `omitempty` identity field. 0009 argues at length (A2, A9) that this is additive to RDR 0005 and does not reopen it — that argument is sound and I do not contest it. It is noted here only because RDR 0002's Existing Infrastructure Audit row "Structured CLI failures … Extend … Add stable parse/lint refusal codes later" scopes the extension to *parse/lint* codes, and 0002 is silent on a runtime sibling code for the same invariant. Cosmetic; recorded for completeness, not raised as a finding.

## Not escalated to exhaustive enumeration

Per the scope rule, exhaustive enumeration is warranted only when a blocks-impl finding cannot be fixed without listing the rest. Findings 1, 2, and 3 are each independently fixable by a single-clause edit to one RDR:

- Finding 1 — RDR 0002 states whether the normalized escape row carries a `Writes` field (write-free) or omits it, and whether the normalizer's row type is `resolve.Row`.
- Finding 2 — one of the two RDRs moves: either 0002 adds `writes = []` to its rejection triggers and its decoder requirement, or 0009 drops the empty-block clause from Phase 3.
- Finding 3 — RDR 0002's dump-derivation contract adds `row kind` and `escape failure classes` to its enumerated field list, reconciling it with 0002's own Round-Trip invariant.

None of the three requires enumerating the others to fix. The input-class table above is supplied because the round-trip assertion was requested per class, not because escalation was triggered.

**Note on precedence**: Finding 3 is a defect *internal to RDR 0002* (its Round-Trip invariant and its dump contract disagree with each other) that RDR 0009 converts from a review-fidelity issue into a safety issue by pinning escape identity to a single field. Fixing it is a 0002 edit; the reason it is now blocking is 0009. Hence joint ownership.
