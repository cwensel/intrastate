## Finding 1 — RDR 0006's acceptance guarantee is stated over an invariant set that has no unevaluability category, and RDR 0007's runtime can refuse a lint-passing table

```
TYPE: gap
```

**A-QUOTE:**
> "Aggregation is resolution-level, not merely per-guard: if any surviving candidate row's guard is GuardUnevaluable, the resolution MUST refuse guard_unevaluable — a decided-GuardTrue sibling row MUST NOT be selected while an unevaluable candidate exists."

and, on where absence comes from:

> "Value-comparing guard operators (equality, membership, bounded integer comparison, set containment) are PARTIAL over the assembled evaluation view: an atom whose referenced tag key is absent from the view MUST evaluate to unevaluable — never to false and never to true."

**B-QUOTE:**
> "Graph lint MUST check at least these blocking invariant classes: dangling edge, dead end, determinism/overlap, guard exhaustiveness/gap, single-valued state, owned-set-before-match, and declared terminal/escape handling."

and the acceptance promise built on that set:

> "Graph lint MUST be a blocking acceptance gate over the normalized transition model. A model with any blocking lint finding MUST NOT be accepted for resolver use or CI success."

and — the only place RDR 0006 comes near the subject, in non-normative prose:

> "Runtime refusal remains separate. Lint proves that the designed graph has no known static defects; RDR 0001's kernel still refuses bad runtime inputs such as missing artifacts, unavailable observed tags, unmodeled recognized outcomes, or guard values that cannot be evaluated for a live call."

**EXPLANATION:** RDR 0006's seven-class mandatory taxonomy has **no category for "this guard reads a tag that may be absent at runtime"** — its `graph-owned-before-write` check covers only *owned* tags reachable from predecessor writes, while RDR 0007 makes presence **provenance-blind** ("A guard atom MUST NOT be decided differently according to how a tag reached the view"), so an *observed* or *recognized* tag read by a value-comparing atom is exactly the unevaluability source that no RDR 0006 invariant inspects and that RDR 0006's own `owned-set-before-match` check is scoped away from by construction.

**Answering the probe directly — can lint pass a table RDR 0007's runtime refuses?** Yes, and the minimal witness is one row: a single candidate row guarded `observed_tag eq v`, in a model with declared terminals, no dangling references, one row per state/outcome (no overlap), and finite-domain coverage over the declared `[true, false]` domain. Every one of RDR 0006's seven blocking invariants passes. At runtime, if `observed_tag` is absent from the assembled view, RDR 0007 makes the atom unevaluable, the row a SURVIVOR ("A row whose guard evaluates to GuardTrue or GuardUnevaluable is a SURVIVOR"), and the aggregation veto refuses the whole resolution with a **non-escapable** `guard_unevaluable`. RDR 0007 concedes this is not hypothetical but is the *current fixture corpus*: "every value-comparing atom in those fixtures becomes `guard_unevaluable` the moment its tag is absent from a view", naming `0003-…/evidence/spikes/guard-fixture.toml` (`cluster_eligible`, `provenance = "observed"`) and `0002-…/evidence/spikes/rdr-fixture.toml`.

**Is RDR 0006's guarantee language actually overclaimed?** This is the finding's hinge, and it is worth being precise rather than scoring the easy hit. RDR 0006 does *not* claim runtime totality — it disclaims it twice, in the Approach paragraph quoted above and in Consequences ("lint is not a promise that every future call has complete artifacts or observed context"). Those disclaimers are real and they are why this is `gap` rather than `contradiction`. **The gap is that the disclaimer is doing work the normative blocks never authorized it to do.** RDR 0006's disclaimer covers runtime refusals whose *cause is a live input* — a missing artifact, an unavailable accessor. RDR 0007 introduces a refusal whose cause is a **property of the authored table**: a guard that names a value-comparing operator over a tag with no presence guarantee is unevaluable-prone *by construction*, statically visible in the normalized row, and discoverable by exactly the finite-domain predicate machinery RDR 0006 already mandates for coverage. That class is a *static defect wearing runtime clothing*, and RDR 0006's disclaimer swallows it only because RDR 0006 could not have known the class existed. The phrase "no **known** static defects" is load-bearing in RDR 0006's favor and against it simultaneously: the set of known static defects grew when RDR 0007 locked, and RDR 0006's `MUST check at least` floor was never raised to match.

**Neither RDR owns the static-detection obligation.** RDR 0007 considered and rejected owning it, under *Briefly Rejected*: "**Lint-only totality (statically reject guards over possibly-absent tags)**: observed-tag presence is a runtime fact; a static rule either rejects nearly every legitimate observed-tag guard or proves nothing". That rejection is sound as stated — a *blocking* static rule would be intolerable — but it disposes of a **blocking** lint rule, not of an **advisory** one, and RDR 0006 has a slot for precisely that shape which no RDR has claimed: "Non-blocking advisories may exist for redundant rows or unreachable rules only if they do not weaken the mandatory acceptance gate." So the disposition is: RDR 0007 declined blocking-lint ownership on reasoning that does not reach advisory lint; RDR 0006 owns the advisory surface but is silent on the class; the obligation is unowned. RDR 0007 routes six other obligations to named destinations (A6b→RDR 0004 implement, A10/A15→RDR 0003 Phase 1, A12→both RDR 0003 and RDR 0006 implement stages) — this one it did not route, because it believed it had disposed of it.

**SEVERITY:** risks-impl

*Why not blocks-impl:* both RDRs are implementable as written and their outputs do not conflict — a table can be linted, accepted, and then refused at runtime with each RDR behaving exactly as specified. What is lost is a design-time warning the maintainer would want, and the calibration of RDR 0006's user promise. No test is prevented and no decision is deadlocked, which is the blocks-impl bar. It is not cosmetic because RDR 0006's Problem Statement is *"illegal or incomplete transition graphs caught at design time instead of discovered at runtime"*, and this is a defect class discovered at runtime, one call at a time — the precise failure mode RDR 0006 rejects "Runtime-only resolver refusal" for ("it discovers design defects one call at a time instead of rejecting the graph").

**OWNERSHIP:** joint

**BLOCKS:** The decision of whether an unevaluability-risk check enters RDR 0006's finding taxonomy, and at what severity. Concretely it blocks fixing RDR 0006's MVV finding-code matrix, which enumerates a closed list — "The illegal fixture matrix must assert `graph-dangling-edge`, `graph-dead-end`, `graph-overlap`, `graph-coverage-gap`, `graph-unprovable-coverage`, `graph-single-valued-state`, `graph-owned-before-write`, and `graph-terminal-escape`" — with no slot for an unevaluability advisory, so RDR 0006's implement stage will encode a fixture corpus that cannot express the class even as a warning. It also blocks RDR 0007's Phase 3 authoring handoff from telling an author *at authoring time* which of their guards are unevaluability-prone; today RDR 0007 can only tell them after a refusal ("Recovery: make the artifact state readable, or rewrite the guard with an explicit existence atom if absence was intended").

## Finding 2 — RDR 0006's exhaustiveness invariant proves a property the aggregation veto makes unachievable at runtime

```
TYPE: contradiction
```

**A-QUOTE:**
> "This veto is intended, and it is the cost the RDR accepts: one unreadable row refuses a table whose other rows decide cleanly."

and the reason it cannot be narrowed:

> "Narrowing the veto would require deciding that an undecided edge is a non-edge, which is absence-as-false at resolution scope."

**B-QUOTE:**
> "**Guard exhaustiveness / gap** — for each state/outcome pair that claims closed coverage, finite-domain input assignments must either match exactly one modeled row or a declared escape row."

and:

> "Graph lint MAY claim exhaustiveness only over finite declared domains supplied by the predicate/tag model. If a required dimension is not finite, lint MUST emit a blocking inability-to-prove finding for any contract that depends on closed coverage."

**EXPLANATION:** RDR 0006's exhaustiveness invariant proves "**every** finite-domain input assignment matches exactly one modeled row or a declared escape row" — a promise of *closed coverage*, which to a table author reads as "this partition always resolves" — but RDR 0007's aggregation veto makes closed coverage insufficient for resolution in two independent ways that RDR 0006's proof cannot see, and the second is the sharper one.

**Failure (i) — the proof's domain excludes absence.** RDR 0006's proof quantifies over "finite-domain input assignments" drawn from declared domains; RDR 0007 establishes that absence has no standing in that product, and does so with a verified assumption rather than a guess. A12: "RDR 0002's tag-declaration schema has **no optionality field**, and a sweep for `optional|nullable|required|absent` across every TOML in the RDR tree returns zero rows". So the *absent* case is not a member of the assignment space lint enumerates — lint proves coverage over the presence-complete assignments only, and every assignment with a missing tag is outside the proven set. RDR 0006's guarantee is therefore conditional on total presence, a condition it never states.

**Failure (ii) — the veto is not a coverage property at all, and this is what makes it a contradiction rather than a second gap.** Even restricted to assignments where every tag *is* present, "matches exactly one modeled row" is what RDR 0006 proves; RDR 0007 then adds a rule that operates *after* matching and *outside* coverage reasoning: a matching row whose guard is unevaluable does not fail to match — it **survives** and **vetoes the resolution**, including a sibling that lint proved was the exactly-one match. "a decided-GuardTrue sibling row MUST NOT be selected while an unevaluable candidate exists". Lint's exactly-one proof and the runtime's selection therefore come apart on an input where lint's own theorem holds: lint says one row matches, runtime says no plan. This is not lint being silent about a runtime input class — it is lint's *conclusion* being falsified on inputs inside its own quantifier, which is why this reads as contradiction and Finding 1 reads as gap.

**Why RDR 0006 cannot repair this locally, and why the escape valve does not apply.** RDR 0006's one relief mechanism for an unprovable guarantee is `graph-unprovable-coverage`, gated on finiteness: "If a required dimension is not finite". Unevaluability is not a finiteness failure — every domain involved is finite and declared — so the valve does not fire, and lint reports a *clean* exhaustiveness proof for a partition the runtime can refuse. RDR 0006's own Risks section names this exact hazard and believes it mitigated: "**Risk**: Exhaustiveness checks overclaim on open domains. **Mitigation**: Require finite declared domains for closed-coverage claims" — the mitigation is scoped to *open domains*, and the overclaim RDR 0007 introduces happens on **closed** ones. RDR 0007 is likewise unable to see the problem from its side: it reasons about disjointness at runtime and explicitly flags the wrong-forum error in A5's *Carried constraint* ("the sub-clauses above establish disjointness at *runtime*, over assembled views, which is the wrong forum for the binding risk"), but it applies that correction only to the two-row absence pattern's **overlap** exposure, never to **exhaustiveness**. Each RDR is individually well-reasoned; the contradiction is in the composition.

**Bounding the claim.** RDR 0006's Consequences bullet — "Some live failures remain runtime refusals by design" — is the strongest defense available, and it fails here for a specific reason: it justifies runtime refusals on *bad inputs*, whereas the veto refuses on an input lint certified as good. And RDR 0007 forecloses reading the veto as a rare edge: it declines to bound the frequency, recording that "how *often* the veto fires on tables whose rows are unrelated in practice … is an empirical question with no installed base to answer it", carried as "accepted risk rather than scored away".

**SEVERITY:** blocks-impl

*Why blocks-impl:* RDR 0006's MVV requires a passing legal fixture — "It must pass one legal transition model and fail one illegal model for each blocking invariant class" — and Testing Strategy scenario 1 requires that legal model to carry "all mandatory declarations and **finite-domain coverage**". The implementer must decide what claim the green `graph-coverage-gap` result licenses. Under RDR 0007 it licenses strictly less than RDR 0006's invariant states, and RDR 0006 supplies no weaker wording to encode. This is not a documentation nicety: the coverage invariant is one of the seven MUST-check classes, and its meaning must be fixed before Phase 2 ("Implement the mandatory graph checks over normalized rows, finite domains, tag provenance, declared terminals, and owned writes") can be written.

**OWNERSHIP:** joint

**BLOCKS:** RDR 0006 Phase 2 (Invariant Engine) implementation of the guard-exhaustiveness check, and its Testing Strategy scenario 1 assertion. Neither can be encoded until it is decided whether closed coverage is claimed over presence-complete assignments only, and whether an exhaustiveness pass is permitted to imply "this partition resolves" when the aggregation veto can refuse an assignment inside the proven set. Also blocks RDR 0007 Testing Strategy scenario 8, which already carries a routed load-time precondition on RDR 0006 but names only overlap: "the vector is unreachable until RDR 0003's implement stage discharges A12 (projection) and A15 (the conjoined value-row shape)."

## Finding 3 — RDR 0003 hands the `unevaluable guard` semantic kind to RDR 0006's lint-finding mapping, and RDR 0006 never receives it

```
TYPE: gap
```

**A-QUOTE:**
> "The kernel maps GuardUnevaluable to the refusal kind `guard_unevaluable`, which is not a modelable escape class (RDR 0002). Missing artifact state MUST NOT be maskable behind an escapable refusal class."

and, on where the missing-tag diagnostic is routed:

> "`GuardResult` carries no missing-tag payload, so \"which tag was absent\" is inferable only from the guard text; if that proves insufficient in practice, the enrichment belongs to RDR 0003's semantic-kind diagnostics (Phase 3 hands it off), not to a kernel enum change."

**B-QUOTE:** silent.

RDR 0006's finding taxonomy is closed against it — eight codes, none covering unevaluability:

> "| Invariant | Stable Code |
> | Dangling edge/reference | `graph-dangling-edge` |
> | Dead end | `graph-dead-end` |
> | Determinism / overlap | `graph-overlap` |
> | Guard exhaustiveness / gap | `graph-coverage-gap` |
> | Required finite-domain proof unavailable | `graph-unprovable-coverage` |
> | Single-valued state violation | `graph-single-valued-state` |
> | Owned-set-before-match | `graph-owned-before-write` |
> | Declared terminal/escape handling | `graph-terminal-escape` |"

**EXPLANATION:** The third party makes this a documented broken handoff rather than an inference. **RDR 0003 A4 explicitly assigns the mapping to RDR 0006** — "This RDR owns predicate semantic kinds such as unknown operator, type mismatch, literal parse failure, and **unevaluable guard**; **RDR 0006 owns graph-lint finding codes** for non-exhaustive and overlapping row groups; RDR 0005 owns the CLI command/envelope mapping" — and RDR 0003's Testing Scenario 4 requires that chain be demonstrated end to end: "one documented ownership chain from predicate semantic kind through RDR 0006 lint finding to RDR 0005 CLI envelope." RDR 0006 receives four of RDR 0003's named semantic kinds into its taxonomy and drops `unevaluable guard` on the floor; the word appears **zero times** in RDR 0006. RDR 0007 then hardens `unevaluable guard` from one of several predicate kinds into the RDR's entire subject — non-escapable, resolution-vetoing, and load-bearing on absence — without noticing that its static counterpart was assigned to a peer that never took delivery.

**Why this is distinct from Finding 1 and not a restatement.** Finding 1 is about a *defect class* nobody detects. This is about a *named obligation* with an explicit source, an explicit destination, and an explicit test scenario requiring the chain to close — RDR 0003 wrote the handoff, RDR 0006 predates the cargo, RDR 0007 changed what the cargo weighs. The two findings would be fixed by different edits: Finding 1 by adding a detection rule, this one by RDR 0006's implement stage accepting an already-assigned mapping obligation. Finding 1 could be resolved "no detection is worth it" and this one would still be open, because RDR 0003 Scenario 4 would still fail.

**Reachability check — is `unevaluable guard` even a lint-time kind?** This is the obvious objection and it does not hold. RDR 0003 lists it beside *unknown operator*, *type mismatch*, and *literal parse failure* — all load-time kinds — which suggests RDR 0003 considered it load-time too; and RDR 0007 confirms a lint-time reachable instance exists independent of runtime views. A15 establishes that RDR 0003 "neither admits nor forbids two operator keys on one tag-table", so a guard whose *shape* cannot be resolved into atoms is a load-time defect; and RDR 0007's own Normative Contracts create a second load-time-adjacent class — the mapping-failure case it forbids from ever reaching the verdict channel: "a well-loaded guard the evaluator cannot parse is a defect in the evaluator, not a fact about the view. Such a failure MUST NOT be reported as GuardUnevaluable". RDR 0007 asserts that case is "unreachable for any guard that passed lint" **because** "Unknown operators and undeclared tags are already rejected at load (A1, A7)" — a claim that leans on lint catching it, while RDR 0006's taxonomy has no code under which lint would report it. RDR 0007's safety argument for its most severe clause (the one whose sanctioned failure surface is a PANIC — "the only out-of-band surface that exists is a PANIC") is thus grounded in a lint guarantee RDR 0006 does not enumerate. A7's own "If wrong" branch anticipates this shape: "a vocabulary lint must then be added to RDR 0003's obligations before this RDR's rule is safe."

**SEVERITY:** risks-impl

*Why not blocks-impl:* the escape route is real — A7 verifies that the undeclared-key rejection is anchored in **RDR 0002's** validation-category block rather than RDR 0006's ("the normative MUST-reject for an undeclared key is RDR 0002's validation-category block … Cite RDR 0002 for the hard obligation"), so the specific undeclared-key case RDR 0007 leans on is covered elsewhere and the panic clause is not left unguarded. What remains at risk is RDR 0003's Scenario 4 chain, which is a real named test with a real gap, and the residual lint-shape cases (A15's unresolvable atom shapes) that RDR 0002's category does not reach.

**OWNERSHIP:** single-RDR — RDR 0006. RDR 0003 already discharged its half by naming the kind and the destination; RDR 0007 hardened the semantics within its own scope. The unreceived mapping sits in RDR 0006's taxonomy alone, and RDR 0007's A12 already establishes the precedent for routing an obligation to RDR 0006's implement stage ("RDR 0006's must define row-group membership"), so the destination exists and is in use.

**BLOCKS:** RDR 0003's Testing Scenario 4 — the documented ownership chain from predicate semantic kind through RDR 0006 lint finding to RDR 0005 CLI envelope — which cannot be satisfied for `unevaluable guard` because the middle link has no code. Downstream it blocks RDR 0006's Cross-Cutting "Versioning" commitment ("lint finding codes and JSON payload fields must be stable and **append-only**"): adding the missing code after RDR 0006 ships is append-only-compatible for the *code list*, but the `graph-coverage-gap` semantics change Finding 2 requires is not, so the two must be decided together rather than deferred.

## Round-trip / inverse invariant pass

Both RDRs disclaim owning an encode/decode pair, and RDR 0006 says so explicitly:

> "This RDR introduces no encode/decode, import/export, or inverse operation. Parse/render fidelity remains owned by RDR 0002. Lint determinism is covered by the finding identity decision and the Minimum Viable Validation."

The seam nevertheless carries one composed inverse — **the static-verdict ↔ runtime-verdict correspondence**, i.e. "lint accepts model M" ought to invert to "runtime resolves M for every input lint quantified over". Finding 2 is that round-trip failing, and it is reported there as `contradiction` per the instruction to treat a fidelity-losing round-trip as a contradiction even where neither RDR's prose is individually wrong. Recording the shape once, explicitly, so it is not lost as a mere coverage quibble:

- **Forward (lint):** for each state/outcome pair claiming closed coverage, every finite-domain assignment matches exactly one modeled row or a declared escape row.
- **Inverse (runtime):** for that same assignment, resolution yields a plan.
- **Break:** the inverse fails on two disjoint input classes — (a) assignments outside lint's quantifier because absence has no domain standing (A12: no optionality field anywhere in the tag schema), and (b) assignments **inside** lint's quantifier where a matching row is unevaluable and the aggregation veto refuses the resolution lint proved was exactly-one. Class (b) is the fidelity loss proper: the forward proof holds and the inverse still fails.

Two further inverses were checked and are **clean**, and are recorded to bound the finding:

- **Lint finding identity ↔ re-run.** RDR 0006's identity tuple `(model id, invariant code, source rule/context id or graph element id, normalized predicate/write fingerprint)` and its deterministic-order contract are self-contained and unaffected by anything RDR 0007 introduces; RDR 0007 adds no lint findings. Idempotent.
- **Refusal identity ↔ row identity.** RDR 0007 pins `Refusal.Rows` as `[]resolve.RowRef` carrying "the shipped `(RuleID, SourceLocator)` source-identity pair", which is the same source-identity pair RDR 0006 requires its findings to carry ("the source rule/context id or source span when the normalized model can provide one"), both sourced from RDR 0002's normalized rows. A runtime refusal and a lint finding on the same row are therefore correlatable by a common key — the one place the static/runtime seam composes cleanly, and worth preserving in whatever fix Findings 1–3 receive.

## Enumeration discipline

Escalation to exhaustive enumeration was **not** triggered. Finding 2 is the sole `blocks-impl` finding, and its fix is local to RDR 0006's `graph-coverage-gap` semantics plus a decision on the veto's interaction with coverage; it does not require listing the remaining invariant classes.
