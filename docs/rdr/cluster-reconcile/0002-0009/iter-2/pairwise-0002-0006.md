### G3 — `<clear>` is a value-space sentinel in the normalized writes, and 0006 re-pairs "writes" and "clears" from it

TYPE: round-trip
A-QUOTE (0002:673-677, fenced): "Normalization MUST populate the next-state tags with the tag values the rule's write block and clear list produce, and the writes with the owned-tag writes the accessor layer applies — the same rendered set, including `<clear>` entries"; and (0002:936-938) "the `<clear>` sentinel is not reserved in the tag-value space, so an authored value of `<clear>` renders identically to a cleared tag" — listed among "Three sites [that] make the **rendered form** lossy" while "the normalized value is the contract" (0002:941-942).
B-QUOTE (0006:494-496): the input contract lists "match predicates, guard predicates …, writes, clears" as distinct inputs; (0006:1044-1046) an edge produces "the node with that row's writes applied and clears removed".
EXPLANATION: the normalized value's writes field is a `[]Tag` of key/value strings on `main` (0002:1466: "On `main` both are `[]Tag` slices"), so a clear reaches the value — not just the dump text — as the string `<clear>`; 0002 does not reserve the string at load. On the input class *a rule that writes the literal value `<clear>`*, 0006 (and RDR 0004, which applies the writes) cannot re-pair the authored `clear` list from the writes set — a fidelity loss 0002 misclassifies as rendering-only. The fix is one load-time category (reject `<clear>` as an authored tag value), which 0002 did not state.
SEVERITY: risks-impl
OWNERSHIP: single-RDR (0002 — the value-level ambiguity is internal to its own normalized-value contract and its own lossy-site classification)
BLOCKS: 0006 invariant 6 and the reachability dataflow on that input class (a "clear" that is actually a write of `<clear>` removes a key lint should see as held); 0002 Scenario 2's "writes are deterministic" assertion cannot distinguish the two.
LEDGER: NET-NEW — adjacent to iteration-1 row `0009-0004 | <clear> sentinel reaches 0004, which never mentions "clear"` (`report.md:103`), which the report homed as "JD-12 `<clear>` sentinel semantics at the write accessor" (`report.md:179`); the JDR's §JD-12 is a different entry (guard enforcement site) and the word "clear" occurs zero times in the JDR, so that iteration-1 tolerance was never given a home. Flag for the parent.
