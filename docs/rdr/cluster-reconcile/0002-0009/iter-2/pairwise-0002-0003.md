## Findings

### F1 — match/guard split keyed on operator (0002 handoff) vs on authored block (0003 lint)

TYPE: round-trip (contradiction across the seam)
A-QUOTE (0002:703-708): "the handoff MUST route each atom to exactly one of them: atoms whose operator is equality on a declared tag populate `Match`; every other atom — set membership, comparison, existence, and every `unless` atom regardless of operator — belongs to the guard predicate." Corroborated by A12 (0002:274-278): "the `unless`-block equality atom (`status.eq=closed@unless` in the kata fixture), which routes to the guard despite being an equality operator."
B-QUOTE (0003:1149-1154): "**The match/guard split is per atom per group, not per key per model.** … Participation is therefore decided by where each atom is authored **within the group being proved**"; and (0003:1138-1143) "**Match keys are not product dimensions.** A row's match pattern … is a separate field from its guard both in RDR 0002's authored shape (`[rule.match.*]` vs. `[rule.guard.*]`) and in the normalized row the kernel consumes"; and (0003:1360-1362) "A row \"can refuse\" when the row carries a value atom over a key **declared optional** **in either block** — `all` or `unless`".
EXPLANATION: 0002 decides *which atoms are the guard's* by operator (+ `unless`), 0003 decides product participation and the "can refuse" narrowing by authored block (`match` vs `guard.*`); the two partitions differ on two input classes. (a) A non-`eq` atom authored under `[rule.match]` over an optional key (e.g. `k.in = […]`, `k.gte = n`, `k.exists`) — 0003 excludes it from the product and from the can-refuse test (match keys are the grouping context, not guard atoms), so the group can certify green; 0002 routes it to the guard, so at runtime an absent `k` is `guard_unevaluable` (RDR 0007 domain rule) — **a false green, outright failure of P5**. (b) An `eq` atom authored under `[rule.guard.all]` over an optional key (0003's own fixture row `foundational-to-cove`, `profile eq "foundational"`, 0003:1536) — 0003 withholds the claim (`row-can-refuse`); 0002 routes it to `Row.Match`, where an absent key is a silent non-candidate (escapable `no_match`, never a refusal) — a fidelity loss in the conservative direction, and it also moves the witness 0002's own Scenario 4 (0002:1474-1475, "a sibling candidate's guard is unevaluable") depends on. Neither document's prose is individually wrong; the seam is.
SEVERITY: blocks-impl
OWNERSHIP: joint — 0002 owns the routing ("this RDR owns the split", 0002:694), 0003 owns participation and the withholding test, RDR 0007 owns absent-key semantics; no home entry covers which atoms are guard atoms (§D1/§D4 fix atom shape and presence enforcement, not the Match/Guard partition).
BLOCKS: 0003 MVV Scenario 8 (withheld claim naming the refusing atom) and 0006 `graph-unprovable-coverage`/`row-can-refuse` — the atom lint names may not be a guard atom at runtime; 0002 MVV Scenario 4's unevaluable-sibling case; the P5 promise for any group whose `[rule.match]` carries a non-equality atom.
LEDGER: NET-NEW

### F2 — the five type-model fields have no wire spelling anywhere

TYPE: gap
A-QUOTE (0002:807-818): "A tag declaration also carries its **type model** — value kind, and optionally a finite domain, an optionality marker, a set-element universe, and a single-valued marker. … This RDR owns where a declaration is authored — under `[tags.<tag>]`, beside `provenance` and the optional accessor reference"; together with (0002:431-432) "The source schema MUST use the Resolve spike field layout", (0002:465-467) "The decoder MUST reject unmapped keys so an unknown schema field is a stable refusal", and (0002:887-888) "The RDR and kata spike fixtures are the canonical examples implementation tests must promote."
B-QUOTE (0003:1658-1660): "The `single_valued` spelling above is illustrative: the field's authoring location is RDR 0002's to fix (**A16**), which is why this block shows a shape rather than asserting one." Yet 0003 normatively fixes one spelling itself (0003:960-961): "notation, not wire spelling: the authored form is two fields, `min` and `max`". And A16's own done-condition (0003:538-540): "\"`single-valued` occurs in RDR 0002's authoring schema, citing this RDR for meaning\" is met to the letter".
EXPLANATION: The JDR's ownership correction gives 0002 "authoring location under `[tags.<tag>]`"; 0002 fixes the *location* (under `[tags.<tag>]`) but names no TOML key for any of the five fields, while its spike fixtures — the canonical examples — declare none of them (0003:161-162: "a fixture declaring none of the five fields") and its strict decoder refuses unmapped keys; 0003 defers the spelling to 0002 except for `min`/`max`, which it fixes normatively (a leak of 0002's wire-format charter). A16 was closed on the *prose name* appearing in 0002, not on a key an author can write; two implementations (and 0003's Phase 3 fixture declaring `single_valued` on six tags, 0006's fixtures needing an explicit always-present marker) can spell the fields differently and none is portable.
SEVERITY: risks-impl
OWNERSHIP: single-RDR (0002 — the wire-format owner is silent; 0003:960-961 is a secondary duplication to retire once 0002 names the keys)
BLOCKS: authoring any fixture that carries the type model (0003 Scenarios 2, 4, 5; 0006 Scenario 11) against a spelling both documents agree on; 0002 Scenario 3's `unknown schema field` control cannot be told apart from a mis-spelled type-model key.
LEDGER: NET-NEW (traces to the JDR "Ownership corrections" rehoming, which assigned authoring location to 0002 without a spelling done-condition)

### F3 — who rejects a bad declaration, inside whose pipeline, under which category

TYPE: gap
A-QUOTE (0002:851-860): "**\"Load\" names the whole source-to-candidate-rows pipeline, not one callable.** Every category above MUST be refused by that pipeline before it yields candidate rows"; the category list (0002:827-839) carries no type or value-domain category, and (0002:868-871) "Category identifiers are **snake_case renderings of the prose names above** … these identifiers are an API surface, not message text."
B-QUOTE (0003:1060-1067): "a malformed *declaration* (domain disagreeing with its kind) is rejected by the declaration loader before normalization completes, since normalization carries declarations it must first be able to trust; a *literal-outside-domain* is rejected by guard parsing after normalization has supplied the declaration to check against, and before resolution. Both surface through the predicate semantic kinds this RDR owns (A4) onto RDR 0006 findings and the RDR 0005 envelope."
EXPLANATION: 0003 places a rejection *inside* 0002's load pipeline ("before normalization completes") and a second one *after* it ("after normalization has supplied the declaration"), but 0002's pipeline contract enumerates exactly its own categories and its identifier set is an API surface, so a declaration/kind error has no category to travel under and no named caller; and 0003 routes both kinds "onto RDR 0006 findings" while 0006 mints no code for anything refused before normalization (0006:821, "refused before normalization; lint never runs | none of this RDR's codes"). Not a restatement question — the rehoming moved meaning to 0003 and left the *invocation site* of 0003's validators unnamed in 0002.
SEVERITY: risks-impl
OWNERSHIP: joint (0002 pipeline × 0003 semantic kinds × 0006 finding surface)
BLOCKS: 0003 Scenario 4 ("rejected before normalization completes … with a predicate semantic kind that RDR 0006 can map to a lint finding") — no document supplies the mapping or the emitting package; the CLI category name for a declaration error (RDR 0005's A5-style work) has no data-level identifier to render.

### F6 — literal identity: byte-exact sequence (0002) vs typed set (0003)

TYPE: gap
A-QUOTE (0002:583-593): "**Literals carry the same byte-exact identity as keys, and a set literal is a sequence, not a joined string.** A set-valued literal MUST normalize to an ordered sequence of its members, each compared byte-exactly … Members sort byte-lexicographically".
B-QUOTE (0003:1377-1384): "A set literal … has one canonical spelling: an unordered set of typed elements, duplicate-free, and compared as a set … Implementations MUST canonicalize before the literal enters the identity tuple"; and (0003:1063-1065) typing happens "after normalization has supplied the declaration".
EXPLANATION: 0002's normalized value carries literals as byte strings sorted byte-wise (so `[10, 9]` canonicalizes as `10, 9`), 0003 types them against the declared kind *after* normalization and compares as a set — compatible as long as the byte-sorted sequence is the agreed canonical form of 0003's set, but no document says so, and 0003's "duplicate-free … rejected at parse" is a rejection 0002 relies on (0002:647-648) without listing a category for it.
SEVERITY: cosmetic
OWNERSHIP: joint
BLOCKS: nothing until a typed literal (int vs string `"3"`) reaches the identity tuple.
