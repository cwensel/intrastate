### F2 — "the same obligation" parenthetical blurs authored-vs-kernel strictness

TYPE: contradiction
A-QUOTE (0009:844-849, fenced): "an empty one (`writes = []`) is rejected too. The authored layer is therefore stricter than the kernel's length-based predicate, deliberately: authoring an empty write block on an escape rule is a statement of intent worth refusing, while an empty Writes slice reaching the kernel is a Go representation detail that cannot mutate owned state."
B-QUOTE (0002:481-483, fenced): "An escape rule MUST contain an `escape` list and MUST NOT contain a write block or clear list, even an empty one (RDR 0009 binds the same obligation at the kernel boundary)."
EXPLANATION: 0002 attaches "binds the same obligation at the kernel boundary" immediately after "even an empty one", which can be read as the kernel also rejecting an empty write set — 0009's kernel predicate is explicitly length-based and its normative fixture 3 (`empty-not-nil-conforms`, 0009:1595-1602) requires no error for `[]Tag{}`; the shared obligation is "no writes/clears", not the empty-block strictness.
SEVERITY: cosmetic
OWNERSHIP: single-RDR (0002)
BLOCKS: nothing — 0009 is the normative home and is unambiguous; an implementer reading only 0002's parenthetical could wrongly add a kernel-side empty-slice rejection, which 0009 scenario 3 would then fail.
LEDGER: JD-11 (row 3, `writes = []`).
