## Finding 1 — the guard round-trip loses atom cardinality across `Row.Guard`

```
TYPE: round-trip
```

**A-QUOTE:**
> "This RDR requires only that the mapping be total and lossless for operator, referenced tag key, literal, and block placement: an evaluator that cannot recover which tag keys an atom references cannot implement the domain rule at all."

and, from A10's resolution of how that mapping is to be built without reopening RDR 0001:

> "RDR 0003's Identity decision — \"a guard predicate is identified by its source rule/context id plus its position within `all` or `unless`\" — is already a total, unique, string-expressible key, so a key-into-atom-table mapping fits `Row.Guard string` losslessly"

**B-QUOTE:**
> "**Identity** — a guard predicate is identified by its source rule/context id plus its position within `all` or `unless`; semantic equality is the normalized tuple `(tag, operator, literal)`."

and:

> "This RDR introduces no encode/decode pair. Parse/render fidelity for the sparse TOML source belongs to RDR 0002."

**EXPLANATION:** The input class that breaks identity is **any row carrying more than one guard atom** — the ordinary case, and the case both RDRs' own illustrative TOML shows (`status.eq` + `profile.in` under one `[rule.guard.all]`): RDR 0003's Identity key is scoped to a *single* guard predicate (one atom, keyed by its position within `all` or `unless`), but the kernel hands the evaluator exactly one `Row.Guard string` per row (`resolve.go:185 Guard string`; `resolve.go:93 Evaluate(guard string, view TagSet) GuardResult`), so an N-atom row must round-trip N per-atom identity keys through a 1-slot channel — an outright failure, not a fidelity loss, because the multi-atom encoding A10 leans on does not exist in either RDR and the one A10 names cannot express N>1.

**SEVERITY:** blocks-impl

**OWNERSHIP:** joint

**BLOCKS:** Encoding of RDR 0007 Phase 2 conformance vector rows 4/6/7/8 (every row that asserts operator × presence/absence and strong-Kleene *combination* across atoms), and RDR 0003's `Phase 1: Predicate Model` step that A10/A15 name as the obligation's destination. Neither RDR can be implemented against a multi-atom row until the per-row/per-atom cardinality is reconciled. RDR 0007 concedes the dependency ("Testing Strategy rows 4–8 and the Phase 2 conformance vectors remain un-encodable until RDR 0003 Phase 1 discharges the mapping") but records it as discharged-by-naming, having verified A10 on a key whose cardinality it did not check.

**Why this is a round-trip finding and not merely A10 restated.** A10's own text treats the mapping as *unowned but demonstrably possible* and grades its "If wrong" branch as NOT triggered, resting that verdict entirely on the sufficiency of RDR 0003's Identity key. The seam-level check refutes the sufficiency claim while leaving A10's "unowned" framing intact: the emitted artifact (RDR 0002's normalized "one candidate-row predicate **set**") and the consumed artifact (one opaque string) differ in arity, and RDR 0003 has explicitly disclaimed the bridge that would reconcile them ("introduces no encode/decode pair"). No single-RDR lens sees this — RDR 0003 is correct that it owns no encode/decode pair, and RDR 0007 is correct that a *single* atom's identity is string-expressible. The defect lives in the composition.

## Finding 2 — `exists = false` in `all` versus RDR 0003's locked placement MUST

```
TYPE: contradiction
```

**A-QUOTE:**
> "A14 settles the adjacent grammar question in favor of expressibility: RDR 0003 never defines \"positive\"/\"negative\" atom, so its placement rule (\"Positive guard atoms MUST live in `all`\") is placement-only and does not read a `false` literal as making an atom negative — polarity in the literal and polarity in placement are structurally independent."

**B-QUOTE:**
> "Positive guard atoms MUST live in `all`; negative guard atoms MUST live in `unless`. Successful row matching MUST NOT depend on source order or first-match priority."

**EXPLANATION:** RDR 0007 makes `all … exists = false` — an atom that decides TRUE precisely when its tag is ABSENT — normative and load-bearing (Scenario 6, and the sole sanctioned single-row absence route after A14 narrowed A5), which is a negative atom sitting in `all` under any reading of "negative" that survives contact with the word; RDR 0007 rescues it only by construing RDR 0003's locked MUST as vacuous for want of a definition, which converts a normative constraint in a Final peer into dead text rather than extending it.

**SEVERITY:** risks-impl

**OWNERSHIP:** joint

**BLOCKS:** The decision of whether RDR 0003's placement MUST is a real authoring constraint or an unenforceable one — and therefore whether Testing Strategy Scenario 6's `all … exists = false` leg is authorable at all. A lint implementing RDR 0003's placement rule literally will reject the fixture RDR 0007 Scenario 6 requires; a lint implementing RDR 0007's A14 reading must treat RDR 0003's placement MUST as unenforceable. Both RDRs are Final, so the implementer picks one and silently breaks the other. RDR 0007's own A14 "If wrong" branch names the fallout precisely: "Scenario 6's `all … exists = false` leg is unauthorable."

**Note on the extend-vs-contradict test.** RDR 0007's general posture — fixing absent-operand behavior RDR 0003 left silent — is genuine extension, and most of its domain rule absorbs cleanly into RDR 0003's closed vocabulary without reopening it (A1 is sound: `exists` is the only absence-naming operator, and the other four are silent, not contrary). This clause is the exception: it does not fill a silence, it reinterprets a written MUST. That is the one place RDR 0007's "No peer RDR text is reopened" claim does not hold — RDR 0003's text is not reopened, but its meaning is.

## Finding 3 — `contains` over an absent set-valued tag: runtime rule fixed, lint algebra left contradictory

```
TYPE: gap
```

**A-QUOTE:**
> "In particular, an absent set-valued tag MUST be treated as unevaluable under set containment, NOT as the empty set — absence is not an empty value."

**B-QUOTE:**
> "`contains` | set-valued tag with a declared element universe | non-empty typed element set | Narrows the set-valued domain to assignments containing every listed element."

**EXPLANATION:** RDR 0003's lint proof role for `contains` is stated purely as domain narrowing over "a declared element universe" whose assignments are all *present* values, so a `contains` row's accepted-assignment set has no representation for the absent case that RDR 0007 makes a first-class third verdict — meaning RDR 0003's coverage arithmetic (`union(row_i accepted assignments) == scoped product`) will score a table exhaustive over a product that RDR 0007's runtime can nonetheless refuse as unevaluable.

**SEVERITY:** risks-impl

**OWNERSHIP:** joint

**BLOCKS:** RDR 0003 MVV Scenario 2 ("Complete partitions pass") and Phase 3's mandatory `contains` predicate — a partition lint proves complete can still refuse `guard_unevaluable` at runtime, so "exhaustive" stops meaning "no refusal". Also blocks RDR 0007 Testing Strategy Scenario 7, which asserts the runtime half with no lint-side counterpart.

**Relation to the recorded A12 obligation.** RDR 0007's A12 routes the *existence-atom* projection question to RDR 0003's implement stage and confines the fallout to the two-row absence pattern's load-time legality. This finding is the same silence reached from the other side and with wider blast radius: A12 asks whether an `exists` row projects onto the declared-domain product, whereas the exposure here is that **every value-comparing operator** now has a runtime verdict — unevaluable — with no image in RDR 0003's assignment algebra at all. RDR 0007 makes absence semantically load-bearing for `eq`/`in`/comparison/`contains` alike, but only routes the `exists` projection. The coverage/overlap arithmetic RDR 0003 locks is therefore under-specified against RDR 0007's runtime for the other four operators, and no assumption in either RDR carries that case.

## Round-trip / inverse-invariant pass — summary

RDR 0003 declares no encode/decode pair of its own, but the pair exists across the seam whether or not either RDR claims it: RDR 0002 emits normalized rows carrying a guard predicate **set**, the kernel transports one opaque `Row.Guard string`, and RDR 0003's evaluator must reconstruct the atom structure RDR 0007's domain rule quantifies over. The invariant that must hold is *reconstruct(transport(atoms)) == atoms*, for operator, referenced tag key, literal, and block placement.

| Input class | Invariant holds? | Disposition |
| --- | --- | --- |
| Row with no guard (`Guard == ""`) | Yes | `evaluateGuard` answers `GuardTrue` before the seam; RDR 0007's unguarded-row clause matches. |
| Row with exactly one `all` atom | Yes, if a side table exists | RDR 0003's Identity key is total and string-expressible for one atom; A10's fallback works here and only here. |
| Row with N>1 atoms (`all`, or `all`+`unless`) | **No** | Finding 1 — N per-atom identity keys, one string slot. Outright failure. |
| Row whose `unless` block is omitted | Not observable | RDR 0007 Scenario 9(b) concedes it: such a row reaches the kernel as `Guard == ""`, so the empty-`unless` identity RDR 0007 fixes is untestable at the seam it binds. |

The second and fourth rows are worth flagging together: RDR 0007 fixes the empty-`unless` identity normatively (A9) and simultaneously records that the kernel cannot see it, so the clause binds only the future evaluator's internal vectors — which are the same vectors blocked by Finding 1.
