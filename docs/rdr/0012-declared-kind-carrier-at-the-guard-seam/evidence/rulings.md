# RDR 0012 — rulings

## 2026-09-20 — resolve

- **Q1** — RULED: Option (a), widened — canonicalize int spellings at load. Reject non-canonical spellings at every authoring site: guard literals, match literals, `[initial]` values, and `[rule.write]` values. The rule is `strconv.Itoa(n) == authored` after `Atoi` (which also rejects `-0`), and it must cover the bare-float path (`eq = -0.0` renders literal `"-0"` via `FormatFloat`), not only quoted strings. The refusal is a new user-visible load-time `CLIError` and must be diagnostic, naming the offending site and the canonical rewrite — Postgres error-style, e.g. `<site>: "00" is not the canonical spelling of int tag n; write 0`. Reuse the existing refusal codes at each ingress `conformKind` serves (`malformed_predicate_atom`, `malformed_initial_declaration`, `flow-tag-invalid`/`flow-write-invalid`); no new envelope field. Option (b) is rejected: it would ratify lint going silent on a genuine dead end (measured fixture `matchlit` — typed lint exit 0 while the runtime is `flow-no-match` at the root). Option (c) is rejected: validate-then-byte-compare reintroduces the silent prune this record exists to remove, and splits `int` semantics against `lt/gte`, which already parse both sides. Option (d) — excluding `atomAdmitsValue` from typed comparison — is rejected: it institutionalizes two comparison semantics for one declared kind (Meyer, OOSC §11.7 Non-Redundancy, pp.354-355; Raymond, AoUP SPOT p.124), and leaves lint more permissive than the kernel, which is the worst orientation for the split. Rationale for acting now with zero existing violators: the invariant is cheapest before a violator population exists (SWE-at-Google pp.161-162, gofmt vs buildifier; Refactoring Databases p.186). A `--fix` affordance may be layered on later; it is not a substitute for the refusal. — absorbed @resolve 2026-09-20

Re-scope the Problem Statement (and Failure Modes' "Visible break") onto the reader-supplied owned ingress — the `--tag iter=many` example is factually wrong on `main`, since `flow_input.go` conforms declared tags before resolution — and re-author MVV steps 1-3 onto an owned-reader path. The unevaluable arm IS worth building: owned reader values are the sole unconformed door (`OwnedSnapshot` folded into `resolve.Input.Owned`; nothing in `internal/accessor` conforms), and that door is the primary state ingress, not a narrow one — every persisted owned value and every hand edit to the artifact enters through it. This is the record's own O1-vs-O4 argument: boundary validation is discipline at one ingress, and the owned ingress proves it is not total, so the seam-level arm is the only structural guarantee. Cite JDR 0004 §JD-2 where the record states the widening's reach. — absorbed @resolve 2026-09-20

Under Q1's ruling (a), C4 otherwise stays as written — `atomAdmitsValue` remains a construction site — and the record states that lint's typed admission is safe ONLY because load has made typed-vs-bytes unobservable. Validation scenario 4's "no `Evaluator{}` literal survives in non-test code" is the mechanical enforcer for any future site; the enumeration is documentation, not the guarantee. — absorbed @resolve 2026-09-20

### Provenance

These rulings were reached with three delegated passes at the model ceiling: a design consult, an adversarial falsification of its load-bearing empirical claim (which REFUTED the shared-seam premise for match atoms and produced the `matchlit` counterexample), and a literature/prior-art pass over the arc corpora and peer Go CLIs. Key correction carried forward: lint and the runtime share the seam for GUARD atoms only; the kernel byte-compares MATCH atoms (`resolve.go` `TagSet.matches`) and C1 requires it to keep doing so. A4's "changes no lint verdict" was a proxy for REQ-67's lint-runtime agreement and should be retired rather than narrowed; the restated assumption is that with canonical int spellings at load and parsed held values at the seam, lint and runtime agree on every `eq`/`in` over an int dimension, and a model spelling an int non-canonically refuses at load naming the canonical form.

## 2026-09-20 — prelock (A4 re-ruled after the lens row)

- **A4** — RULED: Option (ii) — the seam's MATCH arm byte-compares. Typed comparison is confined to the GUARD path, where lint (`product.go::valueSatisfies` via `Denotation`) and the kernel (`resolve/guard.go::evaluateAtom`) genuinely share the seam. The graphlint match site (`reach.go::matchSatisfiable` → `atomAdmitsValue`) is REMOVED from the set of sites that construct the typed evaluator, so lint's match admission stays byte-equal to the kernel's `TagSet.matches` (`resolve.go:178`) — which C1 requires the kernel to keep doing. C4 narrows accordingly. — absorbed @reconcile 2026-09-20

  Why this and not (i) (extend canonicalization to the held ingress): (i) is not available to this record. 3amigo narrowed C5 to the predicate ingress because the wider rule is refuted by two BOUNDARY-marked tests enforcing RDR 0024's locked REQ-7/REQ-9, and this project does not re-open locked RDRs — new evidence files a kata or a new RDR. So (i) would make 0012 depend on a successor record landing first, while leaving the divergence live in the interim. (ii) is implementable inside this record today.

  Effort, both directions: (ii) costs the USER nothing — match atoms compare exactly as they do on `main`, so there is no new refusal, no model edit, and no migration; guards get the fix the record exists to deliver. (ii) costs US less to implement than (i): it is a narrowing rather than new surface, and it DELETES work the lens row found defective — A7 (widening graphlint's atom check to three-valued, whose failure mode is a SUPPRESSED finding invisible to a diff over firing findings) ceases to exist, along with C4's consumption obligation and the `atomVerdictForValue` signature. A6's census narrows to the guard path.

  On the conceptual-integrity cost (Meyer Non-Redundancy, Raymond SPOT / "almost the same"): the objection is real and is not dismissed. It was raised against an option (a) that delivered one comparison rule everywhere; measurement retired that option — 3amigo showed the wider rule contradicts locked requirements, critique showed the leak sits in the narrowed-away held ingress. The boundary (ii) draws is principled rather than arbitrary: typing applies exactly where lint and the kernel share a decision path, which is a structural fact about the code and is stated and testable. The record must name this split explicitly in C2 and in the user-facing docs so it is discoverable rather than surprising.

  Residual, stated not hidden: a non-canonical int in an `[initial]`/`[rule.write]` cell still reaches `heldValues` → `canonicalValues` with no integer round-trip. FILE A KATA carrying critique's evidence for that path, with the RDR 0024 REQ-7/REQ-9 conflict recorded as the reason it is not resolved in 0012.

  Verification owed at reconcile, not assumed: (ii) narrows what C2 covers, so reconcile must check the MVV remains coherent under it and still witnesses the parsed-comparison leg on the guard path; and must confirm A7 is genuinely retired by the narrowing rather than merely re-scoped.
