## 1. Prospective hindsight — the failure narrative

We shipped command-invoking accessor bindings in 0025 and the first quarter of field use dismantled the three properties the RDR was named for.

First, the "no per-tool wrapper" promise died on contact. Not one established tool spoke the envelope: `git` ignores a JSON stdin object and prints porcelain text; `gh --json` emits nested typed JSON, not a flat string map; `test -f` says everything in its exit code, which our mapping classified as execution_failure. Within two weeks every production model's `command` fields pointed at `check-status.sh`, `apply-tag.sh` — wrapper scripts. The wrappers are where the actual authority now lives, and they are exactly the artifact the problem statement forbade: an edit no model declared and no lint covered, now with an executable bit. One team's wrapper was `["bash", "-c", "gh pr view $(cat) --json labels | jq ..."]` — a fixed argv vector, zero placeholders, lint-clean, and a shell runner reading caller data into a command line. The static-reviewability property was true of the argv shape and false of the executed authority.

Second, the timeout hole. A model bound a write to a wrapper that invoked `git push`; git spawned a credential helper that blocked on a prompt. Context cancellation killed the wrapper; the helper — a grandchild holding the inherited stdout pipe — did not die, and the executor's Wait blocked on pipe drain. The CLI hung past its declared 10-second timeout for eleven minutes until an operator killed it, and the state machine's artifact was left mid-transition: the DECIDE had been persisted to the flat-JSON artifact, the APPLY had half-happened remotely, and read-back never ran. Separately, a 70 KiB planned-writes envelope fed to a tool that never reads stdin deadlocked the pipe write before the child even misbehaved.

Third, disposition inversion. A gate accessor bound to `git diff --quiet` was supposed to deny transitions on a dirty tree. Dirty tree → exit 1 → execution_failure, whose disposition was retry-with-backoff. The engine retried a semantic "no" three times, then surfaced "tool failed" to a user whose tree was simply dirty. Meanwhile every command-backed write against the eventually consistent forge API failed its immediate read-back and landed applied-but-unverified; after a month of 100% unverified-but-fine writes, operators filtered the disposition out of their dashboards — the week the filter went in, a genuinely lost write scrolled past unread.

The postmortem's one-line summary: the design moved the undeclared edit from the caller's hands into undeclared wrapper scripts, kept the injection surface it claimed to close, and its two safety dispositions (execution_failure, applied-but-unverified) fired so often on healthy paths that they stopped carrying information.

## 2. Obstacle negations (claims 1–7)

**C1 — expressiveness without wrappers.** Negated. The whole-element restriction cannot express joined forms (`--output={artifact}`), derived paths (`{artifact}.lock`, the artifact's parent directory for `-C`), or a path appearing twice. Independently, "established tool" and "speaks the envelope" are nearly disjoint sets, so the wrapper the claim eliminates is reintroduced by claim 2's protocol. Scenario: author tries to bind `jq --arg k v '.tags[$k]=$v' {artifact}` as a write — jq writes to stdout, not in place; no shell means no redirection; the only fix is a wrapper.

**C2 — envelope for real tools.** Negated. Scenario: a write accessor binds a tool whose convention is "content on stdin" (e.g., `sponge`-style in-place writers). The executor feeds it the JSON planned-writes envelope; the tool faithfully writes the envelope bytes into the artifact. Exit 0, and if the role's reader is lenient, read-back even passes. Silent corruption with a green disposition. Converse scenario: tool never reads stdin, envelope exceeds the pipe buffer, executor blocks on write.

**C3 — static reviewability.** Negated twice. (a) `["python3","-c","<50 lines>"]` and `["bash","-c","…"]` are fixed argv vectors passing every stated lint (fixed, placeholder whole-element, mutual exclusion) — the model is a shell runner and lint cannot know. (b) The caller-bound artifact path is runtime data spliced into argv; a path spelled `-rf` or `--force` (legal filename) is parsed as a flag by the child. The executed authority is a function of PATH, of the wrapper file's current content on disk, and of the caller's binding — three runtime inputs the model does not carry.

**C4 — context cancellation suffices.** Negated by Go's own process semantics: `exec.CommandContext` signals the direct child; grandchildren survive, inherit pipe fds, and `Wait` blocks on pipe drain past cancellation (the documented reason `Cmd.WaitDelay` and process-group `Setpgid`/negative-pid kill exist). The binding does need machinery of its own: process group, kill escalation, WaitDelay, and non-blocking/bounded stdin write.

**C5 — exit mapping preserves disposition semantics.** Negated for exactly the tools the problem statement names ("a VCS query, a file probe, a tool's own status verb") — all encode the semantic answer in the exit code. Under the mapping, command gates can only deny by printing a verdict and exiting 0, which no established tool does; so either gates require wrappers (contradicting C1) or deny is unreachable (S2). Reads: "established-absent" cannot be expressed by exit code, and exit 1 (absent) vs 127 (tool not installed) collapse into one refusal class with one disposition.

**C6 — read-back through the declared reader.** Negated on four axes: eventual consistency of external state (systematic false unverified); value canonicalization by the tool (normalized refs/case fail equality against planned writes); context lifetime (reader run under the writer's cancelled or nearly exhausted context); and existence (a role writable only by command may have no reader — the RDR must say whether that is a lint error or a permanent unverified, and says neither).

**C7 — sibling field, no identity or shape change.** Negated if any consumer derives role-binding requirements, artifact discovery, identity, or documentation from the locator field. Mutual exclusion guarantees command accessors have no locator; the binding validator that walks locators to decide which roles the caller must bind will either reject the model or fail to demand the binding that `{artifact}` needs — and ambient discovery is forbidden, so there is no fallback.

**Rejected-alternative inversions.** P-8: the stdin-only alternative's rejection ("forces a wrapper per tool") is equally true of the chosen design once C1/C2 fall — the placeholder's only marginal value is avoiding one wrapper line, at the price of dash-path injection. P-9: the adapter registry's cost (a release per tool) buys versioned, reviewed, model-visible adapters; the chosen design gets unversioned wrapper scripts instead — the rejection optimizes the axis the proposal claims to prize in the wrong direction. P-10: the allowlist rejection removed the only mechanism that could make "not a shell runner" more than a sentence; a narrow interpreter deny-list is not "constraining semantic power," it is the enforcement of the proposal's own stated boundary.

## 3. Consumer artifacts — what would have caught each at review time

- **A-1 (for P-1/C1):** Binding-corpus fixture `testdata/bindings/established-tools.toml` — a table of ten real tools (git status/tag, gh label, jq read, test -f, stat, sed -i, touch, grep -q, a status verb) each bound with `command` and no wrapper. Acceptance: at least eight bind and round-trip. Running it yields ~one. The claim dies in the fixture, not in the field.
- **A-2 (for P-2):** Test `TestWriteEnvelope_ToolTreatsStdinAsContent` — bind a write to a stdin-consuming in-place writer, assert the artifact does not contain the envelope bytes. Companion `TestWriteEnvelope_ToolIgnoresStdin_LargePayload` with a >64 KiB envelope and a child that sleeps without reading; assert return within timeout.
- **A-3 (for P-3):** Lint red-team fixture set `testdata/lint/authority/` containing `["bash","-c",…]`, `["python3","-c",…]`, `["env","sh","-c",…]`, and a binding whose caller path is `--force`. Review question printed by the suite: which of these does lint reject, and on what declared rule? Plus test `TestArtifactSubstitution_DashPrefixedPath` asserting either refusal or a `--` guard.
- **A-4 (for P-4):** Test `TestTimeout_GrandchildHoldsStdout` — command spawns a child that spawns `sleep 300` inheriting stdout, parent exits on signal; assert executor returns within timeout+ε and no orphan remains (process-group check). This is a named, mechanical reproduction of the known Go pitfall; it fails against bare `CommandContext`.
- **A-5 (for P-5/P-12):** Table test `TestExitCodeMapping_GateConventions` with rows: (`git diff --quiet` on dirty tree → expected: deny), (`test -f` missing → expected: established-absent), (exit 127 → expected: execution_failure). The table cannot be filled in under the proposed mapping — forcing the decision (declared per-accessor exit semantics, or an explicit "gates must be protocol-speaking" rule) at propose time. Ordering case: tool prints `{"result":"deny"}` and exits 1; assert deny, not failure.
- **A-6 (for P-6):** User journey `journey/write-to-eventually-consistent-remote.md`: author binds a forge-API write; walk the read-back with a reader that returns stale state for 2s. Question the journey must answer in writing: what fraction of healthy writes land applied-but-unverified, and what does the operator do with that signal? Plus test `TestReadBack_NoDeclaredReaderForRole` asserting a defined behavior (lint error or declared disposition), not a nil deref.
- **A-7 (for P-7/P-11):** Test `TestRoleBinding_CommandAccessorWithoutLocator` — load a model whose only accessor for a role is command-backed with `{artifact}`; assert the CLI demands the role binding from the caller and substitutes it. Second assertion: the executor's dispatch is reached (instrument the seam), i.e., no earlier locator validation rejects the model. This is the direct probe of the peer's real partition.
- **A-8 (for P-8/P-9):** Decision-table artifact `evidence/propose/wrapper-inventory.md`: for each tool in A-1 that required a wrapper, one row — wrapper LOC, where it lives, who reviews it, how it versions. If the table is non-empty, the stdin-only and adapter-registry rejections must be re-argued against the table, not against the ideal.
- **A-9 (for P-14):** Test `TestExecutionFailure_CarriesStderrTail` — failing tool writes a diagnostic to stderr; assert the refusal surfaces a bounded stderr tail. Forces the unspecified stderr channel to be specified.

## 4. Refutation targets — this proposal's instances of S1–S3

**S1 (partition the peer does not have).** Two named sites. (a) The claim that the command field slots in "under the existing execution seam" presumes the seam's selection site branches per-accessor after role binding and before I/O. If the shipped executor's real control flow resolves locators or artifact paths for all accessors up front (load-time validation, discovery, doc generation), the command branch is dead code or a load error — the peer selects earlier than the proposal's imagined partition. (b) Read-back: if verification is implemented inside the file-backed writer rather than at the seam, command writes never reach it, and claim 6 is about code the command path does not execute. Artifact A-7 probes both.

**S2 (widening claim negated by check order).** The claim-5 shape "non-zero exit is never a gate deny" is the inverse widening claim: it asserts the new path cannot repurpose an existing refusal. But in the real order of checks — exit code inspected before stdout parse — a tool that both prints a deny verdict and exits non-zero (the natural composition of the two conventions) is classified execution_failure; the deny outcome is unreachable for exactly the tool style the feature targets. Same class in claim 4: "timeout is enforced" is negated by the pipe-drain wait that runs after cancellation in the real control flow. Artifacts A-4 and A-5 are the reproductions.

**S3 (borrowed authority).** The phrase "under the existing capability/timeout/read-back/disposition rules" cites four prior decisions for coverage they do not provide. The timeout rule decided in-process context cancellation; bounding a subprocess tree (process groups, WaitDelay, stdin deadlock) is a new decision. The applied-but-unverified rule decided synchronous read-after-write on a locally located file; read-back against eventually consistent external state, value canonicalization, and reader-less roles are new decisions. Both extensions are probably the right calls — but they must be made in this RDR as decisions with their own rationale, not inherited by citation. A third, smaller instance: "`{artifact}` drawn from a closed tool-defined vocabulary" leans on the file-locator role vocabulary's record; that record defined roles for path resolution, not for argv substitution semantics (quoting-free, dash-prefix, relative vs absolute) — the substitution contract is likewise new.

## Mitigations that keep the approach viable

1. Restate claim 1 honestly: the unit of integration is "a tool or a thin wrapper conforming to the envelope protocol"; specify the wrapper protocol in the RDR and lint what is lintable (a `command` doc field naming the wrapped tool; wrapper location conventions inside the repo so review sees them).
2. Interpreter guard: lint denies known shell/interpreter `argv[0]` forms with inline-program flags (`sh|bash|zsh -c`, `python* -c`, `perl -e`, `env` chaining into these) unless an explicit per-accessor `unsafe-interpreter = true` is declared and surfaced.
3. Substitution contract: substituted `{artifact}` must be an absolute path; executor refuses dash-prefixed bindings or requires the accessor to place `{artifact}` after a literal `--`.
4. Process bounding: process group + kill escalation + WaitDelay (or equivalent), bounded/asynchronous stdin write; a named test per A-4.
5. Exit-code contract: per-accessor declared exit mapping for gates/reads (e.g., `deny-exit-codes = [1]`, `absent-exit-codes = [1]`) with the default remaining execution_failure; stdout verdict parsed before exit classification when both present.
6. Read-back policy for command roles: declare per-accessor `read-back = required|best-effort|none`, run the reader under a fresh context with its own declared timeout, and lint-error a required read-back on a reader-less role.
7. Specify stderr: bounded tail captured and attached to execution_failure.
