# Prior art: subprocess-invoking CLI bindings (batch A)

Scope: how six Go CLIs carry a user-declared command, substitute values into it, shape the child env, consume its output, and map its exit code; and whether any of those choices were later reversed. Evidence is `repo:path::Symbol` or `repo:path:line` plus a short verbatim quote. Repos are the local `langref` clones; hugo is a shallow clone (1 commit), so its history could not be inspected.

## helm

1. **Carrier.** Both, with a migration. Legacy `plugin.yaml` had `command: <string>` and `hooks: {install: <string>}`; the current runtime is `platformCommand: [{os, arch, command, args[]}]`.
   - `helm:internal/plugin/metadata_legacy.go:52-55`: `// Command is the plugin command, as a single string.` / `// Deprecated: Use PlatformCommand instead. Removed in subprocess/v1 plugins.`
   - `helm:internal/plugin/subprocess_commands.go::getPlatformCommand` still splits the `command` field on a single space: `return strings.Split(c.Command, " "), c.Args` (so argv0 may carry extra tokens, but no shell is involved; `args` is a true list).
   - Legacy hooks (not commands) were shell strings. The v1-era loader wraps them into an explicit argv: `helm:internal/plugin/metadata.go:176`: `platformHooks[hookName] = []PlatformCommand{{Command: "sh", Args: []string{"-c", hookCommand}}}` and sets `expandHookArgs = false`.
   - `helm:internal/plugin/runtime_subprocess.go:117,149,211`: all invocations are `exec.CommandContext(ctx, main, argv...)`; no shell for commands, downloaders, or post-renderers.
2. **Substitution.** `$VAR`/`${VAR}` via `os.Expand` against the *constructed* env map, applied to argv0 always and to every arg only when `expandArgs` is true; never a custom placeholder.
   - `helm:internal/plugin/subprocess_commands.go::PrepareCommands`: `main := os.Expand(cmdParts[0], envMappingFunc)` ... `if expandArgs { baseArgs = append(baseArgs, os.Expand(arg, envMappingFunc)) }`.
   - `$HELM_PLUGIN_DIR` is therefore expanded by Go, not by a shell, and it is expanded in-string (not whole-element).
   - For legacy `sh -c` hooks expansion is disabled (`expandHookArgs = false`) because the shell will do it; for v1 plugins `expandHookArgs` is `apiVersion == "legacy"` only (`helm:internal/plugin/loader_test.go:93`).
3. **Env policy.** Inherit + overlay. `env := ParseEnv(os.Environ()); maps.Insert(env, maps.All(r.EnvVars)); maps.Insert(env, maps.All(ParseEnv(input.Env)))` then `HELM_PLUGIN_NAME`, `HELM_PLUGIN_DIR` (`helm:internal/plugin/runtime_subprocess.go:139-142,200-202`). Downloader adds `HELM_PLUGIN_USERNAME`, `HELM_PLUGIN_PASSWORD`, `HELM_PLUGIN_PASS_CREDENTIALS_ALL` (`helm:internal/plugin/runtime_subprocess_getter.go:63-68`). Base HELM_* set comes from `helm:pkg/cli/environment.go:244+` (`HELM_BIN`, `HELM_CACHE_HOME`, `HELM_CONFIG_HOME`, `HELM_DATA_HOME`, `HELM_DEBUG`, ...). Credentials travel in env, not argv.
4. **Output protocol.** Raw bytes, typed by plugin kind, not by wire format. Getter: `buf := bytes.Buffer{} // subprocess getters are expected to write content to stdout` -> `OutputMessageGetterV1{Data: buf.Bytes()}` (`helm:internal/plugin/runtime_subprocess_getter.go:82-104`). Post-renderer: manifests in on stdin pipe, rendered manifests out on stdout (`helm:internal/plugin/runtime_subprocess.go:246-275`). CLI plugins: passthrough stdio. Versioning is on the *plugin manifest* (`apiVersion: v1`, typed `schema.InputMessageCLIV1`, `OutputMessagePostRendererV1`), not in the byte stream.
5. **Exit codes.** Non-zero -> `InvokeExecError{ExitCode: eerr.ExitCode()}` with stderr logged at debug (`helm:internal/plugin/runtime_subprocess.go::executeCmd`); helm propagates the plugin's exit code. Hooks: non-zero -> error `plugin %s hook for %q exited with error` and stderr written through (`:157-162`). Only zero/non-zero semantics; no code map.
6. **Reversals.**
   - Legacy single-string `command` and shell-string `hooks` were **removed** for `apiVersion: v1` subprocess plugins: commit `c35755a19 Remove legacy Command/Hooks from v1 Subprocess (#23)` (in the HIP-0026 plugin-runtime series: `be74ab72a [HIP-0026] Plugin runtime interface`, `a7578fec7 Plugin types and plugin apiVersion v1`). Rationale in code: `Deprecated: Use PlatformCommand instead. Removed in subprocess/v1 plugins.` The shell wrap survives only as an explicit legacy adapter (`{Command: "sh", Args: ["-c", hookCommand]}`) with env expansion turned off.
   - A code TODO acknowledges the residual inconsistency: `// right now we implement status and error return in 3 slightly different ways in this file` (`helm:internal/plugin/runtime_subprocess.go:166-168`).

## gh-cli

1. **Carrier.** Both, with an explicit shell opt-in. Aliases: non-shell alias expansion is `shlex.Split` into argv and re-dispatched inside gh; shell alias (`!` prefix or `--shell`) becomes `[sh, -c, <expansion>, --, args...]`.
   - `gh-cli:pkg/cmd/alias/set/set.go:89`: `cmd.Flags().BoolVarP(&opts.IsShell, "shell", "s", false, "Declare an alias to be passed through a shell interpreter")`; `:109-110` `if opts.IsShell && !strings.HasPrefix(expansion, "!") { expansion = "!" + expansion }`.
   - Help text `:49-51`: `If the expansion starts with "!" or if "--shell" was given, the expansion is a shell expression that will be evaluated through the "sh" interpreter when the alias is invoked. This allows for chaining multiple commands via piping and redirection.`
   - `gh-cli:pkg/cmd/root/alias.go::expandShellAlias`: `expanded := []string{shPath, "-c", expansion[1:]}` then `expanded = append(expanded, "--")` + args. `sh` is located via `findsh.Find()` and failure is a hard error (`unable to locate sh to execute shell alias with`).
   - Extensions: argv, `m.newCommand(exe, forwardArgs...)`; on Windows only, non-binary extensions are wrapped as `sh -c 'command "$@"' -- exe args...` to honour shebangs (`gh-cli:pkg/cmd/extension/manager.go:116-128`).
   - git: argv only, `commandContext(ctx, c.GitPath, args...)` (`gh-cli:git/client.go::Command`).
2. **Substitution.** Two schemes by carrier. Non-shell alias: in-string textual `$1..$N` replacement *before* `shlex.Split` (`gh-cli:pkg/cmd/root/alias.go:80-93`: `expansion = strings.ReplaceAll(expansion, fmt.Sprintf("$%d", i+1), a)`; lingering `$\d` -> `not enough arguments for alias`). Shell alias: no textual substitution; args are passed positionally after `--` so the shell binds `$1..` itself (safer than splicing). Extensions/git: none.
3. **Env policy.** Inherit + one marker. `externalCmd.Env = append(externalCmd.Environ(), "GH_EXTENSION=1")` with the comment `Signal to the extension that it is being run by gh rather than standalone` (`gh-cli:pkg/cmd/extension/manager.go:131-133`; introduced in `408534a1b Set GH_EXTENSION=1 when gh invokes an extension`). No env scrubbing anywhere in `git/` or `internal/run` (no `GIT_TERMINAL_PROMPT`, `GIT_CONFIG_*`, `Unsetenv` hits). Credentials are injected as `git -c credential.<pattern>.helper=` pairs, not env: `credHelper := fmt.Sprintf("!%q auth git-credential", c.GhPath)` and `preArgs = []string{"-c", fmt.Sprintf("credential.%s.helper=", pattern)}` (`gh-cli:git/client.go::AuthenticatedCommand`), with the "all hosts" pattern explicitly marked `less secure` and to be removed.
4. **Output protocol.** Passthrough stdio for extensions and aliases; `gh api` offers `--jq` / `--template` for the caller side only (`gh-cli:pkg/cmd/api/api.go:299-300`). No versioned envelope.
5. **Exit codes.** Child `*exec.ExitError` is wrapped as `ExternalCommandExitError` (`gh-cli:pkg/cmd/root/extension.go:18,48`; `alias.go:37`) and `internal/ghcmd/cmd.go:197-222` returns `exitCode(extError.ExitCode())`, i.e. passthrough. gh's own codes are a small enum: 0 ok, 1 error, 2 cancel, 4 auth, 8 pending.
6. **Reversals.** None found in-tree for the shell/argv split; the design is the opposite direction from helm: shell stayed *available* but gated behind an explicit `!`/`--shell` opt-in and an explicit `sh` lookup. Softer signal: the credential-helper API was tightened post hoc to require a host pattern (`Callers can currently opt-in to a slightly less secure mode for backwards compatibility by using AllMatchingCredentialsPattern ... we should endeavour to remove it as it's less secure.`, `gh-cli:git/client.go:105-112`).

## goreleaser

1. **Carrier.** Shell-*syntax* string, argv-*executed*. Hooks (`before.hooks`, `builds[].hooks.pre/post`, `publishers[].cmd`, docker v2 hooks) are single strings parsed with `go-shellwords` and run with `exec.CommandContext(ctx, command[0], command[1:]...)`. No shell, no opt-in flag; pipes/redirects are simply not interpreted.
   - `goreleaser:pkg/config/config.go:563-568`: `type Hook struct { Dir string; Cmd string; Env []string; Output bool }`.
   - `goreleaser:internal/pipe/before/before.go:32-38`: `args, err := shellwords.Parse(s)` -> `shell.Run(ctx, "", args, ctx.Env.Strings(), false)`.
   - `goreleaser:internal/shell/shell.go::Run`: `/* #nosec */ cmd := exec.CommandContext(ctx, command[0], command[1:]...)`.
2. **Substitution.** Go template (`{{ .Env.X }}`, `{{ .Version }}`, build/artifact fields) applied to the *whole string* **before** shellwords parsing, so a templated value containing spaces or quotes changes argv shape.
   - `goreleaser:internal/pipe/build/build.go:194-202`: `sh, err := tmpl.New(ctx).WithBuildOptions(opts).WithEnvS(env).Apply(hook.Cmd)` ... `cmd, err := shellwords.Parse(sh)`.
   - `goreleaser:internal/exec/exec.go:174-190`: `tpl := tmpl.New(ctx).WithArtifact(artifact)` ... `cmd, err = tpl.Apply(cmd)` ... `args, err := shellwords.Parse(cmd)`.
   - Docs `goreleaser:www/content/customization/builds/hooks.md:51-52`: `All properties of a hook (cmd, dir and env) support templating with post hooks having binary artifact ...`. `dir` and each `env` entry are templated too; build-level `env` values get `os.ExpandEnv` (`build.go:126-127`).
3. **Env policy.** Two different policies in one project. Hooks: inherit (`ctx.Env.Strings()` = process env) + build env + hook `env` (`build.go:180-181`). Exec publishers: **explicit allowlist**, `var passthroughEnvVars = []string{"HOME", "USER", "USERPROFILE", "TMPDIR", "TMP", "TEMP", "PATH", "SYSTEMROOT"}` and `cmd.Env = []string{}` then only those keys plus the publisher's own `env` (`goreleaser:internal/exec/exec.go:25-26,93-100`).
4. **Output protocol.** Raw. Stdout and stderr are merged into one buffer, passed through `redact.Writer(..., env)` (secret-valued env entries are redacted from logs), and shown only when `output: true` (`shell.go:31-33`; docs `hooks.md:44-45`: `# Always print command output, otherwise only visible in debug mode.`). Output is never parsed; no versioning.
5. **Exit codes.** Zero/non-zero only: any `cmd.Run()` error -> `gerrors.Wrap(err, WithMessage("command failed"), WithDetails("cmd", command[0]), WithOutput(...))` (`shell.go:45-52`). Empty command is a warning and skip (`shell.go:21-24`).
6. **Reversals.** None found; `git log -S shellwords` shows only additions (`9e629ad feat(dockers_v2): pre/post hooks`, `a176567 fix: add retries everywhere possible`). Signal is structural rather than historical: the newer `exec` publisher (which runs with artifacts and secrets in scope) got an env allowlist while older hooks kept full inheritance.

## kubebuilder

1. **Carrier.** Bare executable path, no args, no shell: `cmd := exec.Command(path) //nolint:gosec` (`kubebuilder:pkg/plugins/external/helpers.go::GetExecOutput`). The plugin binary is discovered by name/version in the plugins dir; user cannot declare argv.
2. **Substitution.** None in the carrier; all parameters are carried in the JSON request body (`Args []string`, `Command string`, `Universe map[string]string`, `PluginChain`, `Config`).
3. **Env policy.** Inherit (Go default; `cmd.Env` never set). Nothing added.
4. **Output protocol.** JSON envelope on stdin and stdout, versioned in-band.
   - `kubebuilder:pkg/plugin/external/types.go:23-27`: `type PluginRequest struct { // APIVersion defines the versioned schema of PluginRequest that is being sent from Kubebuilder. // Initially, this will be marked as alpha (v1alpha1). APIVersion string json:"apiVersion" ...`.
   - `types.go:51-69`: `PluginResponse { APIVersion; Command; Metadata; Universe map[string]string; Error bool json:"error,omitempty"; ErrorMsgs []string }`.
   - `helpers.go:70-73`: `cmd.Stdin = bytes.NewBuffer(request); cmd.Stderr = os.Stderr; out, err := cmd.Output()`.
   - Docs `kubebuilder:docs/book/src/plugins/extending/external-plugins.md:111-113`: `Avoid printing directly to stdout in your external plugin. ... stdin and stdout using structured JSON, any unexpected output` (stdout is reserved for the envelope; stderr is the human channel).
5. **Exit codes.** Not a protocol element. Non-zero exit surfaces only as `error getting output for cmd %q: %w` (`helpers.go:74-76`); plugin failure is signalled *in-band* via `res.Error` / `res.ErrorMsgs` (`helpers.go:115-118`: `if res.Error { return nil, fmt.Errorf("%s", strings.Join(res.ErrorMsgs, "\n")) }`). Unparseable stdout -> `error unmarshalling plugin response`.
6. **Reversals.** None; API is still `v1alpha1` (`defaultAPIVersion`, `helpers.go:351,403`). The in-band `error` boolean rather than exit code is a deliberate initial design, not a correction.

## hugo

1. **Carrier.** Argv only, built by Hugo itself; users never declare a command line. Every helper (`sass`, `go`, `git`, `node`, `postcss`, `asciidoctor`, `pandoc`, `babel`, ...) goes through `hexec.Exec.New(name, args...)`, which first checks the allowlist and then does `exec.LookPath` + `exec.Command(bin, args...)` (`hugo:common/hexec/exec.go:143-158,504-531`).
2. **Substitution.** None (no user-facing template into argv). Node helpers get `NODE_PATH=<workDir>/node_modules` appended via `WithEnviron` (`exec.go:249-252`).
3. **Env policy.** **Allowlist, filtered at construction.** `for _, v := range os.Environ() { k, _ := config.SplitEnvVar(v); if cfg.Exec.OsEnv.Accept(k) { baseEnviron = append(baseEnviron, v) } }` (`hugo:common/hexec/exec.go::New`), documented as `// os.Environ filtered by the Exec.OsEnviron whitelist filter.` (`exec.go:122`). Defaults (`hugo:config/security/securityConfig.go::DefaultConfig`):
   - `security.exec.allow` = `"^(dart-)?sass$", "^go$", "^git$", "^node$", "^postcss$"` (regex list; anything else -> `CheckAllowedExec` error naming path `security.exec.allow`, `securityConfig.go:172-176`).
   - `security.exec.osEnv` = `(?i)^((HTTPS?|NO)_PROXY|PATH(EXT)?|APPDATA|TE?MP|TERM|GO\w+|(XDG_CONFIG_)?HOME|USERPROFILE|SSH_AUTH_SOCK|DISPLAY|LANG|SYSTEMDRIVE|PROGRAMDATA)$` with the comment `// These have been tested to work with Hugo's external programs on Windows, Linux and MacOS.`
   - Sibling policies: `security.funcs.getenv` = `^HUGO_`, `^CI$`; `security.http.urls/methods/mediaTypes`; `security.allowContent`; and a newer `security.node.permissions.{allowRead,allowWrite,allowAddons,allowWorker,allowChildProcess}` that maps onto Node's `--permission` flags (`securityConfig.go:143-151`; docs `hugo:docs/content/en/configuration/security.md:42-60`).
   - Docs rationale `security.md:9`: `Hugo's built-in security policy, which restricts access to os/exec, remote communication, and similar operations, is configured via allowlists. By default, access is restricted. If a build attempts to use a feature not included in the allowlist, it will fail, providing a detailed message.`
4. **Output protocol.** Raw per helper: stdin pipe in, stdout captured as the transformed resource, stderr collected into the error (`WithStdin`, `WithStdout`/`WithStderr` options, `exec.go:60-65`). No versioning.
5. **Exit codes.** Zero/non-zero; the error message is what matters. `IsNotFound` distinguishes "binary missing" from failure (`exec.go:110`).
6. **Reversals.** ★ Strongest post-hoc hardening in the set. The whole `security` block (exec allowlist + env allowlist) was added in Hugo 0.91.0 (Dec 2021) after years of unrestricted `os/exec` and `os.Getenv` from templates; the 0.91 release notes frame it as a breaking security change with a deny-by-default posture. That release-note quote could not be verified here because the local clone is shallow (`git rev-list --count HEAD` = 1); the in-tree evidence is the deny-by-default docs sentence above and the `CheckAllowedExec` error that tells users which config key to widen. The Node permission model (`security.node.permissions`) is a second, later tightening on the same axis.

## golangci-lint

1. **Carrier.** No user-declared subprocess. Custom linters are Go **module plugins** compiled into a custom binary (`custom-gcl`), or legacy `goplugin` (`plugin.Open`) (`golangci-lint:pkg/lint/lintersdb/builder_plugin_go.go:19,95`; `builder_plugin_module.go:17`). The builder shells out to fixed argv: `exec.CommandContext(ctx, "git", "clone", "--branch", sanitizeVersion(b.cfg.Version), ...)` and `go get/mod edit/mod tidy/build` (`golangci-lint:pkg/commands/internal/builder.go:93-96,133-189`). The only open-ended subprocess is the cache program `GOLANGCI_LINT_CACHEPROG`, cloned from Go's `GOCACHEPROG`: `prog = args[0]; args = args[1:]; cmd := exec.CommandContext(ctx, prog, args...)` (`golangci-lint:internal/go/cache/prog.go:80-88`), speaking Go's JSON-lines cache protocol over stdin/stdout pipes.
2. **Substitution.** None.
3. **Env policy.** Inherit, with one targeted scrub for git: `filterGitEnviron` drops `GIT_*` except `GIT_CONFIG_KEY_*`/`GIT_CONFIG_VALUE_*` (`builder.go:286-300`), so a user's `GIT_DIR`/`GIT_WORK_TREE` cannot redirect the clone.
4. **Output protocol.** `CombinedOutput` logged on failure for builder steps; JSON-lines for cacheprog.
5. **Exit codes.** Zero/non-zero, wrapped as `"%s: %w", strings.Join(cmd.Args, " "), err`.
6. **Reversals.** Docs now mark module plugins `Recommended` over Go plugins (`golangci-lint:docs/content/docs/plugins/_index.md:7-8`), a move away from in-process `plugin.Open` toward build-time linking, not toward subprocesses. Not relevant to argv/shell.

## Reversal signals

Ranked by strength (1 = strongest evidence that a project *changed* a carrier/env/output choice after use).

1. **helm: shell-string `command`/`hooks` removed in subprocess v1.** `Deprecated: Use PlatformCommand instead. Removed in subprocess/v1 plugins.` (`internal/plugin/metadata_legacy.go:54`); commit `c35755a19 Remove legacy Command/Hooks from v1 Subprocess (#23)` in the HIP-0026 series. Legacy shell hooks survive only as an explicit `{"sh", ["-c", cmd]}` adapter with Go-side env expansion disabled (`metadata.go:172-179`). Direct support for: argv list as the only carrier, explicit-not-implicit shell, expansion scope tied to carrier.
2. **hugo: deny-by-default `security.exec.allow` + `security.exec.osEnv` added post hoc (0.91).** `By default, access is restricted. If a build attempts to use a feature not included in the allowlist, it will fail` (`docs/content/en/configuration/security.md:9`); env is filtered at construction (`common/hexec/exec.go::New`). Followed by a second tightening (`security.node.permissions.*`). Rationale quote from the release notes not verifiable in the shallow clone. Direct support for: executable allowlist and env allowlist as load-time policy.
3. **gh-cli: shell kept, but only behind an explicit opt-in (`!` prefix / `--shell`) with positional `--` args instead of textual splicing.** `Declare an alias to be passed through a shell interpreter` (`pkg/cmd/alias/set/set.go:89`); `expanded := []string{shPath, "-c", expansion[1:]}` + `--` + args (`pkg/cmd/root/alias.go::expandShellAlias`). Not a reversal, but a deliberate two-tier design that keeps `sh -c` out of the default path. Softer companion: credential-helper API narrowed post hoc (`we should endeavour to remove it as it's less secure`, `git/client.go:105-107`).
4. **goreleaser: newer `exec` publisher got an env allowlist (`passthroughEnvVars`) that older hooks never had.** `// Environment variables to pass through to exec` + `cmd.Env = []string{}` (`internal/exec/exec.go:25-26,94`). Structural drift toward explicit env, no deprecation of the inherit path. Also: template-then-shellwords means substituted values can re-shape argv (`internal/pipe/build/build.go:194-202`), the exact hazard a whole-element `{artifact}` placeholder avoids.
5. **golangci-lint: targeted `GIT_*` env scrub in a fixed-argv child** (`pkg/commands/internal/builder.go::filterGitEnviron`). Minor; shows even fixed-argv children get env scrubbing when the child reads ambient config.
6. **kubebuilder: no reversal.** Versioned JSON envelope (`apiVersion: v1alpha1`) with in-band `error`/`errorMsgs` and stdout reserved for the envelope (`docs/book/src/plugins/extending/external-plugins.md:111-113`). Supports: JSON string-map on stdin/stdout, stderr as the only human channel, version field in the envelope rather than in exit codes.
