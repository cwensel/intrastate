## 1. Prospective hindsight: the failure narrative

The change shipped with `make check` green. The first decision-table model written outside the fixtures was the navigator table: nine observed dimensions, forty-one rules, one `[rule.emit]` per rule carrying `command = "..."`. The author ran `flow lint` and got a clean report. That was the failure: the PoC had found a 208-cell hole using the dummy-tag workaround, and the port of the same table to `class = "decision-table"` reported nothing. Two things had happened at once. First, the workaround's dummy owned tag had been one of the dimensions the coverage lint enumerated, so the domain and the group boundaries changed when it was removed (P-1). Second, with every row now in the single group rooted at the empty owned-state node, the group tripped the over-large/unprojectable size guard added a few commits earlier, and coverage for the group was suppressed as designed (P-2). The lint was silent because it was working exactly as specified.

The author, unaware, wrote an "otherwise" rule to be safe. `flow resolve` returned `flow-ambiguous-match` on almost every input, because exact-one is the only policy and the default overlapped everything (P-8). The author reached for an escape row instead, which resolve accepted as a fallback tier; coverage now counted the table as complete (P-7). The hole was permanently hidden.

In production the navigator invoked `flow resolve --json` and parsed `payload.owned` as an object; the first response carried `"owned": null` because the empty view was a nil map (P-6). After that was patched, a recognized-provenance dimension in the table needed a reader, and the CLI, having computed the demand set over owned keys only, ran without it and selected a row over an unset dimension (P-4). The navigator's next command had two arguments, and emit was string-only, so `args = "open --path /tmp/x y"` was split on whitespace by a helper someone wrote in an afternoon (P-9).

A colleague on the previous release opened the model, was told "rule r17 must carry a write block", and spent an hour adding write blocks before discovering the `class` key (P-14). Another colleague ran `flow next --all` against the table out of habit and hit a nil-root panic; cli/0011 had been finalized in parallel with the assumption that every model has a root (P-18).

Six weeks later a state-machine feature branched on `len(model.Owned) == 0` to mean "not yet loaded" and returned early. It passed every state-machine test. Decision tables started returning `emit: {}` for every input (P-17).

## 2. Obstacle negation

**N1 negated.** Identity with the workaround requires the same coverage domain, the same group partition, and the same suppression thresholds. The workaround had one extra dimension (the dummy tag) and, if rules wrote distinct dummy values, more than one group. Removing it changes the denominator (P-1), collapses to one group (P-2), and the over-large-group suppression fires precisely on tables large enough to be worth linting. Separately, "root/dead-end/terminal invariants are vacuous" is asserted for a root node that has zero out-edges; whichever invariant is phrased as "node with no exits" or "atom never written anywhere" (RDR 0006's vacuous-atom) is not vacuous, it is maximally triggered (P-3). And if the observed alphabet is enumerated from the graph walk rather than from tag declarations, unmentioned values are not holes but non-members (P-21).

**N2 negated.** The demand set is defined over owned keys. That is one half of the reader channel. Recognized-provenance tags, and any observed tag with an accessor, are the other half and still need an artifact (P-4). "Ignores a stray `--artifact`" also reclassifies the same flag as caller data on one class and programmer error on the other; if `--artifact` is a cobra `MarkFlagRequired`, the check runs before the model is loaded and the class is known (P-5).

**N3 negated.** Escape rows have empty writes but they are evaluated against a populated owned view; the empty view is the new case. Nil versus empty map surfaces as `null` in JSON (P-6). Escape rows are also evidence against N5, not for N3: they are a second selection tier, so the kernel already has a priority policy (P-7).

**N4 negated.** Explicit `[dump]` lists are the visible half. The default column set is the invisible half: either emit joins it and every stateful golden changes, or it does not and decision-table dumps hide the answer column by default (P-12). User models outside the repository with explicit lists are untouched either way, but they also never see emit.

**N5 negated.** Decision tables have "otherwise" rows and priority by convention (DMN hit policies: unique, first, priority, collect). Exact-one forces set-complement matches; without a negation operator in match/guard, the complement of 41 rows over 9 dimensions is written by enumeration (P-8). If the answer is "use an escape row", then the coverage lint must be pinned on whether escape rows cover; either answer breaks a stated goal (P-7).

**N6 negated.** A command with arguments is not a flat string; the encoding goes into the string, which is the out-of-band map R4 rejected, moved inboard (P-9). The join-by-rule-id step assumes one row per rule and a source rule for every row (P-10). "Keys are not tags" is enforced at match/guard, not at the `--tag` parser or the tag namespace; nothing stops an emit key from shadowing a tag name (P-11).

**N7 negated.** A negative existential about fingerprinting. If the fingerprint is over the normalized row or the dump line, the new column is inside it (P-13).

**N8 negated.** Holds only for a closed-struct decode of `[model]`. If it is a map or has a catch-all, the old binary accepts `class` and fails later on the missing write block with a misleading message (P-14). Even under strict decoding the user is told "unknown key class", not "this binary predates decision tables".

**N9 negated.** Declaration catches the state-machine-with-zero-owned direction. It does not catch decision-table-with-mistyped-provenance, which is the same silent failure R2 was rejected for (P-15). And "refusals already exist" for `[initial]`/`terminal` assumes an empty `[initial]` table over zero owned keys is refused rather than vacuously accepted (P-16).

**N10 negated.** Three sites read the key; every other class-sensitive behavior (artifact requiredness, payload nil/empty, dump defaults, `flow next`, group-size cap) is driven by "owned set is empty", which is inference. The RDR rejected inference as a classification mechanism and then used it as the implementation mechanism at most sites (P-17).

**R1 negated.** The dummy-tag convention costs three lines; the chosen approach adds a grammar key, a payload field, a dump column, a lint root rule, and an unresolved hit-policy question. "Restated as policy" is a rhetorical rejection; the cost comparison was not made (P-19). pytransitions' auto-initial is cited as the same workaround, but pytransitions is a state machine library; a decision-table library (DMN engines) is the relevant prior art and it has hit policies.

**R2 negated.** Inference was rejected for silently reclassifying a machine as a table. The declared key prevents that direction only; the other direction remains, and inference is still used at every non-key site (P-15, P-17).

**R3 negated.** The four-verb contract is reopened anyway by `emit` in the payload and by a class on which one of the four verbs is undefined (P-18, P-20). A verb that is meaningless on a class is a worse contract than five verbs.

**R4 negated.** Row-id-only was rejected for needing an out-of-band map; string-only emit forces the map's structure into strings (P-9). `any`-typed emit was deferred, but the navigator needs it on day one.

## 4. Refutation targets from the seed ledger

**S1 class (false negative-existential, stale peer citation).** N7 ("fingerprint does not read emit") and N8 ("strict decoding refuses an unknown `[model]` key") are both negative existentials that will be stamped Verified from a single reading of one function. The analogue: the fingerprint reads the dump line indirectly, or `[model]` decodes into a permissive type. Require a test, not a citation, for each (P-13, P-14). N9's "nothing else needs the class inferred" is a third; the count of `len(owned)==0` sites is the "appears zero times / appeared 5 times" failure waiting to happen (P-17).

**S2 class (claim verified against one half of a channel).** N2 verifies the reader channel's owned half and says nothing about recognized/observed accessors (P-4). N4 verifies explicit `[dump]` lists and not the default column set (P-12). "Emit keys are never matched" verifies match/guard and not the `--tag` half (P-11). "Stray `--artifact` ignored" reclassifies caller data on one class and not the other, which is the exact shape of the S2 escape (P-5).

**S3 class (peer contract read at the wrong time).** `flow next` is "not touched" while cli/0011 (`flow next` selects by match; `--all` enumerates the alphabet) was seeded in the same batch and will re-lock; RDR 0006's vacuous-atom taxonomy was pinned days ago and this RDR's "vacuous invariants stay silent" reads against it (P-3, P-18). The lint size-suppression commit is the third moving peer (P-2). Each claim about them must cite fenced text with a lock date and be re-checked at reconcile.

## Verdict rationale

No finding forces a switch to a rejected alternative: R1 remains worse for the author, inference remains worse for classification, and a fifth verb would inherit every hit-policy problem. But the approach as stated will fail its own motivating property (P-2, P-7, P-21) unless the coverage domain, the group-size cap, and the escape-row semantics are pinned, and it must decide a hit policy for "otherwise" rows before the first real table is written.
