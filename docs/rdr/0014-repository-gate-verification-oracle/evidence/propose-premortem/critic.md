## Failure narrative (prospective hindsight)

The rule landed in week one and everyone agreed it was cleaner: one carrier, one behavioral test, a two-line CI job. The gate test — invoke `make graph-lint MODEL=testdata/defective.toml`, assert non-zero exit and `graph-lint-failed` in output — went green on the first run and was cited in the RDR as closing the self-certification gap.

Week three: the Go suite started flaking in CI. Two test packages, run in parallel, both shelled out to `make`, and both triggered the binary build prerequisite; the concurrent builds clobbered the output binary and one invocation died with a spurious exec error (P-5). The fix applied under deadline was pragmatic: the gate test got `t.Skip` behind a `-short` guard "until the build race is fixed", and CI ran with `-short`. The behavioral proof was now off. The residual text assertion still passed, so the suite looked like it was still watching the gate.

Week five: the example-models list grew, and someone refactored the `graph-lint` recipe into a loop with an early conditional — lint `$(MODEL)` when set, otherwise loop the examples (P-3). Locally it worked; the (now-skipped, but occasionally hand-run) gate test exercised the MODEL arm and refused correctly. Nobody noticed that on ubuntu's dash + Make 4.x, the example loop's per-iteration failures were swallowed by last-status-wins semantics (P-2, P-6): the loop exited with the final example's status. CI's arm — the only arm CI runs — now enforced nothing about any model except the last example.

Week six: a model change introduced a transition the linter flags with a warn-class code. Under the old regime the deleted inline CI step failed on any non-empty JSON `code`; under the new regime the code was emitted, the exit stayed 0 in the broken loop, and `make graph-lint` returned success (P-1 compounded by P-2). The PR merged. The illegal transition model shipped. The postmortem found the gate test skipped, the CI arm untested by design, and an RDR whose central "subsumes both oracles" claim had never been enumerated against the linter's actual exit/code matrix.

## Per-claim negations and consumer artifacts

**Claim 1 — Make target is the correct single-carrier home.**
Negation: the Makefile is one file with two runtimes (macOS Make 3.81/bash vs ubuntu Make 4.x/dash); recipe status-masking semantics differ, so "single carrier" is environmentally plural (P-6, P-10).
Consumer artifact: a CI matrix leg `carrier-parity` that runs the gate test on both `ubuntu-latest` and `macos-latest` (the two runtimes named in the environment line), or a named test `TestGraphLintCarrier_ShellSemantics` that pins `.ONESHELL`/`set -e` behavior of the recipe. Absent from the brief.

**Claim 2 — Go test can invoke the carrier as a subprocess in test-tolerable time.**
Negation: parallel packages racing on the build prerequisite's output (P-5); cold `-race` cache in CI blowing the timeout; repo-root discovery breaking on package moves (P-12).
Consumer artifact: `TestGraphLintCarrier_ConcurrentInvocations` (two simultaneous subprocess calls must both succeed) plus an explicit serialization decision (package-level lock or `-p 1` for that package) recorded in the RDR; and a repo-root assertion that fails loudly (never skips) when the Makefile is not found.

**Claim 3 — exit integer is the fail-closed floor; JSON code is diagnosis only.**
Negation: the floor is not vacuity-closed — exit 0 from linting zero subjects passes (P-7); wrong-reason non-zero exits satisfy a bare refusal assertion.
Consumer artifacts: `TestGraphLintCarrier_WrongReasonFailure` (invoke with `MODEL=/nonexistent`, assert non-zero AND that the output does *not* claim `graph-lint-failed` — pins refusal-class discrimination); `TestGraphLintCarrier_ReportsSubjectCount` or a carrier that prints and asserts N>0 subjects linted (kills the vacuous pass).

**Claim 4 — deleting the inline JSON-code step loses no enforcement.**
Negation: the two oracles were *stated to disagree*; deletion is lossless only if no outcome exists where JSON code is non-empty while exit is 0. That set was never enumerated (P-1).
Consumer artifact: a table-driven `TestLintRefusalClasses_ExitAndCodeMatrix` enumerating every lint code the binary can emit against its expected exit status, with an explicit row (or an explicit recorded decision) for advisory/warn codes. If the matrix shows exit-0-with-code outcomes exist, the deletion narrows the gate and the RDR must say so on purpose.

**Claim 5 — one residual text assertion pins the CI wiring.**
Negation: the token matches disabled, non-gating, guarded, or `|| true`-suffixed invocations (P-4, P-9).
Consumer artifact: replace substring grep with a parsed-YAML assertion `TestCIWorkflow_GraphLintStepIsGating`: the step's `run` equals the invocation, no `continue-on-error`, no disqualifying `if:`, job present in the workflow triggered on PRs; plus the activation-run checklist item "job appears in required status checks" (per the repo's own verify-ci-on-a-real-runner practice).

**Claim 6 — the defective-model test catches a neutered carrier.**
Negation: it catches a carrier neutered in the arm the test travels. A conditional on `$(MODEL)` splits the target into a tested override arm and an untested default arm — CI's arm (P-3).
Consumer artifact: `TestGraphLintCarrier_DefaultArm` — in a temp copy/worktree, replace the checked-in default model with the defective one and invoke `make graph-lint` with **no** override, asserting refusal. This is the only test that certifies the invocation CI actually performs.

**Claim 7 — MODEL override is linted first and aborts before the example loop.**
Negation: ordering asserted without proof; loop semantics can mask or reorder (P-2), and an aggregate code observed by the test may originate from an example rather than the defective subject.
Consumer artifact: `TestGraphLintCarrier_AbortsBeforeExamples` — defective MODEL plus a sentinel-broken example; assert refusal output names the overridden model and contains no evidence the example was linted.

**Claim 8 — every refusal class exits non-zero carrying a JSON code.**
Negation: panics carry no JSON; the diagnosis step then fails on absent output (P-8).
Consumer artifact: `TestGraphLintCarrier_CrashPath` — a model input that crashes (or a linter stub that panics), asserting non-zero exit and a defined, human-readable diagnosis rather than a jq/parse error.

## Seed-class analysis

**Seed 1 (partition the shipped code does not have) → P-11.** The rule narrates a clean three-way partition — carrier (behavioral), invoker wiring (one text token), diagnosis (JSON code, informational). The shipped Make target collapses all three plus a build prerequisite into one recipe. The build step is invoker wiring *inside* the carrier that neither the behavioral test (which reads any non-zero exit as refusal) nor the text assertion covers. The brief cites the single-carrier principle repeatedly and never confronts the clause that vetoes it: a carrier that can fail for non-gate reasons is not a single oracle.

**Seed 2 (control-flow claim negated by shipped ordering; "strictly widening") → P-1, P-2.** Claim 4 is a textbook "loses nothing" coupling claim: deletion of the JSON-code oracle is asserted subsumed by the exit-integer oracle in the same breath as the problem statement calls them *disagreeing* oracles. That is an inverted citation of the brief's own premise: the disagreement is the reason deletion is lossy, offered as the reason it is safe. Claim 7 is an ordering claim about a recipe that does not exist yet, asserted as fact.

**Seed 3 (borrowed authority; verifying fixture excludes the claimed arm) → P-3, P-9.** The gate test's fixture (MODEL override) structurally excludes the arm CI runs (default model, no override) — the exact shape of Seed 3's "verifying fixture deliberately excluded the arm being claimed." And the workflow-verification rejection borrows the authority of a one-time activation run to dismiss standing coverage of workflow semantics; the activation run's stated purpose (prove the runner once) runs the opposite way from the drift-detection duty being waved off with it.

**Disposition.** None of the negations forces abandoning the single-carrier rule; each forces an artifact the brief does not yet name. The approach survives if and only if it folds in: the default-arm test (P-3), the parsed-YAML gating assertion plus required-checks activation item (P-4/P-9), the exit/code matrix enumeration before deleting the inline step (P-1), wrong-reason and vacuity discrimination (P-7), concurrency serialization for the subprocess test (P-5), and a stated decision on Make-version/shell semantics (P-6) — ideally by moving recipe logic into a `set -euo pipefail` script the Make target invokes, which the rejected-alternatives list dismissed on convention rather than merit (P-10).
