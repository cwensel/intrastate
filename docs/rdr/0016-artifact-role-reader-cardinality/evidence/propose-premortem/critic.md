## 1. Prospective hindsight — the failure, as accomplished fact

It shipped in 0.9. Three weeks later an ingest-team flow author — call her the manifest pipeline owner — filed the bug the RDR existed to prevent.

Her model: a role `manifest`, one write accessor `manifest-write` declaring owned keys `{sha256, size}`, one read accessor `manifest-read` declaring `{sha256, size}`. Both new validations passed: one reader per role, reader covers both owned keys. The execution-boundary mirror arms passed too.

At run time the write command — an external tool, per the accessor contract — emitted `sha256`, `size`, and `content-type`, the last a recognized key the tool has always emitted and which an earlier scoping decision deliberately left reader-less. The post-write compare was built from what the write *produced*, not from what the accessor *declared*. `content-type` entered the compared set. `manifest-read` could not serve it. Refusal: `read_back_incomplete`. Correct write, rejected — under a release whose headline said this refusal class was now impossible by construction.

The incident review found a second casualty from the same release. An auditing team ran a read-only model with two readers on role `ledger` — a v1-format reader and a v2-format reader, keys partitioned by format, no write accessor anywhere in the model. It had loaded and run correctly for a year; registry order never mattered because no flow ever requested a key both readers served. Arm (1) refused it at load. The team pinned the previous binary, and the pin was still in place two releases later.

Root cause, both incidents: the RDR validated *declarations against declarations* and asserted that run-time sets (planned keys, emitted keys, compared keys) coincide with declared sets. Nobody wrote down the compare-set membership rule, so the assertion was untestable, so it was untested, so it was false.

## 2. Obstacle negation — each claim, negated

**Claim 1 negated (P-1).** Planned write keys are not a subset of declared keys whenever the plan is completed at invocation time: caller-supplied tags, templated/parameterized keys expanded per run, executor-injected bookkeeping keys (timestamps, provenance). Arm (2) is a load-time check over static declarations; it is structurally blind to every key that enters the plan after load. Scenario: flow author invokes with a run-scoped tag; the write plan includes it as owned-for-this-run; the role's reader never declared it; compare refuses. The approach must either (a) prove planned ⊆ declared is *enforced* (a plan-admission refusal, cited by name), not assumed, or (b) admit the coverage arm is partial and say so in the contract.

**Claim 2 negated (P-2, P-11).** "The compare requests only planned owned keys plus the resolved reader's declared keys" is the single load-bearing sentence of the whole design and it is stated nowhere as an implemented rule — it is an assumption about executor internals. Three domain-consistent ways it breaks: (i) compare over *emitted* keys — external write commands emit what they emit; recognized keys enter; (ii) compare over accumulated artifact state — a prior step's writer to the same role contributed keys this step's coverage check never examined (arm (2) is per-write-accessor; the compare may be per-artifact); (iii) declared ≠ readable — the reader declared a key it cannot produce for this instance, so even a compare confined to declared keys can refuse. Until compare-set membership is a written, tested contract, arm (2) validates the wrong set.

**Claim 3 negated (P-3).** "No legitimate model relies on it correctly" confuses *undefined selection* with *exercised ambiguity*. A two-reader model whose flows partition the key space by format or by cost never exposes registry order — its behavior is fully determined despite the duplicate role. Such models are legitimate, currently valid, and possibly deployed. Arm (1) converts them from working to unloadable with no migration story. The claim needs a corpus sweep (every shipped, example, and test model loaded under the new arm) before it may be asserted; absent that sweep it is a guess with a fleet-outage blast radius.

**Claim 4 negated (P-4).** The loader already resolves readers per *key* (owned: exactly one; observed: at most one). That is a second, live resolution family — used by whatever consumes the key-arity result: lint, gating, inspection, planning. Arm (1) creates a role-designated reader; the key arms designate a per-key server; nothing in the approach validates that for every owned key of a write accessor, the role's reader *is* the key's designated server. Concrete divergence: writer W on role R owns key K; reader A (role R) *declares* K as observed; reader B (role Q) *owns* K. Key-arm: B serves K. Role-arm + coverage: A covers K. Both validations pass. Read-back uses A; every key-resolved consumer uses B. Two truths, one key.

**Claim 5 negated (P-5).** The problem statement promises "never a spurious `read_back_incomplete`." Claim 5 simultaneously preserves a scoping decision that keeps observed/recognized/caller-supplied keys reader-less. These are jointly satisfiable only if such keys provably never enter the compared set — which is exactly the unwritten rule of Claim 2. If any non-owned key a write produces is compared, the preserved scoping decision *is* the bug. The approach must choose: restrict the compare set to owned keys by written contract (a contract change it claims not to make — "contracts stand unchanged"), or extend coverage beyond owned keys (contradicting Claim 5), or shrink the promise. It currently does none of the three.

**Claim 6 negated (P-6).** "Refusing at load is safe" is a write-path argument applied to a load-path decision. Fail-safe means a wrong write is never accepted; it says nothing about refusing to *load* a model whose only defect is a duplicate reader on a role no write accessor touches. A never-writes model (audit, inspect, dry-run) with duplicate readers is behaviorally correct today and dead tomorrow. Minimum answer: scope arm (1) to roles referenced by at least one write accessor, or provide a migration/waiver path, or produce the corpus-sweep evidence that the refused set is empty.

## 3. Consumer artifacts — what would have caught each, at review time

- **P-1** — `TestPlanAdmission_RuntimeKeyOutsideDeclaredSet`: invoke a flow supplying a run-time key not in the write accessor's declared set; assert either the plan is refused at admission with a named error, or the compare provably excludes it. If neither branch can be written, Claim 1 is unfounded.
- **P-2** — `TestReadBackCompare_MembershipGolden`: a golden test enumerating the exact compared-key set for a write whose external command emits (owned ∪ recognized ∪ one surprise) keys. The golden file *is* the missing compare-set contract; its absence is the finding.
- **P-3 / P-6** — `TestLoad_ExistingModelCorpus`: load every model under version control (shipped defaults, examples, fixtures) with arm (1) active; the diff of newly-refused models is the migration bill, reviewed before lock. Plus user journey "operator upgrades CLI over a read-only audit model" written as a release-note draft — if the draft must say "your model no longer loads," that sentence forces the scoping decision.
- **P-4 / P-11** — `TestBindingConsistency_RoleReaderIsKeyServer`: for every write accessor, for every owned key, assert the role-designated reader equals the key-arity-designated server, and that the reader's declaration mode for that key entitles it to actually read it. This is the missing third arm; the test names it.
- **P-5** — `TestReadBack_WriteEmitsObservedKey`: writer owns `{a}`, tool emits `{a, b}` with `b` observed/reader-less; assert acceptance. If it refuses, the RDR's headline promise is false as scoped and the RDR text must shrink the promise explicitly.
- **P-7** — `TestBoundaryValidation_AllArmsEvaluatedPerDefect`: a registry carrying two independent defects (one pre-existing class, one new arm's class); assert both are reported — proves no early return starves the new arms. Plus `TestRegistryConstruction_AllPathsValidated`: an inventory/architecture test asserting every registry construction site routes through the boundary validation (resume, cache, lint/export included).
- **P-10** — `TestRoleResolution_RefusesMultipleCandidates`: make the resolution point itself assert cardinality (refuse, not first-match) so any future bypass of arm (1) fails loudly at the resolution site. The rejected execution-time refusal returns here as defense-in-depth, not as primary mechanism — its blanket rejection is what this test indicts.
- **P-8 / P-9** — anchor-quotation requirement in the RDR: every rejection reason that cites a prior decision ("deliberate earlier scoping decision", "validate-before-execute posture") must quote the governing clause verbatim with its record id. S3's lesson is precisely that a sweep confirming the record *exists* is worthless; only the quoted clause is evidence.

## 4. Refutation targets — S1–S3 applied

**S1 — uncited governing clause (found: P-4, P-9).** The brief cites the key-arity clauses (owned: exactly one reader; observed: at most one) five-times-over as *background* — "the model loader counts reader coverage per key" — and then routes the entire fix into a new role-arity coordinate without ever citing the key clauses as *governing* the servability question. But servability of a compared key is decided key-by-key; the key-arity arms are the clauses that actually govern which reader can serve K. The approach adds role arms *beside* them and never reconciles the two (no arm requires role-reader ≡ key-server). This is the S1 shape exactly: the neighboring clause (role carried in the binding) is cited throughout; the governing clause (per-key server designation) is cited zero times as a constraint on the new design. Shipped code will confirm the misrouting the first time a key's designated server and its role's reader differ (P-4 construction). Secondary S1 instance: the "validate-before-execute posture" is invoked as governing the rejection of execution-time refusal while the approach's own arm (3) is an execution-boundary check — the posture clause is either misquoted or misapplied to one of the two (P-9).

**S2 — control-flow ordering negates a coupling claim (found: P-7, P-10).** The load-bearing coupling claim here is "role-based reader resolution keeps first-match mechanics, which under (1) has at most one candidate." That sentence has S2's exact structure: a property of a downstream switch (first-match is harmless) guaranteed by an assumption about upstream control flow (the validation arm always runs first, on every path). S2's escaped defect was an early return sitting above the switch the claim assumed reachable. The equivalents to hunt in implementation: (i) an early return in the boundary validation on a prior defect class that skips the new mirror arms; (ii) a registry construction path (resume/replay, cached or normalized registry, lint/export) that reaches the resolver without the boundary validation; (iii) validation-order coupling where arm (2)'s coverage check resolves the role's reader *before* arm (1) has refused duplicates, silently using first-match inside the validator itself — validating coverage of the wrong reader. Each leaves "at most one candidate" true at load and false at the resolution site. The mitigation is structural, not procedural: the resolver refuses on >1 candidate (P-10 artifact), so ordering bugs fail closed.

**S3 — borrowed authority (found: P-8, P-5).** Two rejections and one claim lean on records the brief characterizes but does not quote. (i) "Preserving a deliberate earlier scoping decision" (Claim 5): if that record's actual text kept observed keys reader-less *because* reads were resolved per-key with multiple readers available per role, then arm (1) runs opposite the record it claims to preserve — the S3 pattern of a deviation entry that, opened, runs the other way. (ii) "No demonstrated need" for reader-set semantics: absence-of-need is asserted, not evidenced; the artifact that would evidence it (the model-corpus sweep, P-3) is exactly the "anchor sweep that confirms the file exists, not what it says" unless it inspects model *shapes*, not model *presence*. (iii) The validate-before-execute posture is borrowed to kill the execution-time alternative while the approach itself installs execution-boundary arms — whichever way the posture record actually reads, one half of the approach is currently citing it falsely. Before lock, each of these three must be replaced by a verbatim clause quotation with record id, or the dependent rejection re-argued on its own merits.

## Verdict rationale

No negation forces a switch to a rejected alternative: P-1/P-2/P-5 are answered by writing and testing the compare-set membership contract (owned-keys-only compare — a restatement the RDR must own explicitly rather than claim "contracts stand unchanged"); P-3/P-6 by scoping arm (1) to write-referenced roles or a corpus-sweep proof plus migration note; P-4/P-11 by a third consistency arm (role-reader ≡ key-server); P-7/P-10 by refuse-on-plural at the resolution site as defense-in-depth. The reader-set alternative stays unnecessary and the tiebreak alternative stays insufficient. The approach survives only with these mitigations folded; as written, it validates declarations against declarations and assumes the run-time sets follow.
