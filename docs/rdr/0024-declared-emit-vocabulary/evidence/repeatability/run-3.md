## 1. Public API

### Function Signatures

**Load pipeline entry point:** (already exists, not changed by this RDR)
```go
func Load(src []byte, sourceID string) (*Model, error)
```

**New load-stage functions (Phase 1, to be implemented):**
```go
// loadEmitDecls decodes and validates emit declarations from the source.
func (l *loader) loadEmitDecls() error

// checkRuleEmit validates every [rule.emit] block against the declared schema.
func (l *loader) checkRuleEmit() error
```

These two functions MUST be inserted into the loader's step slice immediately after `loadTags` and before `normalizeRules`, in that order (C2).

### Error Categories

Two new categories join `0002:C24`'s load-category floor:
- `unknown_emit_key` — a `[rule.emit]` key not declared under `[emit]` (C2)
- `emit_value_out_of_domain` — an authored emit value not conforming to its key's declared kind/domain (C2)

A third category, `malformed_emit_declaration`, is generated by the grammar arm in `loadEmitDecls` (C1):
- Unknown `kind` token
- `enum` with no usable domain, empty-string member, or duplicate member (across disposition lists)
- `domain` on a non-enum kind
- Empty-string disposition token
- `domain` neither a flat array nor a table
- Disposition value not an array of strings
- Nesting below disposition level
- Non-string member

### Return Behavior

Both functions return a single `error` (fail-fast contract, C2). The refusal is a `*Failure` with a `Category` field mapping to one of the three categories above.

## 2. Three Key Internal Helper Functions

### A. `(l *loader) loadEmitDecls() error`

**Responsibility:** Decode and validate the source `[emit]` table against C1's grammar.

**Key steps:**
1. Extract the source `[emit]` table (if present).
2. If zero declarations, populate `l.model.EmitDecls` with an empty map and return nil.
3. For each declared emit key:
   - Validate `kind` is one of `{enum, bool, int, scalar}`.
   - If `kind == "enum"`, validate the domain:
     - Accept either `domain = [...]` (flat array) OR `[emit.<key>.domain]` (sub-table).
     - Reject if both are present or if `kind != "enum"` carries any domain.
     - Flatten the domain to a union if partitioned by disposition.
     - Sort the flattened domain bytewise.
   - If `kind == "bool"` or `kind == "int"`, disallow any `domain` key.
   - Store `Kind`, sorted `Domain[]`, and `Dispositions map[string]string` (member → disposition token).
4. Return the first failure encountered, or nil.

**GUESS:** The source schema for `[emit]` is decoded with `DisallowUnknownFields: false` at the domain subtree level (A7), similar to `sourceModel.Metadata`.

### B. `(l *loader) checkRuleEmit() error`

**Responsibility:** Validate every `[rule.emit]` block against the declared emit vocabulary.

**Key steps:**
1. If `len(l.model.EmitDecls) == 0`, skip all checks and return nil (opt-in, C2).
2. For each source rule (`l.doc.Rule[i]`):
   - For each key in `sourceRule.Emit` (a `map[string]string`):
     - If the key is not declared, return `unknown_emit_key` failure.
     - If the key IS declared, call `ConformValue` on the value against the declared kind/domain.
       - **GUESS:** Construct a temporary `TagDecl{Kind: d.Kind, Domain: d.Domain}` to pass to `ConformValue`, per C3.
     - If conformance fails, return `emit_value_out_of_domain` failure.
3. Return nil if all rules pass.

**GUESS:** The checks run against `sourceRule.Emit` (the raw authored form), not normalized rows, because validation must happen before normalization (C2).

### C. `func (m *Model) dispositionsFor(row *Row) map[string]string`

**Responsibility:** Build the `dispositions` map for a selected row's payload.

**Key steps:**
1. If `len(m.EmitDecls) == 0`, return an empty map (no declarations, no dispositions).
2. For each `EmitValue` in `row.Emit`:
   - Look up the key in `m.EmitDecls[key]`.
   - If the value is listed in `EmitDecls[key].Dispositions`, fetch the disposition token.
   - Add entry `key → token` to the result map.
3. Sort result keys bytewise and return.

**GUESS:** This function is called from `internal/cli/flow_resolve.go::resolvePayload` to populate the new `Dispositions` field.

## 3. Data Model

### New Model-Level Type: `EmitDecl`

```go
type EmitDecl struct {
	Kind         string            // one of {enum, bool, int, scalar}
	Domain       []string          // sorted, union of all disposition partitions (enum only)
	Dispositions map[string]string // member → disposition token (enum only, empty if flat domain)
}
```

**Carried on:** `Model.EmitDecls map[string]EmitDecl` (keyed by emit key, sibling to `Model.Tags`).

**Immutability:** Once created at load, `EmitDecls` is carried through normalization untouched (C3). The normalization step does not mutate or re-sort this carrier; `0010:C3` fixes "Emit is never mutated after normalization", which extends to its declarations.

**Storage durability:** The carrier lives on the normalized `Model` so downstream readers (resolve payload join, future lint exports) can access the same declaration the author wrote.

### Serialization of Dispositions in Payload

The `resolvePayload` struct gains one field:

```go
type resolvePayload struct {
	// ... existing fields ...
	Emit         map[string]string `json:"emit"`
	Dispositions map[string]string `json:"dispositions"`  // NEW, C4
	Next         map[string]string `json:"next"`
	// ... remaining fields ...
}
```

**Behavior (C4):**
- Always present, never `null`, never omitted (`omitempty` is explicitly NOT used).
- Keyed by emit key, values are disposition tokens (as authored in the declaration).
- Entries are present ONLY for keys the selected row authors AND whose value is listed under a disposition in the declaration.
- Keys are in byte order.
- Empty map `{}` when no selected value carries a disposition.

## 4. Top-Level Pseudo-Code of Main Operation

### Load Pipeline (Phase 1 – Declaration Grammar and Load Proof)

This describes the normalized load flow after both new steps are inserted:

```
LOAD PHASE:

1. Version gate (existing)
2. Strict TOML decode (existing)
3. loadModelHeader → populate Model.ID, Version, Description, Class, Metadata
4. loadOutcomes → populate Model.Outcomes
5. loadTags → populate Model.Tags (existing tag declarations)
6. loadAccessors → populate Readers, Writers, Gates (existing)
7. loadDump → populate DumpOrder (existing)
8. loadContexts → cache context atoms (existing)
9. loadInitial → populate Initial (existing)
10. loadTerminal → populate Terminal (existing)

11. [NEW] loadEmitDecls:
    - Extract [emit] TOML table from doc
    - If zero keys:
      - Set Model.EmitDecls = empty map
      - Return nil (opt-in, zero-declaration model)
    - For each [emit.<key>] entry:
      - Validate kind ∈ {enum, bool, int, scalar}
      - If enum:
        - Accept domain in one of two forms: flat array OR partitioned sub-table
        - Flatten to union, sort bytewise
        - Build Dispositions map from partition keys
      - If bool/int/scalar: reject any domain key
      - Store EmitDecl{Kind, Domain[], Dispositions}
    - Return first failure, else nil

12. [NEW] checkRuleEmit:
    - If Model.EmitDecls is empty, return nil (opt-in)
    - For each rule in doc.Rule:
      - For each key in rule.Emit:
        - If key not in Model.EmitDecls, return unknown_emit_key failure
        - Construct temporary TagDecl from EmitDecl
        - Call ConformValue(tagDecl, authored_value)
        - If fails, return emit_value_out_of_domain failure
    - Return nil if all pass

13. normalizeRules → populate Rows (existing)
14. checkClassAgreement (existing)
15. checkAccessorBindings (existing)

OUTPUT: Model with Rows, Tags, AND EmitDecls all normalized
```

### Resolve Payload Building

When `flow resolve` selects a row:

```
RESOLVE PHASE (flow resolve):

1. Run the kernel selection against the narrowed model (existing)
2. One row selected (or refusal)
3. Run gates on selected row (existing)
4. Build resolvePayload:
   a. Populate Emit from row.Emit (existing)
   b. [NEW] Populate Dispositions:
      - Iterate row.Emit entries
      - For each (key, value), look up key in m.EmitDecls
      - If found AND value is in EmitDecls[key].Dispositions:
        - Add key → EmitDecls[key].Dispositions[value]
      - Sort result keys bytewise
   c. Populate Gates, Next, Writes, Clear (existing)
5. Return payload with emit AND dispositions both present
```

## Widening Notes

**C1 domain handling (scope-extension read):** The RDR states that `domain` is two-shaped and "the ONE place in the source schema that cannot be concretely typed", with `DisallowUnknownFields` stopping at it. Read lines 557–562 of the RDR to confirm the carve-out is identical to `sourceModel.Metadata`.

**C2 ordering and fail-fast (full section read 634–766):** The RDR states explicitly that the two new steps are inserted "immediately after `loadTags`" and both must run before `normalizeRules`. The fail-fast contract is inherited from `0002:C24` and is not invented here; read `internal/table/load.go::Load` doc line 24 to confirm.

**C3 ConformValue reuse (scope-extension read):** The RDR justifies reusing `ConformValue(decl TagDecl, member string)` by constructing a throwaway `TagDecl{Kind: d.Kind, Domain: d.Domain}` and passing it, accepting that `Min`, `Max`, `Elements` stay nil. Read lines 798–811 to confirm the adapter pattern.

**C4 dispositions field placement (full section read 838–888):** The RDR fixes the field insertion position as "immediately after `emit`" in the struct declaration order, because Go's JSON encoder uses declaration order for key output. Read line 850 to see the example: "`emit` itself is never-omitted for `0010:C4`'s reason".
