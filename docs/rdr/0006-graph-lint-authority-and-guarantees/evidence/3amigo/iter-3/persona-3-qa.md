2. **Invariant 5's second half — "no reachable path leaves a second value held beside one no write or clear on that path removes" (Technical Design, invariant 5) — has no decision procedure and no scenario.**
   The reachability relation in `Load-Bearing Decisions` abstracts an owned-state node as "per owned tag: absent, or held with its set of possible declared values". A node is thus already a *set* of possible values, which is the abstraction's normal representation of path-merge uncertainty, not a defect. Nothing states how lint distinguishes "this node abstracts to `{a,b}` because two paths reach it with different single values" (legal — each concrete run holds one) from "this path leaves two values held simultaneously" (invariant 5's violation). The two are indistinguishable in the stated node representation. Scenario 2 lists "multi-valued state" only in the flat list of illegal fixtures, which the MVV narrows to `graph-single-valued-state`; both are satisfiable by the *first* half of the invariant (one row's writes assigning two values), which is a trivial single-row syntactic check.
   **Test prevented**: the path-accumulation half of invariant 5 — build a model where row A writes `tag=x`, row B (reachable after A, no clear) writes `tag=y`, assert `graph-single-valued-state`. I cannot state the expected result, because the same fixture is the textbook shape of a legal two-path merge. An implementation that ships only the single-row check satisfies scenario 2 and the MVV verbatim while omitting half the normative invariant.

3. **A7 makes invariant 5 discharge RDR 0003 A18 as "the model-level producer", but no clause maps a model-level finding onto the view-level property, and there is no scenario for the discharge.**

   **Test prevented**: the soundness test for the A18 discharge — enumerate reachable views for a model lint accepted and assert every one is single-valued conforming. I have no pass/fail criterion for "conforming view" in this document (`internal/resolve/resolve.go::assemble` is cited as performing *no* such check), so the assumption that closes a peer RDR's open premise cannot be falsified by any test named here.
