## 1. The Three Most Likely Ways Implementation Goes Wrong

### 1.1 The coverage proof is unsound at merged nodes, and the RDR certifies the opposite (C-1, C-10)

**Root cause.** Two decisions made independently — each defensible alone — compose into a false green. Decision one: the join rule ("two edges reaching the same successor produce one node whose per-tag value sets are the union of theirs"), sold as the safety mechanism itself: "Merging is what keeps the relation an over-approximation… can never miss one it does (no false green). This is the whole reason the guarantee holds." Decision two: group membership by satisfiability — "a row belongs to the group of every reachable node its match pattern over owned tags is satisfiable in."

**Why it is wrong.** RDR 0003's coverage identity, `union(row_i accepted assignments) == scoped product`, is sound only when every row in the group actually matches whenever the group's context holds — which is exactly what 0003's definition ("rows sharing one source state") guarantees and what 0006's redefinition destroys. Take a merged node N with `status ∈ {done, review}` (the RDR's own two-path-merge example from invariant 5). Row A matches `status=done` and covers guard assignment `x=1`; row B matches `status=review` and covers `x=2`. Both are satisfiable in N, so both join N's group; the union covers `{1,2}`; invariant 4 passes. At the concrete runtime state `status=done`, only A matches, and the call with `x=2` refuses `no_match`. Match keys are, per 0003's locked ownership table, "explicitly not an arm" of the product — so the differing match patterns are invisible to the union. The over-approximation that is conservative for invariants 2 and 6 (universal checks over the node) is *anti*-conservative for invariant 4 (existential membership inflating a union). The RDR states the no-false-green property once, globally, and never re-derives it per invariant.

**Enabling passage.** §Technical Design, "Source state is a tag-set, not a name," including the flat prohibition "Lint MUST NOT key groups on the syntactic match pattern" — which outlaws the one grouping under which 0003's identity is actually sound, while the normative clause "MUST NOT define a second grouping predicate" claims no redefinition happened (C-10).

**Symptom.** A maintainer merges a model under a green gate; days later a flow run refuses `no_match` in a group the lint certified exhaustive. The failure arrives with lint's credibility attached: the tool whose entire promise is "no false green" produced one, and the postmortem finds the defect in the locked contract, not the code.

### 1.2 The reachability fixpoint as written cannot be implemented as written (C-2, C-11)

**Root cause.** The Load-Bearing "Join rule and termination" bullet was added to answer "does this terminate?" and answers only that. Two constitutive questions are unanswered. First, *when do two nodes merge?* There are no named states, so "the same successor" has exactly one grounded meaning: value-set-tuple equality — under which union-merging is an identity operation, the "lattice widening" never fires, and the traversal is a raw enumeration of the tuple space, finite (as promised) and astronomically large (as not mentioned). Any behavior other than enumeration requires a partition key — held-key set? match-context? — that the RDR does not supply, and each choice yields *different findings* for invariants 2, 4, and 6. Second, *what is held ⊔ absent?* The node domain is "per owned tag: absent, or held with its set of possible declared values" — there is no element combining the two. Encode absent as the empty set and union it away, and a tag absent on one path but held on another reads as held at the merged node: invariant 6 passes a row that reads it, which is a false green in the one invariant (`graph-owned-before-write`) whose runtime counterpart (`owned_state_unavailable`) the RDR explicitly names as its design-time charge.

**Enabling passage.** "The lattice is finite — … — so the fixpoint terminates on cyclic graphs" — a termination argument standing in for an algorithm. The 3amigo pass asked for a join rule (its S3) and got this paragraph; the paragraph names a fixpoint without defining node identity, and calls the no-false-green property "a derivation, stated inline" when nothing per-tag about the absent case is derived anywhere.

**Symptom.** Phase 2 either hangs on the first model with a handful of enum-domained owned tags, or the implementer picks a merge key on the spot — at which point the "normative" reachability relation, the group partition, and every finding downstream of them are implementation folklore, not RDR contract.

### 1.3 The output contract is written against an envelope that does not exist (C-3, C-4)

**Root cause.** A4 verifies that `clierr`/`respond`/`ExitCodeFor` exist — true — and the RDR then specifies byte shapes those symbols do not produce. Normative wire format: failure findings at `error.findings` under `{"type":"failed","error":{…}}`. Shipped reality: `respond.Fail` calls `clierr.EmitJSON`, which marshals the bare `CLIError` — `{"code":…,"message":…,…}`, no `type`, no `error` key — and `docs/cli-output-contract.md` says so in as many words ("`{"type":"failed", ...}` is not emitted by `Fail`"). The findings field will actually be a top-level sibling of `code`, and every golden, script, and the A5 CI assertion written from the RDR's normative text will be wrong. Compounding it: the text-mode clauses are jointly unsatisfiable with the shipped gateway. Success findings live in `Success.Data`; `respond.OK`'s text branch drops `Data` and prints only notes/warnings; `clierr.EmitText` prints no findings; and the command "MUST NOT write directly to stdout or stderr." Enumerating every finding in text mode therefore requires extending both renderers — changes the Existing Infrastructure Audit explicitly books as "Reuse" (respond) and never books at all (`EmitText`).

**Enabling passage.** §Load-Bearing Decisions "Wire / byte format," and the audit row "Text/json output routing | `internal/cli/respond` | … | Reuse."

**Symptom.** JSON consumers parse for `.error.findings` and get `undefined`; the CI gate's jq assertion passes vacuously or fails permanently depending on which half of the contradiction the implementer resolved; text-mode success runs print nothing for the bare-escape closure — the "silent catch-all" outcome the disposition table promises is impossible.

## 2. The Section Rewritten Within 6 Weeks

**§Load-Bearing Decisions — "Reachability relation" + "Join rule and termination" (and the dependent "Source state is a tag-set, not a name").** This is the RDR's only genuinely novel contribution — everything else is citation plumbing — and it is the part that cannot survive implementation in its current form, for three compounding reasons already rowed: the merge trigger is circular (C-2), the coverage direction of the over-approximation is unsound (C-1), and the node count is the one unbounded cost in a design that declares performance not load-bearing (C-11). The first week of Phase 2 forces a node-identity decision the text does not contain; whatever is chosen redefines "reachable," which redefines the group partition, which redefines what invariants 2, 3, 4, and 6 even quantify over. Because peers "cite the relation" (§Capability Dependencies: "peers quantify over" it, RDR 0003's owned-tag clause quantifies over it by name), the rewrite is not internal cleanup — it is a semantics change to a cross-RDR export, made under implementation pressure, after lock, in a process whose doctrine is that locked RDRs are never amended. The section will be rewritten in the only place left: the code, silently diverging from the locked text.

## 3. The Assumption That Will Not Survive First Contact With a Real User

**"A false positive is expected to be rare and fixable… There is no suppression or waiver mechanism" (§Trade-offs, Consequences; C-9, with C-12).** The rarity claim is load-bearing — it is the entire justification for shipping a blocking gate with no waiver — and it is contradicted by the strongest evidence available in this repo: RDR 0003's own desk trace. That fixture, authored by the same cluster for the same flows, at declared defaults (nothing marked `single_valued`, nothing marked always-present) produced an 8,192-assignment scoped product and atoms that do not project at all — meaning blocking `graph-unprovable-coverage`, not a rare edge case but the *default outcome for an unannotated model*. Stack the rest of the defaults the RDR adopts: exhaustiveness claims are "default-on, never an opt-in annotation"; A21 makes any `eq`/`in` atom over an unmarked tag blocking; unmarked keys default optional and double the product; invariant 2's universal satisfaction makes every terminated-path/live-path merge a structural `graph-dead-end` (C-12) whose sanctioned "cure" is declaring a terminal over a live state. The first real maintainer — the flow maintainer from the Problem Statement, editing the rdr transition model — runs `intrastate lint` and gets a page of exit-2 findings on a model `Resolve` handles correctly today. There is no waiver, no advisory downgrade, and the RDR's pre-answered response is "a clearer model, never a weaker lint" plus a successor RDR someday. Users do not file successor RDRs; they remove gates. The assumption fails not because false positives exist but because the RDR bet its no-waiver posture on a frequency claim its own cluster's evidence already falsified.

## 4. Premortem

*Written 2026-11-30, as if looking back.*

RDR 0006 shipped in mid-September. The lint gate was removed from required checks on November 18. Here is how it went.

Phase 2 died first. The implementer sat down to write the worklist for the owned-state fixpoint and could not answer the first question the code forced: the map key for a visited node. The RDR said nodes merge when "two edges reach the same successor," but with no state names, "same successor" meant tuple-equality of per-tag value sets — under which the union-merge in the spec was a no-op and the promised widening never happened. On the rdr flow model (six owned tags, enum domains of 3–5), the exact enumeration blew past two million abstract nodes before anyone killed it. The fix — merging on the set of *held* keys, invented in a PR comment — changed which contexts were "reachable," which changed the group partition, which changed the findings. Nobody routed it back to the RDR; the RDR is locked and we never amend RDRs. From that day, the normative reachability relation and the shipped one were different relations.

Then the false green everyone had been promised was impossible. `kata-flight`'s maintainer merged a model revision under a green gate — coverage certified for the `(status held, outcome=reviewed)` group. Two days later `Resolve` refused `no_match` for a call at `status=done`, `retries=2`. The group at the merged node `{done, review}` had contained a `status=review` row whose accepted assignments closed exactly that arm of the union; at the concrete state, that row does not match, and there was nothing else. The RDR had ordered membership by satisfiability ("Lint MUST NOT key groups on the syntactic match pattern") and had derived no-false-green only for the universal invariants. The one guarantee the Problem Statement promised — illegal graphs caught at design time — failed in the false-green direction on its second month.

The output surface never matched its spec. The gate script asserted `.error.findings` per the Load-Bearing wire format; `respond.Fail` emits a flat `CLIError` via `clierr.EmitJSON` — no `type`, no `error` nesting — exactly as `docs/cli-output-contract.md` had said all along. The script was rewritten against the real envelope; the RDR's goldens were regenerated to disagree with the RDR. Text mode was worse: `respond.OK` drops `Data`, so the `graph-coverage-closed-by-escape` receipt — the finding whose whole point was that a bare catch-all "MUST NOT" pass silently — was invisible in the default output mode until someone patched `EmitText` and `OK` in an unreviewed direction.

CI was the slow failure. There was already a `jobs.lint` (golangci-lint), so the new job became `graph-lint`, quietly failing Scenario 7's literal oracle. It had nothing to run against: no checked-in transition model existed — the flow models live in the process repo, `--flow` pointed at RDR 0005 config discovery that 0005 had deferred, and A6's initial/terminal schema still hadn't landed in RDR 0002, so every candidate model was rejected with `graph-dangling-edge` at the root. The job ran the fixture corpus — the exact thing A5 said was not the gate — and A5 stayed Pending forever.

What killed the gate was volume. The first real model produced 41 blocking findings: `graph-unprovable-coverage` on every unmarked tag (A21), `graph-product-too-large` on the two annotated groups (the published bound had been set to 4,096 after the CI job hit eleven minutes), and `graph-dead-end` on every merge where the archive path had terminated and the review path continued. No waiver existed by design. The maintainer annotated for a week, hit the structural dead-end class that no annotation fixes honestly, declared a terminal over a live state to shut it up, and filed the issue that ended with `graph-lint` moved to non-required. The runtime kernel, which had been refusing bad calls correctly the whole time, was never the problem.
