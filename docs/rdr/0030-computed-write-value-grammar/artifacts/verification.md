Independent pass over the RDR and `req-list.md` only. Probes were scratch
models run through the built CLI (`graph`, `lint`, `flow resolve
--plan-only`), plus a main-vs-branch `lint`/`graph` diff over every
committed `.toml` (218 files). Held: REQ-1…REQ-5, REQ-7…REQ-34, REQ-36,
REQ-38…REQ-47 and the behaviour behind REQ-48…REQ-58. Corpus diff: `graph`
0 changed; `lint` 4 changed, every one only a `#`-suffix on an
`in`-expanded row's `rule`/`element` (Q1 reading (a)).

FAIL-1 (REQ-6, REQ-3 boundary): a representable-width `int` makes the loader panic. Input: `[tags.big] kind="int" min=0 max=70368744177664` (also `max=9223372036854775806`, width `math.MaxInt`, which `resolve.IntWidth` accepts), a rule with `[rule.guard.all.big] lt = 5` and `big = { step = 1 }`. Observed: `graph`/`lint` crash with `panic: runtime error: makeslice: cap out of range` at `internal/table/step.go:84` (`stepCells` pre-sizes the cell slice to the full declared width before any atom is applied). The process exits with a Go stack trace and no envelope. The control model, same declaration with `big = 3`, loads. REQ-6 says such a domain "is admitted and merely expensive". Widths below the cap-out-of-range threshold still allocate the full width eagerly, even when the atoms admit only 5 cells.
Outcome: fixed:c8e9c23 — `stepCells` narrows the int walk by the positive atoms and never pre-sizes by the declared width (deviations D9); regression `TestAdv1_0030_RepresentableWidthNeverPanics`.
FAIL-2 (REQ-37/REQ-36 under the Q1 reading (a) ASSUMPTION): `graph-coverage-closed-by-escape` names an expanded row by its bare id. Input: a bare escape rule `id="esc" escape=["no_match"]` with `[rule.match.recognized] in = ["retry","done"]`, beside a stepped `retry` rule. Rows publish as `esc#retry` / `esc#done`. Observed: `lint` emits `rule: "esc"` and the message `closed by the bare escape row "esc"` for group `m/retry …`, while the same run's per-row `graph-idempotent-write` reads `fin#retry`. The Rule slot names a ROW (from `bareEscapeFor` → `row.RuleID`, `internal/graphlint/coverage.go:403,439`), not a `firstRuleID` group site, so under "every surface that names a ROW publishes the suffixed identity" it should read `esc#retry`. It is reachable only through `in` expansion: an escape row cannot step.
Outcome: fixed:4da1865 — `bareEscapeFor` names the row by `rowIdentity` (deviations D12); regression `internal/graphlint/adversarial_0030_test.go::TestReq37_0030_ClosedByEscapeNamesTheExpandedEscapeRow`.
NOTE (ASSUMPTION drift, not a REQ-N failure): the loader's kind mapping has two bodies. `internal/table/step.go::(*loader).tagKinds` re-implements `internal/guard/declaration.go::DeclaredKinds` (the same loop and the same empty-Kind omission), and `DeclaredKinds` does not delegate to it. The req-list's second ASSUMPTION ("The loader-side mapping has one body", JDR 0004 JD-3) expects a single shared helper. Behaviour is identical today.

## Phase 3b — Adversarial

ADV-1 (F1, representable side of the width line; blocking) — a step over `int` `min = 0, max = math.MaxInt - 1` (width `MaxInt`, representable, so C1 admits it: "representability, not size") whose rule admits five cells (`gte 0`, `lt 5`) PANICS the loader: `internal/table/step.go::stepCells` preallocates `make([]string, 0, width)` and dies with `makeslice: cap out of range` before any atom is consulted. Past about 2^44 cells every representable width crashes the process. Below that, the walk is still sized by the declared width, not the admitted cells (A7). So F1's "explicit refusal rather than an accidental fall-through" holds one step outside the line, and one step inside it the process crashes. Test: `internal/table/adversarial_0030_test.go::TestAdv1_0030_RepresentableWidthNeverPanics` (runs the load in a child process with a 30 s bound; expects rows `retry#0…#4`). FAILS now (child panic). The fix needs a decision: bound the walk by the positive atoms, or take a ceiling that C1 currently forbids.
Outcome: fixed:c8e9c23 — same defect as FAIL-1; the walk is bounded by the positive atoms, no ceiling taken (deviations D9; fixture corrected, D10).

ADV-2 (F4 with A5/MVV zero-gap, the S8 shape; blocking) — a stepped rule over a subsumed `match.attempt in = [0..4]` plus a cap rule `in = [5..9]` claims every cell, yet lints five BLOCKING `graph-coverage-gap`s, one per claimed cell ("group adv2/retry attempt.eq=N … leaves 9 of 10 assignments … uncovered"). The rewritten `match eq = <cell>` splits the rule into per-cell groups. The mandated `guard.all eq = <cell>` then makes `attempt` a dimension of each group's scoped product, and the group's own match `eq` does not narrow that product. The hand-unrolled twin (one `match eq` per cell) lints zero gaps; it is asserted as the control. A literal row carrying both atoms reproduces the gap, so the trigger is REQ-13's two-atom row shape meeting lint's product scoping. The step ladder is therefore not the literal ladder to lint, and F4's gap fires on claimed cells instead of unclaimed ones. Test: `internal/graphlint/adversarial_0030_test.go::TestAdv2_0030_SubsumedInLadderLintsNoCoverageGap`. FAILS now (5 gaps).
Outcome: fixed:b9c340f — D13 resolved: `expand` emits a stepped row's `guard.all eq = <cell>` only when no match `eq` pins the tag (the subsumed-`in` rewrite, or an authored/inherited match `eq`), so each per-cell group carries no `attempt` guard dimension; the test goes green unchanged; `TestReq13_0030` re-cut to the resolved reading; regression `TestAdv2_0030_AuthoredMatchEqStepLintsNoCoverageGap` (authored match `eq` + step, 0 gaps).

ADV-3 (F1 "refuses the same way"; low severity) — the non-representable-width refusal's detail (`a step cannot enumerate int bound {0..9223372036854775807}: its width is not representable`) names neither admitted kind nor the admitted form. The kind refusal beside it names both (`an int declaring both min and max, or an enum with a non-empty domain`), and S5 expects every such refusal's detail to name "the admitted form or kinds". Test: `internal/table/adversarial_0030_test.go::TestAdv3_0030_WidthRefusalNamesAdmittedKinds` (the unbounded-int kind arm is the passing control). FAILS now on both width arms (`max - min == MaxInt`, and the one wrapping from `math.MinInt`).
Outcome: fixed:c8e9c23 — the width refusal appends the kind refusal's admitted-kinds text (deviations D11).
